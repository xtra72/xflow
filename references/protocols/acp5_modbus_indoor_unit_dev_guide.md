# ACP5 Modbus TCP 실내기 제어 개발 가이드

> LG 시스템 에어컨 중앙 제어기 ACP5 — Modbus TCP 기반 실내기 연동
>
> 참조: ACP5 사용자 설명서 v2.22.1 (Modbus Commission 섹션)

---

## 1. 개요

### 1.1 ACP5 소개

ACP5는 LG 시스템 에어컨용 중앙 제어기로, 하나의 공간에서 최대 256대의 장치를 개별 또는 통합하여 관리할 수 있다. 웹 서버가 내장되어 있으며 BACnet IP, Modbus TCP, Lonworks 프로토콜을 통해 BMS(Building Management System)와 연동할 수 있다.

### 1.2 Modbus TCP 연동 구조

```
┌─────────────┐     Modbus TCP      ┌──────────┐     RS-485/LGAP     ┌──────────┐
│  BMS 시스템   │◄──────────────────►│   ACP5   │◄──────────────────►│  실외기    │
│  또는         │   Port 502         │ (중앙제어) │   4800bps 8N1      │  (ODU)   │
│  커스텀 장치   │   (TCP/IP)         │          │                    │    │     │
└─────────────┘                     └──────────┘                    │    │     │
                                                                    │  ┌┴─────┴┐
                                                                    │  │실내기  │
                                                                    │  │(IDU)  │
                                                                    │  └───────┘
                                                                    │  ┌───────┐
                                                                    └──│실내기  │
                                                                       │(IDU)  │
                                                                       └───────┘
```

### 1.3 XIAO-nRF52840 프로젝트 연동 시 구조

본 프로젝트에서는 ACP5의 Modbus TCP를 직접 사용하는 것이 아니라, ACP5가 사용하는 것과 동일한 레지스터 정의를 참조하여 XIAO-nRF52840 디바이스가 LGAP 프로토콜을 통해 동일한 데이터를 BLE로 전달하는 것이 목표이다. 따라서 이 문서는 ACP5 Modbus 레지스터 구조를 이해하고 BLE 특성 매핑의 참조 기준으로 활용한다.

## 2. Modbus TCP 연결 설정

### 2.1 사전 설정

ACP5에서 Modbus TCP를 사용하려면 웹 GUI에서 다음 설정이 필요하다.

**경로**: `[설정]` > `[BACnet/Modbus/Lonworks 설정]`

| 항목 | 설정 | 비고 |
|------|------|------|
| Modbus TCP 사용 | `설정` | 반드시 활성화 |
| Vnet Number | 1~247 | Modbus Slave ID로 사용됨 |

### 2.2 통신 사양

| 항목 | 사양 |
|------|------|
| 프로토콜 | Modbus TCP |
| 전송 계층 | TCP/IP |
| 기본 포트 | 502 |
| Slave ID | Vnet Number 값 (1~247) |
| 바이트 순서 | Big-Endian |

### 2.3 주의사항

- 2대 이상의 ACP5가 설치되는 경우 Vnet Number가 중복되지 않게 설정해야 한다
- `Read Single Coils` 명령 (Function Code 1)은 최대 **2,000개**까지 한 번에 조회 가능
- `Read Holding Registers` 명령 (Function Code 3)은 최대 **125개**까지 한 번에 조회 가능

## 3. 지원 Function Code

ACP5가 지원하는 Modbus Function Code는 다음과 같다.

| Function Code | Hex | 명칭 | 용도 |
|:---:|:---:|------|------|
| 1 | `0x01` | Read Single Coil | ON/OFF 상태 읽기 (비트 단위) |
| 3 | `0x03` | Read Holding Registers | 레지스터 값 읽기 (16비트 단위) |
| 5 | `0x05` | Write Single Coil | ON/OFF 상태 쓰기 (비트 단위) |
| 6 | `0x06` | Write Single Register | 레지스터 값 쓰기 (16비트 단위) |

**Function Code 사용 구분:**

- **Coil (FC 01/05)**: 전원 ON/OFF, 풍향, 잠금, 알람 등 2진 상태 제어/모니터링
- **Holding Register (FC 03/06)**: 운전 모드, 풍량, 온도, 에러 코드 등 다중 값 제어/모니터링

## 4. 레지스터 주소 체계

### 4.1 주소 구조 (16비트)

ACP5의 Modbus 레지스터 주소는 다음 구조로 이루어진다.

```
레지스터 주소 (16비트) = 제품타입(4비트) + 제품주소(8비트) + 포인트(4비트)

  ┌──────────┬──────────────┬──────────┐
  │ [15:12]  │   [11:4]     │  [3:0]   │
  │ 제품타입  │  제품주소      │  포인트   │
  │ (4 bit)  │  (8 bit)     │  (4 bit) │
  └──────────┴──────────────┴──────────┘
```

### 4.2 제품 타입 코드

| 제품 타입 | 코드 (Hex) | 주소 범위 |
|---------|:---------:|---------|
| 실내기 (에어컨) | `0x0` | `0x0000` ~ `0x0FFF` |
| 환기 | `0x4` | `0x4000` ~ `0x4FFF` |
| AHU | `0x8` | `0x8000` ~ `0x8FFF` |
| 시스템 보일러 | `0xC` | `0xC000` ~ `0xCFFF` |

### 4.3 제품 주소 (장치 번호)

- 실내기: 0~255 (0x00~0xFF) — 최대 256대
- 환기: 0~27 (0x00~0x1B) — 최대 28대
- AHU: 0~15 (0x00~0x0F), 장치당 주소 2개 사용 — 최대 16대
- 시스템 보일러: 0~15 (0x00~0x0F) — 최대 16대

### 4.4 레지스터 주소 계산 공식

```
Register Address = (제품타입 << 12) | (제품주소 << 4) | 포인트
```

**실내기 주소 계산 예시:**

| 대상 | 제품타입 | 제품주소 | 포인트 | 레지스터 주소 |
|------|:------:|:------:|:-----:|:---------:|
| 실내기 0번 — 운전 설정 | 0x0 | 0x00 | 0x1 | **0x0001** |
| 실내기 0번 — 운전 모드 | 0x0 | 0x00 | 0x1 | **0x0001** |
| 실내기 1번 — 운전 설정 | 0x0 | 0x01 | 0x1 | **0x0011** |
| 실내기 27번 — 운전 설정 | 0x0 | 0x1B | 0x1 | **0x01B1** |
| 실내기 100번 — 운전 설정 | 0x0 | 0x64 | 0x1 | **0x0641** |

**중요**: Coil 주소(FC 01/05)와 Holding Register 주소(FC 03/06)의 기본 주소가 동일하다. 포인트 번호는 동일하나 Function Code가 다르다. 같은 포인트 번호라도 FC에 따라 의미가 달라진다.

### 4.5 C 구현 — 주소 계산

```c
#define MODBUS_TYPE_INDOOR   0x0
#define MODBUS_TYPE_VENT     0x4
#define MODBUS_TYPE_AHU      0x8
#define MODBUS_TYPE_BOILER   0xC

uint16_t modbus_calc_address(uint8_t device_type, uint8_t device_addr,
                             uint8_t point) {
    return ((uint16_t)device_type << 12) |
           ((uint16_t)device_addr << 4)  |
           (point & 0x0F);
}

// 예: 실내기 5번의 포인트 3 (희망온도)
// modbus_calc_address(0x0, 5, 3) → 0x0053
```

## 5. 실내기 레지스터 리스트 (상세)

하나의 실내기 장치는 다음과 같은 포인트 리스트를 가진다. 일부 포인트는 제품에 따라 지원되지 않을 수 있다.

### 5.1 Coil 레지스터 (FC 01: 읽기 / FC 05: 쓰기)

Coil은 비트 단위(0 또는 1)로 동작하며, ON/OFF 상태 제어 및 모니터링에 사용된다.

| 포인트 | 설명 | FC | R/W | 값=0 | 값=1 |
|:-----:|------|:--:|:---:|-----|-----|
| 1 | **운전 설정 (On/Off)** | 01/05 | R/W | 정지 | 운전 |
| 2 | **풍향 조절** | 01/05 | R/W | 정지 | 운전 |
| 3 | **잠금** (전체) | 01/05 | R/W | 해제 | 잠금 |
| 4 | **모드 잠금** | 01/05 | R/W | 해제 | 잠금 |
| 5 | **풍량 잠금** | 01/05 | R/W | 해제 | 잠금 |
| 6 | **온도 잠금** | 01/05 | R/W | 해제 | 잠금 |
| 7 | **알람 (Alarm)** | 01 | R | 정상 | 비정상 |

**Coil 주소 계산 예시 (실내기 N번):**

```
포인트 1 (운전 설정): 0x0000 + (N << 4) + 0x0 = (N × 16)
포인트 2 (풍향 조절): 0x0000 + (N << 4) + 0x1
포인트 3 (잠금):       0x0000 + (N << 4) + 0x2
포인트 4 (모드 잠금):  0x0000 + (N << 4) + 0x3
포인트 5 (풍량 잠금):  0x0000 + (N << 4) + 0x4
포인트 6 (온도 잠금):  0x0000 + (N << 4) + 0x5
포인트 7 (알람):       0x0000 + (N << 4) + 0x6
```

> **참고**: Coil 포인트 번호 1~7은 주소 오프셋 0x0~0x6에 매핑된다 (포인트 - 1).

### 5.2 Holding Register (FC 03: 읽기 / FC 06: 쓰기)

Holding Register는 16비트 값으로 동작하며, 다중 값 제어 및 모니터링에 사용된다.

| 포인트 | 설명 | FC | R/W | 단위 | 값 정의 |
|:-----:|------|:--:|:---:|:---:|--------|
| 1 | **운전 모드** | 03/06 | R/W | — | 1: 냉방, 2: 제습, 3: 송풍, 4: 자동, 5: 난방 |
| 2 | **풍량 조절** | 03/06 | R/W | — | 1: 약, 2: 중, 3: 강, 4: 자동 |
| 3 | **희망 온도** | 03/06 | R/W | °C | 16~30 (°F: 60~86) |
| 4 | **상한 온도 설정** | 03/06 | R/W | °C | 18~30 (°F: 64~86) |
| 5 | **하한 온도 설정** | 03/06 | R/W | °C | 16~30 (°F: 60~86) |
| 6 | **실내 온도** | 03 | R | °C | 현재 실내 온도 |
| 7 | **에러 코드** | 03 | R | — | LG 에러 코드 리스트 참조 |
| 8 | **누적 전력량 (LOW)** | 03 | R | — | 하위 16비트 |
| 9 | **누적 전력량 (HIGH)** | 03 | R | — | 상위 16비트 |
| 10 | **누적 가스량 (LOW)** | 03 | R | — | 하위 16비트 |
| 11 | **누적 가스량 (HIGH)** | 03 | R | — | 상위 16비트 |

**Holding Register 주소 계산 예시 (실내기 N번):**

```
포인트 1 (운전 모드):      0x0000 + (N << 4) + 0x0
포인트 2 (풍량 조절):      0x0000 + (N << 4) + 0x1
포인트 3 (희망 온도):      0x0000 + (N << 4) + 0x2
포인트 4 (상한 온도):      0x0000 + (N << 4) + 0x3
포인트 5 (하한 온도):      0x0000 + (N << 4) + 0x4
포인트 6 (실내 온도):      0x0000 + (N << 4) + 0x5
포인트 7 (에러 코드):      0x0000 + (N << 4) + 0x6
포인트 8 (전력량 LOW):     0x0000 + (N << 4) + 0x7
포인트 9 (전력량 HIGH):    0x0000 + (N << 4) + 0x8
포인트 10 (가스량 LOW):    0x0000 + (N << 4) + 0x9
포인트 11 (가스량 HIGH):   0x0000 + (N << 4) + 0xA
```

### 5.3 누적 에너지 계산

**누적 전력량:**

```
누적 전력량 (100W 단위) = 누적전력량(HIGH) × 65536 + 누적전력량(LOW)
실제 전력량 (kWh) = 누적 전력량 × 0.1
```

**누적 가스량:**

```
누적 가스량 (100L 단위) = 누적가스량(HIGH) × 65536 + 누적가스량(LOW)
실제 가스량 (m³) = 누적 가스량 × 0.1
```

**C 구현:**

```c
// 누적 전력량 계산 (kWh)
float calc_energy_kwh(uint16_t high, uint16_t low) {
    uint32_t raw = ((uint32_t)high << 16) | low;
    return raw * 0.1f;  // 100W → kWh 변환
}

// 누적 가스량 계산 (m³)
float calc_gas_m3(uint16_t high, uint16_t low) {
    uint32_t raw = ((uint32_t)high << 16) | low;
    return raw * 0.1f;  // 100L → m³ 변환
}
```

## 6. 운전 모드 코드 상세

### 6.1 Modbus vs LGAP 운전 모드 코드 비교

ACP5 Modbus와 LGAP 프로토콜의 운전 모드 코드가 **다르다**는 점에 유의해야 한다.

| 운전 모드 | Modbus (ACP5) | LGAP (PI-485) | 비고 |
|---------|:------------:|:------------:|------|
| 냉방 (Cool) | **1** | **0** | 코드 차이 주의 |
| 제습 (Dry) | **2** | **1** | 코드 차이 주의 |
| 송풍 (Fan) | **3** | **2** | 코드 차이 주의 |
| 자동 (Auto) | **4** | **3** | 코드 차이 주의 |
| 난방 (Heat) | **5** | **4** | 코드 차이 주의 |

**변환 함수:**

```c
// Modbus → LGAP 모드 변환
uint8_t modbus_to_lgap_mode(uint8_t modbus_mode) {
    if (modbus_mode >= 1 && modbus_mode <= 5) {
        return modbus_mode - 1;  // Modbus 1~5 → LGAP 0~4
    }
    return 0;  // 기본값: 냉방
}

// LGAP → Modbus 모드 변환
uint8_t lgap_to_modbus_mode(uint8_t lgap_mode) {
    if (lgap_mode <= 4) {
        return lgap_mode + 1;  // LGAP 0~4 → Modbus 1~5
    }
    return 1;  // 기본값: 냉방
}
```

### 6.2 풍량 코드 비교

| 풍량 | Modbus (ACP5) | LGAP (PI-485) | 비고 |
|------|:------------:|:------------:|------|
| 약 (Low) | **1** | **1** | 동일 |
| 중 (Medium) | **2** | **2** | 동일 |
| 강 (High) | **3** | **3** | 동일 |
| 자동 (Auto) | **4** | **4** | 동일 |
| 미풍 (Quiet) | 미지원 | **5** | LGAP 전용 |
| 터보 (Turbo) | 미지원 | **6** | LGAP 전용 |

풍량 코드 1~4는 두 프로토콜에서 동일하나, LGAP에서만 미풍/터보 추가 옵션이 있다.

## 8. Modbus TCP 통신 구현

### 8.1 Modbus TCP 패킷 구조

```
┌──────────────────────────────┬────────────────────────┐
│     MBAP Header (7 bytes)    │    PDU (Variable)      │
├──────┬──────┬──────┬─────────┼────────┬───────────────┤
│TxnID │Proto │Length│ UnitID  │  FC    │   Data         │
│2byte │2byte │2byte│ 1byte   │ 1byte  │   N bytes      │
└──────┴──────┴──────┴─────────┴────────┴───────────────┘
```

| 필드 | 크기 | 설명 |
|------|:---:|------|
| Transaction ID | 2 | 요청/응답 매칭용 식별자 |
| Protocol ID | 2 | 항상 0x0000 (Modbus) |
| Length | 2 | 이후 바이트 수 (Unit ID + PDU) |
| Unit ID | 1 | Slave ID = ACP5의 Vnet Number |
| Function Code | 1 | 01, 03, 05, 06 중 하나 |
| Data | N | FC에 따라 다름 |

### 8.2 요청/응답 예제

#### 8.2.1 실내기 0번 전원 ON (Write Single Coil, FC 05)

```
요청:
  TxnID: 00 01
  Proto: 00 00
  Length: 00 06
  UnitID: 0A          (Vnet Number = 10)
  FC:     05          (Write Single Coil)
  Addr:   00 00       (실내기 0번, 포인트 1 = 운전설정)
  Value:  FF 00       (ON = 0xFF00)

응답:
  TxnID: 00 01
  Proto: 00 00
  Length: 00 06
  UnitID: 0A
  FC:     05
  Addr:   00 00
  Value:  FF 00       (확인)
```

#### 8.2.2 실내기 0번 운전 모드를 냉방(1)으로 설정 (Write Single Register, FC 06)

```
요청:
  TxnID: 00 02
  Proto: 00 00
  Length: 00 06
  UnitID: 0A
  FC:     06          (Write Single Register)
  Addr:   00 00       (실내기 0번, 포인트 1 = 운전모드)
  Value:  00 01       (1 = 냉방)

응답:
  TxnID: 00 02
  Proto: 00 00
  Length: 00 06
  UnitID: 0A
  FC:     06
  Addr:   00 00
  Value:  00 01       (확인)
```

#### 8.2.3 실내기 0번 상태 일괄 읽기 (Read Holding Registers, FC 03)

```
요청:
  TxnID: 00 03
  Proto: 00 00
  Length: 00 06
  UnitID: 0A
  FC:     03          (Read Holding Registers)
  Addr:   00 00       (시작 주소: 실내기 0번, 포인트 1)
  Count:  00 0B       (11개 레지스터 읽기)

응답:
  TxnID: 00 03
  Proto: 00 00
  Length: 00 19       (25 bytes)
  UnitID: 0A
  FC:     03
  ByteCnt: 16         (22 bytes = 11 registers × 2)
  Data:   00 01       (운전 모드 = 냉방)
          00 04       (풍량 = 자동)
          00 18       (희망 온도 = 24°C)
          00 1E       (상한 온도 = 30°C)
          00 10       (하한 온도 = 16°C)
          00 17       (실내 온도 = 23°C)
          00 00       (에러 코드 = 정상)
          01 F4       (전력량 LOW = 500)
          00 00       (전력량 HIGH = 0)
          00 00       (가스량 LOW = 0)
          00 00       (가스량 HIGH = 0)

→ 누적 전력량 = 0 × 65536 + 500 = 500 (100W 단위) = 50 kWh
```

## 9. BLE 특성 매핑 (XIAO-nRF52840)

ACP5 Modbus 레지스터와 BLE Characteristic의 대응 관계.

### 9.1 Modbus → BLE 데이터 매핑

| Modbus 항목 | Modbus FC | Modbus 포인트 | BLE Characteristic | BLE 바이트 |
|-----------|:---:|:---:|-------------------|---------|
| 운전 설정 (On/Off) | 01/05 | Coil 1 | Status (0x0002) | Byte 0, bit 0 |
| 운전 모드 | 03/06 | HR 1 | Status (0x0002) | Byte 1 |
| 풍량 조절 | 03/06 | HR 2 | Status (0x0002) | Byte 2 |
| 희망 온도 | 03/06 | HR 3 | Temperature (0x0003) | Byte 0 |
| 실내 온도 | 03 | HR 6 | Temperature (0x0003) | Byte 1~2 (×10) |
| 에러 코드 | 03 | HR 7 | Status (0x0002) | Byte 3 |
| 잠금 | 01/05 | Coil 3 | Status (0x0002) | Byte 0, bit 2 |
| 알람 | 01 | Coil 7 | Status (0x0002) | Byte 0, bit 7 |
| 누적 전력량 | 03 | HR 8~9 | Power (0x0005) | Byte 0~3 (32비트) |

### 9.2 모드 코드 변환 주의

BLE 전송 시 코드 체계를 통일해야 한다. 권장사항: **LGAP 코드 체계를 기준으로 통일** (0~4).

```c
// BLE에서 수신한 모드 코드는 LGAP 기준 (0~4)
// ACP5 Modbus와 연동할 경우에만 변환 필요

typedef struct {
    uint8_t power;        // 0: OFF, 1: ON
    uint8_t mode;         // 0: 냉방, 1: 제습, 2: 송풍, 3: 자동, 4: 난방 (LGAP 기준)
    uint8_t fan_speed;    // 1: 약, 2: 중, 3: 강, 4: 자동
    uint8_t target_temp;  // 16~30 °C
    int16_t room_temp;    // 실내 온도 × 10 (예: 235 = 23.5°C)
    uint8_t error_code;   // 0: 정상
    bool    locked;       // 잠금 상태
    bool    alarm;        // 알람 상태
    uint32_t energy_100w; // 누적 전력량 (100W 단위)
} indoor_unit_state_t;
```

## 10. LGAP 프로토콜과의 비교 요약

ACP5 Modbus TCP와 LGAP(PI-485) 프로토콜의 핵심 차이점 비교.

| 항목 | ACP5 Modbus TCP | LGAP (PI-485) |
|------|----------------|---------------|
| **물리 계층** | Ethernet (TCP/IP) | RS-485 |
| **통신 속도** | 100Mbps | 4,800 bps |
| **프로토콜** | 표준 Modbus TCP | LG 독자 프로토콜 |
| **접근 대상** | ACP5 중앙 제어기 | 실외기 (ODU) 직접 |
| **장치 제어** | ACP5 경유 | 실외기 경유 |
| **모드 코드** | 1~5 (냉/제/송/자/난) | 0~4 (냉/제/송/자/난) |
| **풍량 코드** | 1~4 (약/중/강/자) | 0~7 (추가 옵션 포함) |
| **온도 인코딩** | 직접 값 (16~30) | TX: 값-15 / RX: 별도 공식 |
| **온도 데이터** | 실내 온도만 | 실내 + 배관 입구/출구 |
| **에너지 데이터** | 누적 전력량/가스량 | 부하 지표 (Zone Load, ODU Load) |
| **잠금 기능** | 전체/모드/풍량/온도 개별 잠금 | 전체 잠금만 (기본) |
| **온도 상하한** | 설정 가능 | 프로토콜 미지원 |
| **필요 장비** | ACP5 + 네트워크 | RS-485 변환기 + PI-485 |
| **설치 복잡도** | 높음 (ACP5 필요) | 낮음 (직접 연결) |
| **비용** | 높음 | 낮음 |

## 11. 멀티 실내기 일괄 조회 구현

### 11.1 전략

ACP5 Modbus를 통해 여러 실내기를 효율적으로 조회하는 전략.

**방법 1: 개별 조회 (정확도 높음)**

```
실내기 0번: FC 03, Addr=0x0000, Count=11
실내기 1번: FC 03, Addr=0x0010, Count=11
실내기 2번: FC 03, Addr=0x0020, Count=11
...
```

**방법 2: 연속 조회 (효율적, 제한적)**

실내기 레지스터 간 간격이 16개(0x10)이고 사용 포인트가 11개이므로, 5개의 빈 레지스터가 존재한다. 연속 조회 시 최대 125개 레지스터 제한으로 약 7대까지 가능.

```
7대 일괄: FC 03, Addr=0x0000, Count=112 (7 × 16)
→ 응답에서 빈 레지스터(오프셋 0xB~0xF) 무시
```

### 11.2 C 구현 예시

```c
#define MAX_INDOOR_UNITS    256
#define REGS_PER_UNIT       16   // 실내기당 레지스터 블록 크기
#define USED_REGS_PER_UNIT  11   // 실제 사용 레지스터 수
#define MAX_REGS_PER_READ   125  // Modbus 최대 읽기 수
#define UNITS_PER_BATCH     7    // 한번에 읽을 실내기 수 (125/16=7)

typedef struct {
    uint8_t  unit_id;
    bool     online;
    indoor_unit_state_t state;
} indoor_unit_t;

// 실내기 N번 Holding Register 시작 주소
uint16_t indoor_hr_base(uint8_t n) {
    return (uint16_t)n << 4;  // n × 16
}

// 실내기 N번 Coil 시작 주소
uint16_t indoor_coil_base(uint8_t n) {
    return (uint16_t)n << 4;  // n × 16
}

// 응답 파싱 (단일 실내기)
void parse_indoor_hr(const uint16_t *regs, indoor_unit_state_t *st) {
    st->mode        = (uint8_t)regs[0];   // HR 포인트 1
    st->fan_speed   = (uint8_t)regs[1];   // HR 포인트 2
    st->target_temp = (uint8_t)regs[2];   // HR 포인트 3
    // regs[3]: 상한 온도
    // regs[4]: 하한 온도
    st->room_temp   = (int16_t)regs[5] * 10; // HR 포인트 6 (×10)
    st->error_code  = (uint8_t)regs[6];   // HR 포인트 7

    uint16_t e_low  = regs[7];   // HR 포인트 8
    uint16_t e_high = regs[8];   // HR 포인트 9
    st->energy_100w = ((uint32_t)e_high << 16) | e_low;
}
```

## 12. 에러 처리

### 12.1 Modbus 예외 응답

| 예외 코드 | 설명 | 원인 |
|:--------:|------|------|
| 0x01 | Illegal Function | 지원하지 않는 FC 사용 |
| 0x02 | Illegal Data Address | 잘못된 레지스터 주소 |
| 0x03 | Illegal Data Value | 범위 밖의 값 쓰기 |
| 0x04 | Server Device Failure | ACP5 내부 오류 |

### 12.2 연결 에러 처리

```c
typedef enum {
    MODBUS_OK = 0,
    MODBUS_ERR_TIMEOUT,       // 응답 없음

    MODBUS_ERR_INVALID_RESP,  // 응답 형식 오류

// 재시도 전략

### 실내기 N번 — Coil (FC 01/05)

```
운전 설정:  0x0000 + (N × 0x10) + 0x0
풍향 조절:  0x0000 + (N × 0x10) + 0x1

모드 잠금:  0x0000 + (N × 0x10) + 0x3
풍량 잠금:  0x0000 + (N × 0x10) + 0x4
온도 잠금:  0x0000 + (N × 0x10) + 0x5
알람:       0x0000 + (N × 0x10) + 0x6
```

### 실내기 N번 — Holding Register (FC 03/06)

```
운전 모드:       0x0000 + (N × 0x10) + 0x0
풍량 조절:       0x0000 + (N × 0x10) + 0x1
희망 온도:       0x0000 + (N × 0x10) + 0x2
상한 온도 설정:  0x0000 + (N × 0x10) + 0x3
하한 온도 설정:  0x0000 + (N × 0x10) + 0x4
실내 온도:       0x0000 + (N × 0x10) + 0x5
에러 코드:       0x0000 + (N × 0x10) + 0x6
전력량 (LOW):    0x0000 + (N × 0x10) + 0x7
전력량 (HIGH):   0x0000 + (N × 0x10) + 0x8
가스량 (LOW):    0x0000 + (N × 0x10) + 0x9
가스량 (HIGH):   0x0000 + (N × 0x10) + 0xA
```

### 환기 N번 — 기본 주소

```
Coil/HR 시작:    0x4000 + (N × 0x10)
```

### AHU N번 — 기본 주소

```
Coil/HR 시작 (장치주소×2):    0x8000 + (N × 2 × 0x10)
Coil/HR 시작 (장치주소×2+1):  0x8000 + ((N × 2 + 1) × 0x10)
```

```
Coil/HR 시작:    0xC000 + (N × 0x10)
