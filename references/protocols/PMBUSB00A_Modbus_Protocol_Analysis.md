# LG 시스템 에어컨 PMBUSB00A (Modbus RTU Gateway) 프로토콜 분석

작성일: 2026-09-14
대상: LG 시스템 에어컨 중앙 제어 / BMS 연동
기준 문서: LG PMBUSB00A Installation Guide, LG Gateway Specification (2021-03)

---

## 1. 개요 — PMBUSB00A는 어디에 놓이는가

PMBUSB00A는 LG 시스템 에어컨의 **실외기 측 통신 버스에 접속하여 이를 표준 Modbus RTU로 변환하는 게이트웨이 모듈**입니다.
즉, 이 프로젝트에서 이미 역공학한 **LGCP(실내기↔실외기 독자 RS-485 프로토콜)를 LG가 공식적으로 추상화해 내보내는 창구**가 PMBUSB00A입니다.

```
 ┌──────────────┐   LGCP (독자 RS-485)      ┌──────────────┐
 │   실내기 #1  │◀────────────────────────▶│              │
 │   실내기 #2  │   56 ... CRC16/XMODEM     │    실외기    │
 │   실내기 #N  │   주소 44550065~          │  (Multi V 5) │
 └──────────────┘                           └──────┬───────┘
                                                   │ 중앙제어 버스
                                            ┌──────┴───────┐
                                            │  PMBUSB00A   │  DC 12V
                                            │  Gateway     │
                                            └──────┬───────┘
                                                   │ RS-485
                                       Modbus RTU  │ 9600 8N1
                                                   ▼
                                            ┌──────────────┐
                                            │ Modbus Master│
                                            │ (BMS / PLC / │
                                            │  Go 게이트웨이)│
                                            └──────────────┘
```

**핵심 차이 — LGCP vs PMBUSB00A**

| 항목 | LGCP (역공학) | PMBUSB00A (공식) |
|------|--------------|------------------|
| 접근 난이도 | 프레임/CRC/인코딩 전부 직접 구현 | 표준 Modbus RTU 라이브러리로 즉시 사용 |
| 노출 정보 | 압축기 주파수, 제상 상태, 배관 온도, 용량 단계 등 **저수준 전부** | 전원/모드/풍량/온도/에러 등 **추상화된 상위 집합** |
| 제어 입도 | 압축기 Hz 직접 지정까지 가능 | 실내기 단위 사용자 제어만 |
| 안정성 | 펌웨어 변경 시 깨질 위험 | LG가 스펙 보증 |
| 규모 | 버스 물리 한계 | 모듈당 16대, 4모듈 조합 시 64대 |

> **설계 권고**: 제어·BMS 연동은 PMBUSB00A(Modbus)로, 압축기 주파수·제상 사이클 같은 진단용 저수준 데이터는 기존 LGCP 스니핑으로 — 두 경로를 병행하는 것이 가장 실용적입니다.

## 2. 하드웨어 및 통신 사양

| 항목 | 값 |
|------|-----|
| 모델명 | PMBUSB00A |
| 프로토콜 | Modbus RTU over RS-485 |
| Baud Rate | **9,600 bps** |
| Data Bits | 8 |
| Parity | **None** |
| Stop Bit | **1** |
| 프레이밍 | 9600-8N1, 3.5 char silent interval (≈4 ms) |
| CRC | **CRC-16/MODBUS** (poly 0xA001 reflected, init 0xFFFF, **Little-Endian** 전송) |
| 전원 | DC 12 V |
| 크기 | 53.6 × 89.7 × 60.7 mm |
| 접속 대수 | 모듈 1개 = 최대 16 IDU / 4개 조합 = 최대 64 IDU |
| 지원 기기 | MULTI V 5, MULTI V S, ERV(환기), THERMA V(하이드로킷) |

> ⚠️ **CRC 주의**: LGCP는 CRC-16/**XMODEM**(0x1021, init 0, Big-Endian)이지만, Modbus 구간은 CRC-16/**MODBUS**(0xA001, init 0xFFFF, Little-Endian)입니다. 두 프로토콜을 한 프로세스에서 다룰 때 CRC 함수를 혼용하지 않도록 분리하십시오.

## 3. 주소 체계

### 3.1 Modbus 슬레이브 주소 (DIP 스위치 SW_02M)

게이트웨이 자체의 슬레이브 주소는 **1~16**이며 보드의 4비트 DIP 스위치로 설정합니다. 공장 출하 기본값은 **1**입니다.

| 주소 | SW1 | SW2 | SW3 | SW4 |
|:----:|:---:|:---:|:---:|:---:|
| 1 | OFF | OFF | OFF | OFF |
| 2 | OFF | OFF | OFF | ON |
| 3 | OFF | OFF | ON | OFF |
| 4 | OFF | OFF | ON | ON |
| 5 | OFF | ON | OFF | OFF |
| 6 | OFF | ON | OFF | ON |
| 7 | OFF | ON | ON | OFF |
| 8 | OFF | ON | ON | ON |
| 9 | ON | OFF | OFF | OFF |
| 10 | ON | OFF | OFF | ON |
| 11 | ON | OFF | ON | OFF |
| 12 | ON | OFF | ON | ON |
| 13 | ON | ON | OFF | OFF |
| 14 | ON | ON | OFF | ON |
| 15 | ON | ON | ON | OFF |
| 16 | ON | ON | ON | ON |

즉 DIP는 `주소 = (SW1<<3 | SW2<<2 | SW3<<1 | SW4) + 1` 의 2진 인코딩입니다.

### 3.2 실내기 주소 N

각 실내기는 실외기에서 설정된 **중앙 제어 주소(Indoor Unit Central Address) N** 으로 구분되며, 이 N이 Modbus 레지스터 오프셋을 결정합니다. 모듈 1개가 담당하는 범위가 16대이므로 **N = 0 ~ 15** 입니다.

> 기존 LGCP 캡처의 실내기 주소 `0x44550065 / 66 / 67`은 LGCP 버스 상의 물리 주소이고, Modbus의 N은 **실외기에 설정된 중앙 주소(0부터)** 입니다. 두 값은 별개이므로, 현장에서 "N ↔ 실제 실내기" 매핑은 한 대씩 켜 보며 확인해야 합니다.

## 4. 레지스터 맵

### 4.1 주소 계산식

| 영역 | Function Code | 계산식 |
|------|--------------|--------|
| Coil (읽기/쓰기) | 01 / 05 / 15 | **Register = N × 16 + 항목번호** |
| Discrete Input (읽기 전용) | 02 | **Register = N × 16 + 항목번호** |
| Holding Register (읽기/쓰기) | 03 / 06 / 16 | **Register = N × 20 + 항목번호** |
| Input Register (읽기 전용) | 04 | **Register = N × 20 + 항목번호** |

> ⚠️ **1-base / 0-base 주의**: 매뉴얼의 `00001`, `10001`, `40001`, `30001`은 **Modbus 레지스터 "번호"(1-base)** 표기입니다. 실제 전송 프레임에 들어가는 **프로토콜 주소는 0-base**이므로 1을 빼야 합니다.
> 예) IDU N=0 전원 코일 = 번호 00001 → **프레임 주소 0x0000**
> 예) IDU N=3 설정온도 = 번호 40001 + 3×20 + 2 = 40063 → **프레임 주소 3×20+2 = 62 (0x003E)**

### 4.2 Coil — FC 01 (읽기) / 05, 15 (쓰기)

`Register = N × 16 + ①~⑩`

| 항목번호 | 기능 | 값 | 적용 기기 |
|:-------:|------|-----|----------|
| ① | **운전 On/Off** | 0 = 정지 / 1 = 운전 | 공통 |
| ② | 자동 풍향 스윙 | 0 = 해제 / 1 = 동작 | 에어컨 |
| ③ | 필터 알람 해제 | 0 = 정상 / 1 = 알람 해제 | 공통 |
| ④ | 리모컨 전체 잠금 | 0 = 해제 / 1 = 잠금 | 공통 |
| ⑤ | 운전 모드 잠금 | 0 = 해제 / 1 = 잠금 | 공통 |
| ⑥ | 풍량 잠금 | 0 = 해제 / 1 = 잠금 | 공통 |
| ⑦ | 설정 온도 잠금 | 0 = 해제 / 1 = 잠금 | 공통 |
| ⑧ | 실내기 주소 잠금 | 0 = 해제 / 1 = 잠금 | 공통 |
| ⑨ | 급속 환기 | 0 = 해제 / 1 = 동작 | 환기(ERV) |
| ⑩ | 에너지 절약 | 0 = 해제 / 1 = 동작 | 환기(ERV) |

### 4.3 Discrete Input — FC 02 (읽기 전용)

`Register = N × 16 + ①~⑤`

| 항목번호 | 번호 표기 | 기능 | 값 |
|:-------:|:--------:|------|-----|
| ① | 10001 | **실내기 연결 상태** | 0 = 미연결 / 1 = 연결 |
| ② | 10002 | **알람(에러) 발생** | 0 = 정상 / 1 = 알람 |
| ③ | 10003 | 필터 알람 | 0 = 정상 / 1 = 알람 |
| ④ | 10004 | 목표 온도 기준 선택 | 0 = 공기 / 1 = 물 (하이드로킷) |
| ⑤ | 10005 | 에러 구분 | 0 = CH 타입 / 1 = BC 타입 (하이드로킷) |

> ①(연결 상태)은 **시스템 스캔의 출발점**입니다. 기동 시 FC 02로 주소 0~255를 한 번에 읽으면 어떤 N이 실제 설치되어 있는지 16 bit 단위로 즉시 파악할 수 있습니다.

### 4.4 Holding Register — FC 03 (읽기) / 06, 16 (쓰기)

`Register = N × 20 + ①~⑥`

| 항목번호 | 번호 표기 | 기능 | 값 인코딩 |
|:-------:|:--------:|------|----------|
| ① | 40001 | **운전 모드** | 0 = 냉방, 1 = 제습, 2 = 송풍, 3 = 자동, 4 = 난방 |
| ② | 40002 | **풍량** (또는 급탕 온도) | 1 = 약, 2 = 중, 3 = 강, 4 = 자동 |
| ③ | 40003 | **설정 온도** | 16.0 ~ 30.0 °C (**×10**, 즉 160 ~ 300) |
| ④ | 40004 | 설정 온도 상한 제한 | 16.0 ~ 30.0 °C (×10) |
| ⑤ | 40005 | 설정 온도 하한 제한 | 16.0 ~ 30.0 °C (×10) |
| ⑥ | 40006 | 환기 운전 모드 | 0 = 열교환, 1 = 자동, 2 = 보통 (ERV) |

### 4.5 Input Register — FC 04 (읽기 전용)

`Register = N × 20 + ①~⑥`

| 항목번호 | 번호 표기 | 기능 | 값 인코딩 |
|:-------:|:--------:|------|----------|
| ① | 30001 | **에러 코드** | 0 ~ 255 (0 = 정상, 제품별 에러 코드표 참조) |
| ② | 30002 | **실내 온도** | −99.0 ~ +99.0 °C (×10, **부호 있는 16bit**) |
| ③ | 30003 | 배관 입구 / 입수 온도 | −99.0 ~ +99.0 °C (×10) |
| ④ | 30004 | 배관 출구 / 출수 온도 | −99.0 ~ +99.0 °C (×10) |
| ⑤ | 30005 | 급탕 탱크 온도 | −99.0 ~ +99.0 °C (×10, 하이드로킷) |
| ⑥ | 30006 | 태양열 온도 | −99.0 ~ +99.0 °C (×10, AWHP) |

> 온도 값은 음수를 표현하므로 **반드시 signed int16으로 해석**해야 합니다. 예: `0xFFC4` = −60 = −6.0 °C.

## 5. Modbus RTU 프레임 예제 (CRC 포함, 슬레이브 주소 = 1)

아래는 그대로 시리얼에 흘려보낼 수 있는 완성 프레임입니다 (CRC-16/MODBUS, LSB 먼저).

| 동작 | 전송 프레임 (hex) |
|------|------------------|
| IDU 0 전원 **ON** (FC05) | `01 05 00 00 FF 00 8C 3A` |
| IDU 0 전원 **OFF** (FC05) | `01 05 00 00 00 00 CD CA` |
| IDU 3 전원 **ON** (FC05, coil 48) | `01 05 00 30 FF 00 8C 35` |
| IDU 0 **난방 모드** (FC06, hold 0 = 4) | `01 06 00 00 00 04 88 09` |
| IDU 0 **풍량 강** (FC06, hold 1 = 3) | `01 06 00 01 00 03 98 0B` |
| IDU 0 **설정온도 24.0 °C** (FC06, hold 2 = 240) | `01 06 00 02 00 F0 28 4E` |
| IDU 3 **설정온도 26.0 °C** (FC06, hold 62 = 260) | `01 06 00 3E 01 04 E8 55` |
| IDU 0 **모드+풍량+온도 일괄** (FC16, hold 0~2) | `01 10 00 00 00 03 06 00 04 00 03 00 F0 E7 04` |
| IDU 0 상태 읽기 (FC03, hold 0~5) | `01 03 00 00 00 06 C5 C8` |
| IDU 0 센서 읽기 (FC04, input 0~5) | `01 04 00 00 00 06 70 08` |
| IDU 0 상태비트 읽기 (FC02, discrete 0~4) | `01 02 00 00 00 05 B8 09` |
| IDU 0 코일 상태 읽기 (FC01, coil 0~9) | `01 01 00 00 00 0A BC 0D` |
| **전 실내기 연결/알람 스캔** (FC02, 0~255) | `01 02 00 00 01 00 79 9A` |

### 5.1 응답 해석 예

`01 04 00 00 00 06` (IDU 0 Input 6워드 읽기)에 대한 응답이

```
01 04 0C 0000 00F5 00D2 00E8 0000 0000 <CRC>
```

라면:

| 워드 | 값 | 해석 |
|------|-----|------|
| 30001 | 0x0000 = 0 | 에러 없음 |
| 30002 | 0x00F5 = 245 | 실내 온도 **24.5 °C** |
| 30003 | 0x00D2 = 210 | 배관 입구 21.0 °C |
| 30004 | 0x00E8 = 232 | 배관 출구 23.2 °C |
| 30005 | 0 | 미사용(에어컨) |
| 30006 | 0 | 미사용 |

## 6. 마스터 측 구현 설계 권고

### 6.1 폴링 전략

| 데이터 | 권장 주기 | 함수 | 비고 |
|--------|----------|------|------|
| 연결/알람 비트맵 (전체) | 30 s | FC 02, 0~255 | 1트랜잭션으로 16대 × 16bit 전부 |
| 상태값 (모드/풍량/온도) | 5 ~ 10 s | FC 03, N×20, 6워드 | 실내기 1대 = 1트랜잭션 |
| 센서값 (실내온도/에러) | 5 ~ 10 s | FC 04, N×20, 6워드 | |
| 코일 상태 | 5 ~ 10 s | FC 01, N×16, 10bit | 전원 상태 확인 |
| 제어 명령 | 이벤트 | FC 05 / 06 / 16 | 전송 후 반드시 read-back |

9,600 bps에서 8바이트 요청 + 17바이트 응답 ≈ 26 ms + 처리 지연이므로, 실내기 16대를 4종 영역 모두 폴링하면 한 사이클에 대략 2~4초가 소요됩니다. **5초 주기가 현실적인 하한**이며, 그보다 빠르게 돌리면 게이트웨이가 응답을 거르기 시작합니다.

### 6.2 제어 시 주의

1. **쓰기 후 즉시 반영되지 않음**: 게이트웨이가 LGCP 버스로 명령을 중계하고 실내기가 수락하기까지 수 초가 걸립니다. 쓰기 직후의 read-back은 이전 값을 돌려줄 수 있으므로 **2~5초 후 재확인**하십시오.
2. **잠금 코일과의 충돌**: ④~⑧ 잠금 코일이 설정된 상태에서는 해당 항목의 쓰기가 무시됩니다. 제어가 먹지 않으면 먼저 잠금 상태부터 확인하십시오.
3. **설정 온도 범위 제한**: 40004/40005(상·하한)를 넘는 값을 쓰면 클램핑되거나 거부됩니다.
4. **미설치 N에 대한 쓰기**: 예외 응답 없이 조용히 무시될 수 있으므로, 항상 Discrete ①(연결 상태)로 존재를 먼저 확인하십시오.
5. **모드 전환 직후 풍량/온도**: LGCP 분석에서 확인되었듯 에어컨은 **모드별로 마지막 온도·풍량을 기억**합니다. 모드만 바꾸면 온도가 함께 바뀝니다 — 모드·온도·풍량은 FC 16으로 **한 번에 쓰는 것이 안전**합니다.

### 6.3 Go 구현 스케치

```go
package lgmodbus

import (
    "fmt"
    "time"
    "github.com/goburrow/modbus"
)

type Mode uint16

const (
    ModeCool Mode = 0
    ModeDry  Mode = 1
    ModeFan  Mode = 2
    ModeAuto Mode = 3
    ModeHeat Mode = 4
)

type Fan uint16

const (
    FanLow  Fan = 1
    FanMid  Fan = 2
    FanHigh Fan = 3
    FanAuto Fan = 4
)

// 주소 계산
func coilAddr(n, item uint16) uint16 { return n*16 + item } // item: 0-base (①=0)
func holdAddr(n, item uint16) uint16 { return n*20 + item }
func inAddr(n, item uint16) uint16   { return n*20 + item }

type Gateway struct{ c modbus.Client }

func NewGateway(port string, slaveID byte) (*Gateway, error) {
    h := modbus.NewRTUClientHandler(port)
    h.BaudRate, h.DataBits, h.Parity, h.StopBits = 9600, 8, "N", 1
    h.SlaveId = slaveID
    h.Timeout = 1 * time.Second
    if err := h.Connect(); err != nil {
        return nil, err
    }
    return &Gateway{c: modbus.NewClient(h)}, nil
}

func (g *Gateway) Power(n uint16, on bool) error {
    v := uint16(0x0000)
    if on {
        v = 0xFF00
    }
    _, err := g.c.WriteSingleCoil(coilAddr(n, 0), v)
    return err
}

// 모드·풍량·온도를 한 트랜잭션으로 (FC16)
func (g *Gateway) SetAll(n uint16, m Mode, f Fan, tempC float64) error {
    t := uint16(tempC * 10)
    if t < 160 || t > 300 {
        return fmt.Errorf("temp out of range: %.1f", tempC)
    }
    payload := []byte{
        byte(m >> 8), byte(m),
        byte(f >> 8), byte(f),
        byte(t >> 8), byte(t),
    }
    _, err := g.c.WriteMultipleRegisters(holdAddr(n, 0), 3, payload)
    return err
}

type Sensors struct {
    ErrorCode uint16
    RoomTemp  float64 // °C
    PipeIn    float64
    PipeOut   float64
}

func (g *Gateway) ReadSensors(n uint16) (*Sensors, error) {
    b, err := g.c.ReadInputRegisters(inAddr(n, 0), 4)
    if err != nil {
        return nil, err
    }
    w := func(i int) int16 { return int16(uint16(b[i*2])<<8 | uint16(b[i*2+1])) }
    return &Sensors{
        ErrorCode: uint16(w(0)),
        RoomTemp:  float64(w(1)) / 10,
        PipeIn:    float64(w(2)) / 10,
        PipeOut:   float64(w(3)) / 10,
    }, nil
}
```

## 7. 기존 LGCP 역공학 결과와의 대응 관계

| 의미 | LGCP (독자 프로토콜) | PMBUSB00A (Modbus) |
|------|---------------------|-------------------|
| 전원 ON/OFF | `[18 40]` / `[18 41]` (reg 0x18, attr 0x4_) | Coil `N×16 + 0` |
| 운전 모드 | `[64 50 XY]` 하위 니블 Y<br>0=냉방 1=제습 2=송풍 3=자동 4=난방 | Holding `N×20 + 0`<br>**동일 코드 체계 (0~4)** ✅ |
| 풍량 | `[64 50 XY]` 상위 니블 X, `[71 0V]`<br>1=약 2=중 3=강 **4=초강 5=자동** | Holding `N×20 + 1`<br>1=약 2=중 3=강 **4=자동** ⚠️ |
| 설정 온도 | `[64 8V]`, °C = V + 15 (15~30 °C, 1 °C 단위) | Holding `N×20 + 2`, °C ×10 (16.0~30.0) |
| 실내 온도 | 응답 reg `0x74` (`0x90+V`) | Input `N×20 + 1` (×10) |
| 배관 온도 | 응답 reg `0x61`, `0x62` (`0xD0+V`) | Input `N×20 + 2`, `+3` (×10) |
| 에러 / 알람 | 별도 식별 안 됨 | Input `N×20 + 0` + Discrete `N×16 + 1` |
| 압축기 주파수 | `[18 90 HH]` (16~120 Hz) | **노출되지 않음** ❌ |
| 제상(Defrost) 상태 | `[13 C3]` | **노출되지 않음** ❌ |
| 압축기 용량 단계 | `[18 8V]` (0~15) | **노출되지 않음** ❌ |
| 필터 알람 | 미확인 | Discrete `N×16 + 2`, Coil `N×16 + 2` (해제) |
| 리모컨 잠금 | 미확인 | Coil `N×16 + 3` ~ `+7` |

### 7.1 주목할 두 가지 불일치

1. **운전 모드 코드가 정확히 일치합니다.** LGCP의 `64,50,XY` 하위 니블(0=냉방, 1=제습, 2=송풍, 3=자동, 4=난방)과 Modbus Holding ①이 같은 코드입니다. → 역공학 결과가 LG 내부 코드 체계와 맞았다는 강한 교차 검증입니다.
2. **풍량 코드는 어긋납니다.** LGCP는 5단계(1~4단 + 자동=5)인데 Modbus는 4값(1~3단 + 자동=4)만 정의합니다. 4단(초강)이 Modbus에서 어떻게 매핑되는지는 **실측 확인이 필요**합니다 — 3(강)으로 흡수되거나, 값 4를 쓰면 자동이 아니라 초강이 될 가능성이 있습니다.

## 8. 검증 체크리스트 (현장 실측 필요 항목)

| # | 확인 항목 | 방법 | 우선순위 |

| 1 | **설정 온도 스케일 ×10 여부** | 리모컨으로 24 °C 설정 후 Holding ② 읽기 → 240인지 24인지 확인 | ★★★ |
| 2 | **N의 0-base 여부** | 실내기 1대만 전원 투입 후 FC02 0~255 스캔, 어느 비트가 1인지 확인 | ★★★ |
| 3 | 풍량 값 4의 실제 동작 | 4 기록 후 리모컨 표시 확인 (자동인지 초강인지) | ★★ |
| 4 | 쓰기 반영 지연 시간 | FC05 ON 직후 100 ms 간격 read-back, 값이 바뀌는 시점 측정 | ★★ |
| 5 | 실내 온도 음수 표현 | 겨울철 또는 동결 시험으로 signed 여부 확인 | ★ |

## 9. 제한 사항

- 본 문서의 레지스터 맵은 LG PMBUSB00A 설치 매뉴얼(Loxone 라이브러리 배포본)의 Modbus 메모리 맵 표를 근거로 정리한 것이며, 펌웨어 버전·실외기 기종에 따라 일부 항목의 지원 여부가 달라질 수 있습니다.
- 매뉴얼에 기재된 레지스터는 Holding ①~⑥, Input ①~⑥, Coil ①~⑩, Discrete ①~⑤가 전부이며, **그 이상의 확장 레지스터는 공식 문서에 없습니다.**
- 전력량·소비전력 계측은 PMBUSB00A로 제공되지 않습니다. 필요 시 별도 전력 미터 또는 LG ACP/AC Smart 계열 상위 컨트롤러가 필요합니다.
- 압축기 주파수·제상 상태 등 저수준 진단 정보는 기존 LGCP 스니핑 경로를 유지해야 얻을 수 있습니다.
