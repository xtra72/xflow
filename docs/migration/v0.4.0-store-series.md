# Store v0.4.0 시리즈 모델 마이그레이션 가이드

> `@spec SPEC-STORE-004` — Store 저장 아이템 식별을 단일 string key 에서
> `(key, metric_type, sorted(tags))` 복합 식별(시리즈) 모델로 전환하는 운영자 가이드.

## 핵심 요약

- **모델 변경**: "key 1개 = 아이템 1개" → "key 1개 = 시리즈 N개".
  같은 key 라도 `metric_type` 또는 `tags`(정규화 후)가 다르면 **독립 시리즈**로 저장된다.
- **저장 키 인코딩**: 최종 저장 키 = `namespace + ":" + EncodeSeriesKey(SeriesID)`.
  `EncodeSeriesKey` 형식은 `metric_type|tagsEncoded|key` (예: `temperature|area=a|room`).
- **영속 정합**: 영속 백엔드(`PersistentStore`/`StoreRepository`)는 시리즈를 모른 채
  **불투명 string 키**만 다룬다. 시리즈 인코딩은 상위 `SetWithMeta`(system 계층)가 수행하므로,
  영속 계층의 인터페이스/시그니처 변경은 **없다**.

## 인메모리 데이터 (대부분의 경우): 변환 불필요

가정 A6: 운영 store 에이전트는 현재 `VolatileStore`(인메모리)만 사용한다 (가정 A1).
인메모리 데이터는 **재시작 시 휘발**되므로 별도 변환이 불필요하다. 재시작 후 신규 쓰기가
시리즈 모델로 자연 흡수된다.

YAML `staticKeys` 정의는:

- `metric_type`/`tags` 가 있으면 해당 시리즈로 로드된다.
- 없으면 `(key, "unknown", {})` 기본 시리즈로 로드된다.

## 영속 데이터 (영속 백엔드 활성 시에만): 일회성 마이그레이션

가정 A1: 현재 활성 영속 백엔드(`StoreRepository` 구현)는 **존재하지 않는다**.
아래 절차는 **향후 영속 백엔드가 활성화된 경우에만** 필요하다.

### 변환 규칙

시리즈 도입 이전의 bare key(예: `room`)를 `(key, "unknown", {})` 기본 시리즈
인코딩 키(예: `unknown||room`)로 변환한다.

- 이미 시리즈 인코딩된 키(`DecodeSeriesKey` 성공 + round-trip 일치)는 **건너뛴다** (멱등).
- `data_type`/`tags`/`metric_type` 메타는 변환으로 생성하지 않는다 — bare key 는 정보가 없으므로
  기본 시리즈로만 흡수된다.

### 안전 장치 (데이터 손실 방지)

| 장치 | 설명 |
| --- | --- |
| 변환 전 백업 | 변환 대상 엔트리를 sha256 manifest 로 백업 (`value_sha256_sum`, per-key sha256). |
| dry-run 우선 | `--dry-run`: 무엇이 어떻게 바뀌는지 출력만, 리포지토리 무변경. |
| 멱등성 | 재실행 시 이미 시리즈 키는 건너뜀 — 추가 변환 없음. |
| 변환 후 검증 | 변환 건수 + value sha256 합산이 백업과 일치하는지 확인. |
| 손실 방지 순서 | 각 키는 `SetEntry(new)` → `DeleteEntry(old)` 순서. 중간 실패 시에도 한쪽은 보존. |

### 사용법

현 상태(영속 백엔드 부재)에서는 안내 후 noop 으로 종료한다:

```bash
xflowd migrate store-series
# store-series: 활성 영속 store 백엔드가 없습니다 — 변환 대상 없음 (noop).
#   - 인메모리(VolatileStore) 데이터는 재시작 시 휘발되므로 변환이 불필요합니다 (A6).
#   - 현재 store 에이전트 런타임은 VolatileStore 만 사용합니다 (A1).
#   - 영속 백엔드 활성화 시: internal/migrate/storeseries.NewPlanner 로 Plan/Apply 를 수행하세요.
```

dry-run 미리보기 (영속 백엔드 활성 시):

```bash
xflowd migrate store-series --dry-run
```

향후 영속 백엔드 활성화 시, 변환 로직은 `internal/migrate/storeseries` 패키지의
`NewPlanner(repo, Options{...})` → `Plan(ctx)` → `Apply(ctx)` 흐름으로 수행한다.
`repo` 는 그 영속 백엔드의 `storeseries.Repository`(= `system.StoreRepository` 의 부분집합) 구현이다.

### dry-run 출력 예시

```
Plan summary: convert=2 already-series=1
  [convert]
    "device-uuid-1234" -> "unknown||device-uuid-1234"
    "room" -> "unknown||room"
  [already-series] 1 keys (idempotent, will be left as-is)
dry-run: 2 개 키 변환이 예정됨 (실제 변경 없음)
Result: converted=0 skipped=1 verified=false dry-run=true
```

## API/UI 영향 (참고)

- `POST /query`: `metric_type`/`tags` 필터 추가, 응답에 `labels`(시리즈 출처) 채움.
  필터 생략 시 해당 key 의 **모든 시리즈** 반환.
- `GET /keys`: 행 단위가 key → **시리즈**로 변경 (각 행 = `key, metric_type, tags, data_type, registration`).
- `DELETE`: 단일 시리즈 대상화 (식별자 metric/tags 지정).
