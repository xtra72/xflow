# SPEC-CANVAS-009 수락 기준

## 1. 복합 키 (M2)

### AC-01: 왕복이 성립한다

**Given** 노드 id `a` 와 부품 id `b` 가 있을 때
**When** `parseFrameKey(frameKey(a, b))` 를 부르면
**Then** `{ nodeId: a, partId: b }` 를 돌려주어야 한다

### AC-02: 최상위 키는 부품 자리가 빈다

**When** `parseFrameKey(frameKey(a))` 를 부르면
**Then** `{ nodeId: a }` 이고 `partId` 는 `undefined` 여야 한다

### AC-03: 분해는 첫 구분자에서 한 번만 쪼갠다

**Given** 부품 id 에 구분자가 들어간 키 `grp-1/a/b` 가 있을 때
**When** 분해하면
**Then** `nodeId` 는 `grp-1`, `partId` 는 `a/b` 여야 한다

> 뒤에서 쪼개거나 전부 쪼개면 `nodeId` 가 오염된다. 그 오염은 "어떤 그룹은 선택이 안 된다"
> 로만 보인다.

### AC-04: 판별이 한 자리에서만 이뤄진다

**When** 소스를 검사하면
**Then** `frameKey.ts` 바깥에 구분자 리터럴을 쓰는 분해 코드가 없어야 한다

## 2. 부품 선택 (M3)

### AC-05: 부품을 누르면 부품이 선택된다

**Given** 그룹 `grp-1` 의 부품 `body` 위 좌표가 있을 때
**When** 캔버스에서 그 지점을 누르면
**Then** 선택 상태에 `grp-1/body` 가 들어가야 한다

### AC-06: 최상위 선택 키가 004 와 바이트 동일하다

**When** 최상위 요소 `el-3` 을 누르면
**Then** 선택 상태에 들어가는 문자열이 정확히 `el-3` 이어야 한다

> 이 AC 가 009 전체의 안전줄이다. 여기가 깨지면 001·002·004 의 선택 시험이 전부 흔들린다.

### AC-07: 부품과 그룹이 동시에 선택되지 않는다

**When** 부품이 선택되면
**Then** 그 부품을 담은 그룹의 id 는 선택 상태에 없어야 한다

### AC-08: 부품 선택은 하나뿐이다

**Given** 부품 `grp-1/body` 가 선택된 상태에서
**When** 다른 부품 `grp-1/head` 를 누르면
**Then** 선택 상태에 부품 키가 정확히 하나 있어야 한다

### AC-09: 그룹 상자의 빈 곳은 부품을 선택하지 않는다

**Given** 그룹 상자 안이지만 어느 부품에도 닿지 않는 지점에서
**When** 누르면
**Then** 그 그룹의 부품이 선택되지 않아야 한다 (004 AC-E11 의 성질 유지)

## 3. 핸들 (M3)

### AC-10: 선택된 부품에 핸들이 선다

**Given** 부품이 선택되어 있을 때
**When** 핸들 자리를 구하면
**Then** 여덟 자리가 **부품의 투영 상자**에 놓여야 한다

### AC-11: 그룹만 선택되면 핸들은 그룹 상자에 선다

**Given** 부품 선택 없이 그룹만 선택되어 있을 때
**When** 핸들 자리를 구하면
**Then** 004 와 동일하게 그룹 상자에 여덟 자리가 놓여야 한다

### AC-12: 핸들이 두 상자에 동시에 서지 않는다

**When** 어떤 선택 상태에서든 핸들 자리를 구하면
**Then** 한 벌만 나와야 한다

## 4. 부품 기하 쓰기 (M4)

### AC-13: 부품을 끌면 저장 좌표가 바뀐다

**Given** 그룹 상자가 캔버스 좌표 (100,100)-(300,300) 이고 부품이 로컬 (0,0)-(5000,5000) 일 때
**When** 캔버스 절대 좌표로 (+20,+20) 만큼 끌면
**Then** 부품의 저장 좌표가 그 이동에 대응하는 로컬 값으로 바뀌어야 한다

### AC-14: 그룹 상자는 바뀌지 않는다

**When** 부품 기하를 고치면
**Then** 그룹의 `geometry` 가 한 자리도 바뀌지 않아야 한다

### AC-15: 형제는 참조 그대로다

**When** 부품 하나를 고치면
**Then** 형제 노드와 형제 부품의 객체 참조가 유지되고 새 배열이 나와야 한다

### AC-16: 역투영 자리가 늘지 않는다

**When** 소스를 검사하면
**Then** `toLocalGeometry` · `toAbsoluteGeometry` 를 부르는 자리가 `groupOps.ts` 안에만
있어야 한다

### AC-17: 기하 쓰기 모듈이 `parts` 를 모른다

**When** `canvasEditGeometry.ts` 를 검사하면
**Then** `parts` 필드를 대입하는 자리가 없어야 한다 (004 의 기존 시험 유지)

### AC-18: 부품이 그룹 상자를 넘어도 막지 않는다

**When** 부품을 그룹 상자 밖으로 끌면
**Then** 좌표가 clamp 되지 않고 그대로 저장되어야 한다

## 5. 부품 속성 편집 (M5)

### AC-19: 부품 행이 겉모습 칸을 낸다

**When** 부품 행을 펼치면
**Then** `fill` · `stroke` · `opacity` 등 겉모습 칸이 나와야 한다

### AC-20: 최상위 요소 행과 같은 컨트롤을 쓴다

**When** 부품 행의 색 입력을 검사하면
**Then** 최상위 요소 행이 쓰는 것과 같은 컨트롤이어야 한다 (새 컨트롤을 짓지 않는다)

### AC-21: 기하 칸이 캔버스 단위로 말한다

**Given** 그룹 상자가 (100,100)-(300,300) 이고 부품이 로컬 격자 한가운데 있을 때
**When** 부품 행의 기하 칸을 읽으면
**Then** 캔버스 단위 값(200 근방)이 보여야 하며, 로컬 격자 값(5000)이 보여서는 안 된다

### AC-22: 그룹 로컬 격자가 화면에 없다

**When** 화면 전체를 검사하면
**Then** `GROUP_LOCAL_EXTENT` 범위의 숫자가 사용자에게 노출되지 않아야 한다

### AC-23: 부품 행을 누르면 부품이 선택된다

**When** 목록에서 부품 행을 누르면
**Then** 선택 상태에 그 부품의 복합 키가 들어가야 한다

> 004 는 여기서 **그룹**을 선택했다. 이 AC 가 뒤집힌 조항이다.

## 6. 부품 분리 (M6)

### AC-24: 분리한 부품이 최상위로 올라온다

**Given** 부품 3 개인 그룹에서
**When** 부품 하나를 분리하면
**Then** 최상위 배열에 그 부품이 요소로 나타나고, 그룹의 부품은 2 개가 되어야 한다

### AC-25: 분리된 부품이 그룹 바로 뒤에 놓인다

**When** 분리하면
**Then** 최상위 배열에서 분리된 요소의 자리가 그룹 바로 다음이어야 한다

### AC-26: 좌표가 절대 좌표로 환산된다

**Given** 그룹 상자가 (100,100)-(300,300) 이고 부품이 로컬 (0,0)-(5000,5000) 일 때
**When** 분리하면
**Then** 올라온 요소의 기하가 캔버스 절대 좌표여야 하고, 화면에서 자리가 움직이지 않아야 한다

### AC-27: 겉모습이 보존된다

**Given** 그룹에 `fill: red`, 부품에 `stroke: blue` 가 있을 때
**When** 분리하면
**Then** 올라온 요소가 두 값을 모두 지녀야 한다 (`bakeStyle` 캐스케이드)

### AC-28: 투명도는 곱해져서 구워진다

**Given** 그룹 투명도 0.5, 부품 투명도 0.5 일 때
**When** 분리하면
**Then** 올라온 요소의 투명도가 0.25 여야 한다

### AC-29: 부품 0 개가 되면 그룹이 사라진다

**Given** 부품 1 개인 그룹에서
**When** 그 부품을 분리하면
**Then** 그룹 노드가 배열에서 제거되어야 한다

### AC-30: 부품 1 개가 남으면 그것도 함께 올라온다

**Given** 부품 2 개인 그룹에서
**When** 부품 하나를 분리하면
**Then** 남은 부품도 최상위로 올라오고 그룹이 제거되어야 한다

> 004 는 부품 1 개짜리 그룹을 **만드는 것**을 거절한다. 분리가 그 금지된 상태를 새로
> 만들면 안 된다.

### AC-31: 규칙 손실을 알린다

**Given** 규칙이 걸린 그룹에서
**When** 분리를 시도하면
**Then** 잃게 될 규칙 수가 `rulesLostByUngroup` 의 값과 일치해야 한다

### AC-32: 최상위 요소에는 분리가 없다

**When** 최상위 요소가 선택된 상태에서 분리를 실행하면
**Then** 배열이 바뀌지 않아야 한다

### AC-33: 분리와 풀기가 같은 함수를 쓴다

**When** 소스를 검사하면
**Then** 좌표 환산과 스타일 굽기를 두 경로가 공유해야 하며, 분리 경로에 별도 구현이 없어야
한다

## 7. 그룹 투명도 (M1)

### AC-34: 그룹 행에 투명도 칸이 있다

**When** 그룹 행을 보면
**Then** 투명도 입력 칸이 있어야 한다

### AC-35: 입력이 그룹 스타일에 기록된다

**When** 0.5 를 입력하면
**Then** `node.style.opacity` 가 0.5 여야 한다

### AC-36: 0..1 로 클램프된다

**When** 1.5 또는 -0.5 를 입력하면
**Then** 각각 1 과 0 으로 클램프되어야 한다

### AC-37: 렌더가 곱셈으로 적용한다

**Given** 그룹 투명도 0.5, 부품 투명도 0.4 일 때
**When** 렌더 목표 스타일을 구하면
**Then** 그 부품의 실효 투명도가 0.2 여야 한다

### AC-38: 그룹 투명도만 있어도 적용된다

**Given** 그룹 투명도 0.5, 부품에 투명도 없음일 때
**When** 렌더 목표 스타일을 구하면
**Then** 실효 투명도가 0.5 여야 한다

### AC-39: 최상위 요소의 투명도 칸과 같은 컨트롤이다

**When** 두 칸을 비교하면
**Then** 같은 입력 컨트롤·같은 클램프 함수를 써야 한다

## 8. 견고성 (REQ-07)

### AC-40: 없는 부품 키는 예외를 내지 않는다

**Given** 선택 상태에 `grp-1/nonexistent` 가 있을 때
**When** 화면을 그리면
**Then** 예외가 나지 않고 선택이 그룹 또는 빈 선택으로 강등되어야 한다

### AC-41: 부품 0 개 그룹에서 부품 선택을 시도해도 안전하다

**Given** 부품이 0 개인 그룹에서
**When** 그 상자 안을 누르면
**Then** 예외가 나지 않아야 한다

### AC-42: 없는 그룹에 대한 분리는 아무 일도 하지 않는다

**When** 존재하지 않는 `groupId` 로 분리를 부르면
**Then** 배열이 그대로 돌아와야 한다

## 9. 회귀 — 뒤집지 않은 것 (M7)

### AC-43: 그룹 크기 조절이 부품 저장 좌표를 바꾸지 않는다

**When** 그룹 상자를 8핸들로 늘리면
**Then** 모든 부품의 저장 좌표가 한 자리도 바뀌지 않아야 한다 (004 A17)

### AC-44: 그룹 중첩이 여전히 불가능하다

**When** 타입을 검사하면
**Then** `parts` 가 `CanvasElement[]` 여서 그룹이 올 수 없어야 한다 (004 A6)

### AC-45: 004 의 나머지 시험이 통과한다

**When** 캔버스 스위트 전체를 실행하면
**Then** 009 가 명시적으로 뒤집은 두 단언 외에는 전부 통과해야 한다

### AC-46: 뒤집힌 시험에 근거가 남는다

**When** 뒤집힌 두 단언을 보면
**Then** 그 자리에 SPEC-CANVAS-009 를 가리키는 주석이 있어야 한다
