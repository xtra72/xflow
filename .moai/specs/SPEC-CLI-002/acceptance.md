# SPEC-CLI-002: Interactive Mode - 인수 테스트 기준

## 1. REPL 세션 시작 및 종료 (P0)

### AC-INT-001: REPL 세션 시작 (REQ-INT-001)
```gherkin
기능: REPL 대화형 세션 시작

  시나리오: interactive 명령어로 REPL 진입
    주어진 xflow 바이너리가 설치되어 있고
    그리고 터미널(TTY) 환경에서 실행할 때
    만약 `xflow interactive` 명령어를 실행하면
    그러면 환영 메시지가 출력되어야 한다
    그리고 "help 또는 ?로 명령어 목록을 확인하세요" 안내가 포함되어야 한다
    그리고 프롬프트가 표시되어야 한다

  시나리오: 비TTY 환경에서 interactive 진입 거부
    주어진 stdin이 파이프에 연결된 상태일 때
    만약 `echo "flow list" | xflow interactive` 명령어를 실행하면
    그러면 "대화형 모드는 터미널 환경에서만 사용할 수 있습니다" 에러가 출력되어야 한다
    그리고 종료 코드가 1이어야 한다
```

### AC-INT-002: 컨텍스트 인식 프롬프트 (REQ-INT-002)
```gherkin
기능: 서버 연결 상태에 따른 동적 프롬프트

  시나리오: 서버 연결 시 프롬프트
    주어진 xflowd 서버가 localhost:8080에서 동작 중이고
    그리고 REPL 세션이 활성화되어 있을 때
    그러면 프롬프트가 "xflow [localhost:8080]> " 형식이어야 한다

  시나리오: 서버 미연결 시 프롬프트
    주어진 xflowd 서버에 연결할 수 없는 상태이고
    그리고 REPL 세션이 활성화되어 있을 때
    그러면 프롬프트가 "xflow [disconnected]> " 형식이어야 한다

  시나리오: 서버 URL 변경 시 프롬프트 업데이트
    주어진 REPL 세션에서 `config server http://remote:9090`을 실행한 후
    그러면 프롬프트가 "xflow [remote:9090]> "로 변경되어야 한다
```

### AC-INT-003: 명령어 파싱 및 실행 (REQ-INT-003)
```gherkin
기능: REPL 내 CLI 명령어 실행

  시나리오: 기존 명령어 실행 (접두사 없이)
    주어진 REPL 세션이 활성화되어 있고
    그리고 xflowd 서버가 정상 동작 중일 때
    만약 REPL에서 `flow list`를 입력하면
    그러면 `xflow flow list`와 동일한 결과가 출력되어야 한다

  시나리오: 기존 명령어 실행 (접두사 포함)
    주어진 REPL 세션이 활성화되어 있을 때
    만약 REPL에서 `xflow flow list`를 입력하면
    그러면 `flow list`와 동일한 결과가 출력되어야 한다

  시나리오: 플래그가 포함된 명령어 실행
    주어진 REPL 세션이 활성화되어 있을 때
    만약 REPL에서 `flow list --format json`을 입력하면
    그러면 유효한 JSON 형식의 출력이 표시되어야 한다

  시나리오: 빈 입력 처리
    주어진 REPL 세션이 활성화되어 있을 때
    만약 Enter 키만 누르면
    그러면 에러 없이 다음 프롬프트가 표시되어야 한다

  시나리오: 공백만 포함된 입력 처리
    주어진 REPL 세션이 활성화되어 있을 때
    만약 "   "를 입력하면
    그러면 에러 없이 다음 프롬프트가 표시되어야 한다
```

### AC-INT-004: 세션 종료 (REQ-INT-004)
```gherkin
기능: REPL 세션 종료

  시나리오: exit 명령어로 종료
    주어진 REPL 세션이 활성화되어 있을 때
    만약 `exit`를 입력하면
    그러면 "세션을 종료합니다." 메시지가 출력되어야 한다
    그리고 프로세스가 종료되어야 한다
    그리고 종료 코드가 0이어야 한다

  시나리오: quit 명령어로 종료
    주어진 REPL 세션이 활성화되어 있을 때
    만약 `quit`를 입력하면
    그러면 "세션을 종료합니다." 메시지가 출력되어야 한다
    그리고 프로세스가 종료되어야 한다

  시나리오: Ctrl+D로 종료
    주어진 REPL 세션이 활성화되어 있을 때
    만약 Ctrl+D를 누르면
    그러면 "세션을 종료합니다." 메시지가 출력되어야 한다
    그리고 프로세스가 종료되어야 한다

  시나리오: Ctrl+C로 현재 입력 취소 (종료 아님)
    주어진 REPL 세션에서 부분 입력을 하고 있을 때
    만약 Ctrl+C를 누르면
    그러면 현재 입력이 취소되어야 한다
    그리고 새로운 프롬프트가 표시되어야 한다
    그리고 REPL 세션은 계속되어야 한다
```

### AC-INT-010: 히스토리 탐색 (REQ-INT-008, REQ-INT-009, REQ-INT-010)
```gherkin
기능: 명령어 히스토리 탐색 및 검색

  시나리오: 히스토리 영속화
    주어진 REPL 세션에서 "flow list"와 "agent list"를 실행한 후
    그리고 `exit`로 세션을 종료한 뒤
    만약 새로운 REPL 세션을 시작하면
    그러면 Up 화살표로 이전 세션의 "agent list"가 표시되어야 한다
    그리고 한 번 더 Up 화살표를 누르면 "flow list"가 표시되어야 한다

  시나리오: Up/Down 화살표 히스토리 탐색
    주어진 REPL 세션에서 "flow list", "agent list", "status"를 순서대로 실행한 후
    만약 Up 화살표를 한 번 누르면
    그러면 "status"가 프롬프트에 표시되어야 한다
    만약 Up 화살표를 한 번 더 누르면
    그러면 "agent list"가 프롬프트에 표시되어야 한다
    만약 Down 화살표를 한 번 누르면
    그러면 "status"가 프롬프트에 다시 표시되어야 한다

  시나리오: Ctrl+R 역방향 검색
    주어진 REPL 세션에서 "flow list", "flow get my-flow", "agent list"를 실행한 후
    만약 Ctrl+R을 누르고 "flow"를 입력하면
    그러면 가장 최근의 "flow" 포함 명령어인 "flow get my-flow"가 표시되어야 한다

  시나리오: 히스토리 파일 위치
    주어진 ~/.xflow/ 디렉토리가 존재할 때
    만약 REPL 세션에서 명령어를 실행하면
    그러면 ~/.xflow/history 파일에 명령어가 저장되어야 한다
```

### AC-INT-011: API 리소스 자동완성 (REQ-INT-011)
```gherkin
기능: API 리소스 이름 동적 자동완성

  시나리오: 플로우 이름 자동완성
    주어진 REPL 세션이 활성화되어 있고
    그리고 xflowd 서버에 "my-flow-1", "my-flow-2", "test-flow" 플로우가 등록되어 있을 때
    만약 `flow get my-`를 입력하고 Tab 키를 누르면
    그러면 "my-flow-1"과 "my-flow-2" 후보가 표시되어야 한다

  시나리오: Agent ID 자동완성
    주어진 REPL 세션이 활성화되어 있고
    그리고 xflowd 서버에 "mqtt-agent-1", "http-agent-1" Agent가 등록되어 있을 때
    만약 `agent get mqtt`를 입력하고 Tab 키를 누르면
    그러면 "mqtt-agent-1"으로 자동완성되어야 한다

  시나리오: 캐시 동작
    주어진 REPL 세션에서 `flow get` Tab으로 자동완성을 수행한 후
    만약 즉시 다시 `flow get` Tab을 수행하면
    그러면 API를 재호출하지 않고 캐시된 결과를 사용해야 한다

  시나리오: 서버 미연결 시 자동완성
    주어진 xflowd 서버에 연결할 수 없는 상태일 때
    만약 `flow get` Tab을 시도하면
    그러면 명령어/플래그 자동완성은 동작하되
    그리고 API 리소스 자동완성은 건너뛰어야 한다 (에러 표시 없음)
```

## 4. Wizard Mode (P2)

### AC-INT-012: Wizard 모드 진입 (REQ-INT-012)
```gherkin
기능: Wizard 모드 시작

  시나리오: REPL 내에서 Wizard 진입
    주어진 REPL 세션이 활성화되어 있을 때
    만약 `wizard flow deploy`를 입력하면
    그러면 "=== Flow Deploy Wizard ===" 헤더가 표시되어야 한다
    그리고 첫 번째 파라미터 프롬프트가 표시되어야 한다

  시나리오: CLI에서 직접 Wizard 진입
    주어진 터미널(TTY) 환경에서 실행할 때
    만약 `xflow interactive --wizard flow deploy`를 실행하면
    그러면 REPL 세션 없이 바로 Wizard가 시작되어야 한다
    그리고 Wizard 완료 후 프로세스가 종료되어야 한다

  시나리오: 존재하지 않는 명령어로 Wizard 시도
    주어진 REPL 세션이 활성화되어 있을 때
    만약 `wizard nonexistent`를 입력하면
    그러면 "알 수 없는 명령어입니다: nonexistent" 에러가 출력되어야 한다
```

### AC-INT-013: 단계별 파라미터 수집 (REQ-INT-013)
```gherkin
기능: Wizard 단계별 프롬프트

  시나리오: flow create Wizard

    그러면 다음 순서로 프롬프트가 표시되어야 한다:
      1. "플로우 정의 파일 경로를 입력하세요:" (필수, 파일 존재 검증)
    그리고 파일이 존재하지 않으면 재입력을 요청해야 한다

  시나리오: flow delete Wizard
    주어진 Wizard 모드에서 `flow delete`를 진행할 때
    그러면 다음 순서로 프롬프트가 표시되어야 한다:

    그리고 각 프롬프트에 기본값이 표시되어야 한다

  시나리오: 필수 값 빈 입력
```
