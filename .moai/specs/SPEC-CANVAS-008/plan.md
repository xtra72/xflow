# SPEC-CANVAS-008 — 구현 계획

> 시간을 예측하지 않는다. 순서와 우선순위로만 말한다.

## 기술 스택 (Tech Stack)

- React 19 · TypeScript 5.9(`strict` · `noUncheckedIndexedAccess` · `noFallthroughCasesInSwitch`)
- Vite 6 / Vitest / Testing Library / jsdom
- Tailwind v4(테마 토큰 변수)
- zustand + `zustand/middleware` `persist`(이미 `uiStore` 가 쓰는 그 기구)
- **신규 의존성 0.** 베지어 평탄화도 다각형 판정도 수십 줄의 순수 산술이다. 경로 파서
  라이브러리도, 아이콘 라이브러리 확장도, SVG 파서도 들이지 않는다.

## 작업 분해 (Task Decomposition)

### Primary Goal (1차 목표) — 종류 하나를 들이고, 컴파일러가 어디서 침묵하는지 **먼저 안다**

#### M1 — union 확장과 **침묵 지점 실측** (우선순위 High)

**이 밀레스톤의 산출물은 코드가 아니라 목록이다.**

- `PathElement`·`PathCommand`·`PATH_LOCAL_EXTENT`·`MAX_PATH_COMMANDS`·`DEFAULT_PATH` 를 타입과
  상수로만 더한다. 파서도 렌더도 히트도 **손대지 않는다.**
- `tsc --noEmit` 을 돌려 **어디가 울고 어디가 조용한지 그대로 기록한다.**
- 가정 A6(`BoxGeometry` 는 구조적으로 `PointGeometry` 에 대입된다)이 만드는 침묵을 확인한다.
  침묵이 의심되는 자리(정찰이 지목한 것): `parseElement` 화이트리스트 ·
  `drawMeasuredElement`(default 없음) · `handlesFor` · `handlePositions` · `labelAnchor` ·
  `outlineBox` · `ELEMENT_KINDS` · `PALETTE_KINDS`.
- **그 목록이 M2~M5 의 표적이고, 시험 규율 D1 이 지킬 대상이다.**

> **왜 이것이 1차인가.** 이 저장소는 "빠뜨렸는데 조용히 통과한다" 로 이미 여러 번 물렸다
> (패널 타입 등록 지점이 여섯이 아니라 열이었던 일). 008 은 union 에 갈래를 하나 더하는
> 일이라 **정확히 같은 부류**이며, 컴파일러가 얼마나 지켜 주는지를 **추정하지 않고 재는 것**이
> 이 SPEC 의 첫 걸음이어야 한다.

#### M2 — 파서 (우선순위 High)

- `kind` 화이트리스트에 `'path'`. **이 한 줄이 없으면 저장된 경로가 읽을 때 사라진다.**
- `parsePathCommands` — 명령 네 종 · 좌표는 `coordinate()` 재사용 · 상한 죔 · 씨앗 폴백 ·
  첫 명령이 `M` 이 아니면 씨앗.
- `catalog_id` 는 `optionalString`.
- 왕복 시험: `parse(JSON.parse(JSON.stringify(cfg)))` 가 값을 바꾸지 않는다.

#### M3 — 투영 · 렌더 · 인터페이스 둘 (우선순위 High)

- `projectPathPoints` 한 함수(나눗셈이 나타나는 유일한 자리).
- `DrawContext2D` 에 `closePath`·`bezierCurveTo`.
- `drawMeasuredElement` 에 갈래 하나. **`paintFill`/`paintStroke` 는 손대지 않는다.**
- `labelAnchor` 경로 갈래(상자의 중심 — `default:` 의 좌상단이 아니다).
- 기록 스텁 시험: 명령 순서·인자가 그대로 나온다. **닫힘 시험**(선 경로에 `closePath` 가
  기록된다)과 **열린 경로 시험**(기록되지 않는다)을 갈라 잰다.

#### M4 — 히트 테스트 (우선순위 High)

- `flattenPath`(재귀 이등분 · 평탄도 판정) · `hitsPath`(nonzero winding + 변 거리).
- `canvasHitTest` 갈래. **DOM 무의존 유지.**
- 오목 지역 시험(별의 안쪽 · 십자의 겨드랑이)이 **빗나가야** 한다 — 바운딩 박스와 갈리는
  유일한 자리다.
- 경계 ±(허용 오차+ε) 시험.

### Secondary Goal (2차 목표) — 편집의 이음매와 카탈로그

#### M5 — 편집 이음매 전량 (우선순위 High)

M1 이 적은 침묵 지점을 **하나도 빠뜨리지 않고** 메운다.

- `handlesFor('path')` → 8핸들(오늘의 `default:` 는 글자 크기 핸들 하나를 준다).
- `handlePositions` 경로 갈래 → 상자 핸들 좌표.
- `outlineBox` 경로 갈래 → 상자.
- `patchNodeGeometry` 경로 갈래 → 상자 쓰기(오늘의 `default:` 는 상자 기하를 받으면
  **요소를 그대로 돌려준다** = 경로가 영영 움직이지 않는다).
- `withKind` — 경로로 **바꾸지 않는다**(선택지에서 뺀다), 경로에서 다른 종류로는 바뀐다.
- `KIND_LABEL_KEY` 에 경로 이름(있으면 카탈로그 이름을 보인다).
- 각 항목마다 **뮤테이션 확인**: 갈래를 지우면 그 시험이 빨개진다.

#### M6 — 카탈로그 30종 (우선순위 High)

- `shapeCatalog.ts` 30종 + 묶음 셋. 순수 데이터.
- **가정 A2 를 여기서 확인한다** — 30종을 실제로 그려 `bezierCurveTo` 를 쓰는 것이 정확히
  7종인지, `closePath` 밖의 새 멤버를 요구하는 도형이 하나도 없는지 센다.
- 30종 전량이 **한 도형도 빠짐없이** 그려지는지 렌더 시험(스텁 기록에 명령이 남는다).
- id 에 점이 없는지, i18n 키가 양쪽에 있는지 가드.

#### M7 — 팔레트 UI (우선순위 Medium)

- 도형 절을 접히는 묶음으로. **원시형 넷의 testid·자리·순서는 그대로.**
- 카탈로그 묶음 격자 + `drawElements` 미리보기.
- 접힘 상태 기기 지역 기억(못 해도 성립 — REQ-06).
- i18n 양쪽(묶음 셋 + 30종 + 접힘 라벨).

#### M8 — 스크래치패드 저장소 (우선순위 High)

- `scratchpadTypes.ts` 관용 파서(요소는 001 `parseElements` 재사용).
- `scratchpadStore.ts` 전용 `persist` 키 + 항목 50 / 256KB 한도 + **거절하고 말한다**.
- 저장소를 못 쓰는 환경(시크릿 · 용량 초과)에서 **예외가 밖으로 나가지 않는다**.
- 직렬화 왕복 시험: 다섯 종류 전부(명령 네 종 포함)를 담은 항목이 `JSON` 왕복 뒤에도 같다.

#### M9 — 끌어 저장 · 단추 저장 (우선순위 High)

- 드롭 존 노드 컨텍스트(`canvasEditDockHost` 와 같은 꼴, 없으면 `null`).
- 오버레이 `pointerup` 의 드롭 갈래 — **클라이언트 좌표 containment**, 스테이지 산술 없음.
- 드롭 성립 시 **기하 되돌림**(`drag.bases` → `patchNodeGeometry`).
- "선택 항목 저장" 단추(SC 2.5.7). **끌기와 같은 함수를 부른다**(J11).
- 선택이 비면 단추는 disabled, 드롭은 항목을 만들지 않는다.

#### M10 — 스크래치패드에서 놓기 (우선순위 High)

- 항목 → 캔버스 끌어놓기(`stagePoint` 재호출 · `unprojectPoint` · `snapDelta` 재사용).
- "놓기" 단추(`seedOffset` 자리).
- id 재발급 · 배열 끝에 순서대로 · **만들어진 id 전부를 선택으로**.
- 놓은 직후 무리 이동이 실제로 덩어리를 옮기는지 시험.

## 아키텍처 설계 방향

**층을 섞지 않는다.** 008 이 더하는 것은 네 층에 흩어지지만 각 층의 성격은 그대로다.

```
순수 자료   shapes/pathTypes.ts · shapes/shapeCatalog.ts · scratchpad/scratchpadTypes.ts
순수 산술   shapes/pathFlatten.ts · canvasGeometry.projectPathPoints
렌더        drawElement(갈래 하나) — 계산하지 않는다
상태        scratchpad/scratchpadStore.ts(기기 지역) — 그리지 않는다
```

캔버스 표면에는 아무것도 더 그리지 않는다. 그 결정 하나가 006 이 배달한 I23 결함의 재발을
**형상으로** 막는다.

## 크기의 출처 — 왜 상자 하나로 충분한가

경로 요소가 `BoxGeometry` 하나만 갖는 것이 이 설계에서 가장 값싼 결정이다. 그 덕에:

- 8핸들 크기 조절 · 정렬 6종 · 붙임 · 무리 이동 · 방향키 미세 이동 · 순서가 **한 줄도 고치지
  않고** 붙는다(전부 `BoxGeometry` 위에 서 있다).
- 006 의 상자 산술 · 보기 배율 · 작업 영역이 경로를 **모른 채로** 옳게 동작한다.
- 004 가 나중에 `group` 을 얹을 때 경로 부품은 다른 부품과 **같은 형상**이다.

대가는 하나다: **경로는 비균등하게 늘리면 함께 일그러진다**(원이 타원이 되듯). 004 가정 A7 이
심볼에 대해 이미 받아들인 그 성질이며, 한 패널 안에 규칙을 둘 두지 않기 위해 같은 답을 쓴다.

## 히트맵·차트 선례와 충돌하지 않는 이유

- 히트맵의 SVG 도면(`svgAsset.ts`)은 **문서를 읽어 그린다**. 008 은 **자기가 발행한 숫자**를
  그린다. 그 파일이 문서화한 제약(인라인 금지 · `preserveAspectRatio` · `naturalWidth`)은
  008 에 하나도 걸리지 않는다.
- 차트 패널의 편집 툴킷과 겹치는 자리가 없다 — 008 은 캔버스 패널 안에서만 산다.

## 후속 SPEC 로드맵 (008 이 보는 그림)

- **SPEC-CANVAS-004 — 설비 심볼 라이브러리**: 008 이 `path` 를 들여 놓았으므로 004 의 심볼
  부품은 **다섯 종류 가운데 고를 수 있게** 된다. 004 가 착수하기 전에 §로드맵 정합 3 의
  정규화 좌표 진술을 고쳐야 한다. 008 이 못박는 것 하나: **경로 부품도 `group` 안에 온다 —
  `parts: CanvasElement[]` 의 타입이 그것을 이미 허용한다.**
- **SPEC-CANVAS-009 — 경로 정점 편집기 (신설 예약)**: 정점·제어점을 손으로 다루는 일.
  008 이 명령 목록을 **참조가 아니라 값으로** config 에 넣었으므로 009 는 "카탈로그에서 떼어
  내기" 를 발명하지 않아도 된다. 009 가 답해야 할 질문: `CanvasHandleId` 를 매개변수를 가진
  id 로 넓힐 것인가, 제어점의 "부드러운 점 / 꺾인 점" 을 저장 필드로 들일 것인가, 점을 넣고
  빼는 몸짓의 키보드 등가물(SC 2.5.7)은 무엇인가, 되돌리기 없이 배달할 수 있는가.
- **SPEC-CANVAS-010 — 연결선 (신설 예약)**: 순서도 · ER · UML 의 **전제 조건**이다. 도형 위의
  접합점, 도형이 움직일 때의 재경로, 화살촉·선종류·라벨 모델. 010 이 서면 그 세 묶음을 008 의
