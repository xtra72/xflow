# SPEC-CANVAS-013 — 구현 계획

## 구현 전략

### 순서를 이렇게 잡는 이유

**산술이 먼저다.** 이 SPEC 의 위험은 배선이 아니라 좌표다 — 뒤집힌 화살표가 여전히 같은
쪽을 가리키거나, 네 번 돌린 그림이 2 단위 밀리는 결함은 **저장 왕복을 견디고 화면으로만**
드러난다. 그래서 순수 함수를 먼저 세우고 불변식(K1·K2)을 값으로 못박은 뒤에 화면을 붙인다.

**속(로컬 좌표)을 자리(상자)보다 먼저** 한다. 자리만 먼저 붙이면 "뒤집기가 동작한다" 가
화면에서 참으로 보이는 구간이 생기고, 그 구간에 속이 빠져 있다는 사실은 화살표 같은
비대칭 도형을 놓아 봐야 드러난다. 둘을 한 마일스톤에 담아 그 거짓 초록을 만들지 않는다.

### 핵심 설계 결정

| # | 결정 | 근거 |
|---|------|------|
| D1 | 새 잎 모듈 `canvasTransform.ts` | `canvasEditArrange` 는 이미 27KB 이고 주제가 다르다(맞추기 · 순서) |
| D2 | 자리는 `patchNodeGeometry`, 속은 새 함수 | spec §결정 2 — A17 을 깨지 않으면서 정수화는 그대로 받는다 |
| D3 | 90° 는 **중심 고정 + `Math.trunc`** | spec §결정 3 — 흔들린 것은 중심 고정이 아니라 `Math.round` 였다. `trunc` 만 홀함수라 다음 회전이 앞 회전을 정확히 상쇄한다 |
| D4 | 로컬 변환 함수는 **넷이 아니라 하나** | 축·방향을 인자로 받는다. 넷을 적으면 `C` 제어점을 셋에만 넣는 날이 온다 |
| D5 | 문구는 `resolveTextOrigin` 을 **읽기만** 한다 | 두 번째 정렬 산술을 만들지 않는다 |

## 마일스톤

### M1 — 로컬 좌표 변환 (REQ-03 · §결정 4)

**대상**: 새 잎 모듈 `canvasTransform.ts`.

- `TransformKind = 'flipX' | 'flipY' | 'rotateCW' | 'rotateCCW'`
- `transformLocalPoint(kind, p, extent)` — 나눗셈 없는 정수 산술 넷
- `transformPathCommands(kind, cmds)` — **`C` 의 제어점 둘도 함께 지난다**
- `transformAnchors(kind, anchors)`
- 시험: K1(네 번) · K2(두 번) 을 **명령 목록 전체**에 대해

**아직 화면에 닿지 않는다.** 이 마일스톤의 산출물은 값으로만 검증된다.

### M2 — 선택 상자와 자리 변환 (REQ-01 · REQ-02 · §결정 1 · §결정 3)

- `selectionBox(nodes, proj, textWidths)` — `unprojectBox(outlineBox(...))` 의 합집합
  (연결선은 빠진다 — `outlineBox` 가 받지 않는다)
- `transformBoxWithin(kind, box, sel)` — 상자 하나를 선택 상자 안에서 옮긴다
  - 뒤집기: `x ↦ sel.x + sel.w − (x − sel.x) − w`
  - 90°: **중심 고정** — 산술은 선택 상자 로컬 정수로 하고, 반올림은 새 원점
    `X + trunc((W−H)/2)` **한 번뿐**이다(요소마다 반올림하지 않는다)
- 선·기준점은 상자가 아니므로 각각 점 변환으로 간다
- 시험: 4회전 항등을 **상자 열한 가지**와 **요소 여럿 장면 여섯**에 대해,
  그리고 좌우 왕복(K1')까지

### M3 — 노드 한 벌 변환 (REQ-03 · REQ-04 · §결정 2 · §결정 5)

- `transformNodes(kind, nodes, selectedIds, proj, textWidths): CanvasNode[]`
- 갈래: `rect`/`ellipse`(상자 + 앵커) · `path`(상자 + 명령 + 앵커) ·
  `line`(두 끝점) · `text`(§결정 6) · `group`(상자 + 부품 두 겹) · `connector`(자유 끝 · 중간점)
- 자리 반쪽은 `patchNodeGeometry` 를 지난다(D2)
- **아무것도 바뀌지 않으면 받은 배열을 그대로**(REQ-06)
- 시험: 층을 건너는 것 — 비대칭 경로를 뒤집고 **다시 그려** 호출 기록이 거울인지

### M4 — 문구의 기준점 되짚기 (§결정 6)

- 윤곽 상자를 변환한 뒤 `resolveTextOrigin` 의 관계로 기준점을 되짚는다
- 정렬 셋(`left`·`center`·`right`) 각각에 대해 **보이는 상자가 거울 자리에 온다**를 잰다

### M5 — 띠에 절 하나 (§결정 8)

- `CanvasEditToolbar` 에 `변환` 절 — 단추 넷(가로 뒤집기 · 세로 뒤집기 · 왼쪽 · 오른쪽)
- 켜짐 조건은 `selection.size >= 1`(REQ-05) — 정렬의 `>= 2` 와 **다른 자**임을 주석이 적는다
- `CanvasEditOverlay` 가 `applyAlign` 과 같은 모양으로 `applyTransform` 을 배선
- i18n: 절 이름 + 단추 넷의 접근성 이름 (ko · en)

### M6 — 회귀와 문서

- 캔버스 전량 회귀 + 웹 전량 + `tsc` + `eslint`
- 증감이 전부 설명되는지 확인

## 시험 전략

### 불변식을 **값으로** 못박는다

K1(네 번 돌리면 제자리)과 K2(같은 거울 두 번)는 이 SPEC 의 뼈대다. 상자 · 경로 명령 ·
부품 · 앵커 **넷 모두**에 대해 돌린다 — 하나만 재면 나머지 셋이 조용히 갉아먹는다.

### 고정 입력은 **비대칭**이어야 한다

대칭 도형은 뒤집기 결함을 통째로 감춘다. 경로는 네 명령(`M`·`L`·`C`·`Z`)을 다 쓰고
**좌우가 다른** 모양이어야 하며, 상자는 원점 ≠ 0 · `x ≠ y` · 비정사각이어야 한다
(008 이 세운 시험 규율 D2·D3 그대로).

### 층을 건너는 시험

순수 산술이 맞아도 그리는 쪽이 그 값을 안 읽으면 화면은 그대로다. 비대칭 경로를 뒤집고
`drawElements` 로 **다시 그려** 호출 기록이 거울인지 본다 — 편집기와 렌더러가 각각 덮여도
이음매는 덮이지 않는다.

### 뒤집지 않은 것을 고정한다

013 은 선택 위에서 도는 연산을 하나 더할 뿐이고, 정렬 · 순서 · 그룹 · 연결선의 결과는 한
글자도 달라지지 않는다. 그 "달라지지 않음" 은 저절로 참이 아니라 **재야** 참이다.
