# SPEC-CANVAS-007 — SVG 가져오기

## HISTORY

| 일자 | 버전 | 변경 | 작성자 |

| 2026-09-10 | 0.1.0 | 최초 작성. 사용자가 **"svg 이미지 가져오기 추가"** 를 냈다 — 스스로 세운 최종 목표 셋(① 묶음 있는 도형 카탈로그 · ② 벡터 이미지 가져오기 · ③ 작업 영역과 패널 출력 영역) 가운데 **마지막 하나**이며, 006 · 008 의 산문이 `SPEC-CANVAS-007` 로 예약해 둔 그 자리다. 읽는 법 셋을 내밀었고 사용자가 **"SVG 를 파싱해 `path` 요소들로 푼다"** 를 골랐다(기각한 둘과 그 값은 §중심 설계 결정). 정찰이 이 SPEC 의 크기를 정한 사실 다섯을 **실측으로** 확인했다: (1) **008 이 착지점을 이미 깔아 두었다** — `PathCommand` 는 `M`·`L`·`C`·`Z` 넷이고 좌표는 로컬 정수 0..10000, 상한은 256(`shapes/pathTypes.ts`, 실측), (2) **`DrawContext2D` 에 더할 멤버가 0 이다** — `A`(호)를 3차 베지어로 바꾸므로 008 이 더한 `closePath`·`bezierCurveTo` 로 전부 적힌다(008 AC-E2 의 멤버 수 가드가 그대로 산다), (3) **이 저장소에 `DOMParser` 는 처음이다** — `heatmap/svgAsset.ts` 는 SVG 를 **정규식으로** 읽지 DOM 으로 읽지 않는다(`grep -rn 'DOMParser' web/src` → 0건, 실측). 브리핑이 "이 저장소는 이미 SVG 문서 텍스트를 다룬다" 고 한 것은 참이나 **기구가 다르다**, (4) **jsdom 에는 `SVGPathElement` 도 `getBBox` 도 없다**(측정: 둘 다 `undefined`) — SVG 기하 DOM API 에 기대는 설계는 시험 환경에서 서지 않는다, (5) **`parsePathCommands` 는 상한 초과분을 조용히 자른다**(`break`, 실측 `canvasConfig.ts:684`) — 그래서 가져오기가 257번째 명령을 **만들어 내는 순간** "저장할 땐 맞고 다시 열면 잘린" 결함이 생긴다. 이 다섯이 §명령 상한 결정의 하중을 전부 받는다. | xtra |

## 개요 (Overview)

### 이 SPEC 이 바꾸지 않는 것부터 적는다 — 그것이 이 SPEC 의 크기다

- **`PathCommand` 어휘를 넓히지 않는다.** `M`·`L`·`C`·`Z` 넷 그대로다. SVG 가 가진
  `H`·`V`·`S`·`Q`·`T`·`A` 는 **저장되지 않고 축약된다**(§명령 축약).
- **`DrawContext2D` 에 멤버를 더하지 않는다 — 0 개다.** 008 이 그 인터페이스를 정확히 둘
  넓혔고 AC-E2 가 멤버 수를 시험으로 못박았다. 007 은 그 시험을 **한 글자도 고치지 않는다**.
- **`CanvasElement` 합집합을 넓히지 않는다.** 여섯 번째 종류는 없다. 가져오기의 산출은
  008 의 `path` 요소들이다.
- **`CanvasPrimitiveKind` 는 넷 그대로다.** 팔레트에 **다섯 번째 단추를 만들지 않는다** —
  가져오기는 도형을 고르는 일이 아니라 문서를 여는 일이다(§I23).
- **`CanvasProjection { stage, canvas }` 는 두 칸 그대로다.** `stagePoint` 는 좌표 공간을
  넘는 유일한 자리 그대로이며, 007 은 그 함수를 **더 부르지도 않는다**(가져오기는 포인터
  사건이 아니다).
- **기하 쓰기는 여전히 `patchNodeGeometry` 한 함수를 지난다.** 007 이 만드는 요소의 상자는
  **생성 시점의 값**이고, 그 뒤의 모든 이동·조절은 그 통로를 지난다.
- **요소를 만드는 입구는 여전히 `canvasElementFactory` 하나다.** 007 은 그 모듈에 입구
  하나를 **더할 뿐** 자기 id 규칙도 계단 규칙도 갖지 않는다.
- **백엔드 변경 0.** 004 · 005 · 006 · 008 이 나란히 지켜 온 그 값을 007 도 지킨다
  (§파일은 어디서 오는가 — `dashboard-assets` 를 쓰지 않는 이유).
- **config 스키마 무변경(형상).** 필드 이름은 하나도 늘지 않는다. `elements[]` 에
  `kind: 'path'` 원소가 더 생길 뿐이다.
- **`PanelSettingsDialog.tsx` 는 한 줄도 자라지 않는다**(오늘 **8,371행** — 실측. 006 불변식
  I7 · 008 불변식 J12). 가져오기 UI 는 도크가 그린다.
- **신규 의존성 0.** SVG 경로 파서 라이브러리도, 행렬 라이브러리도, 곡선 근사
  라이브러리도 들이지 않는다.

**설계가 `PathCommand` 에 다섯 번째 명령을 더하거나, `DrawContext2D` 에 `arc`/`arcTo`/
`drawImage` 를 들이거나, 팔레트에 다섯 번째 단추를 세우거나, 파싱한 문서를 살아 있는 DOM 에
붙이는 쪽으로 흘렀다면 그것은 길을 잘못 든 것이며 되짚어야 한다.**

### 무엇을 바꾸는가 — 하나다

**사용자가 고른 SVG 파일 하나를, 편집 가능한 `path` 요소 여럿으로 푼다.** 그림으로 걸지
않는다. 놓인 뒤에는 카탈로그에서 놓은 도형과 **구별되지 않는다** — 고르고, 끌고, 8핸들로
조절하고, 색을 바꾸고, 규칙을 걸고, 서랍에 저장한다.

레이어)은 전부 사용자가 아직 요구하지 않은 것이며, 로드맵의 예약일 뿐이다(plan.md
§후속 SPEC 로드맵).

### 중심 설계 결정 — 그림으로 걸지 않고 요소로 푼다

읽는 법 셋을 내밀었고 사용자가 셋째를 골랐다. **기각한 둘을 값과 함께 적는다.**

#### 기각 (A) — 이미지로 그린다 (`<img>`/`drawImage`)

충실도가 완전하다. 그라디언트도 필터도 글자도 원본 그대로 나온다. **그리고 004 가 기각한
것 전부를 되살린다.**

- **비동기 로드·디코드·캐시 수명주기가 rAF 루프 안으로 들어온다.** 001 REQ-05 의 유휴 정지는
  "트윈이 없으면 프레임을 예약하지 않는다" 인데, 이미지가 들어오면 "아직 안 온 이미지가
  있으면 프레임을 예약한다" 는 두 번째 예약 근거가 생긴다. `CanvasSurface.tsx` 의 프레임
  콜백은 그 판정을 한 곳에서 하고 있고(실측 504행 "유휴 정지 판정이 여기 있다"), 둘이 되는
  순간 그 자리가 갈라진다.
- **인증 자산의 data-URL 왕복이 붙는다.** `<img src>` 로 직접 참조할 수 없어 JSON 으로 받아
  data-URL 로 바꿔야 한다(`dashboardAssetService.ts` 실측 — `POST /dashboard-assets` 는
  `{ data_url }` 를 받고 `GET` 은 `{ data_url }` 을 돌려준다).
- **규칙이 그림 안쪽을 지목하지 못한다.** 004 가 "완곡하게 말하지 않겠다" 며 (B) 를 죽인 그
  근거다.
- **고칠 수 없다.** 색 하나를 바꾸려면 원본 도구로 돌아가 다시 내보내 다시 올려야 한다.
  사용자가 이 패널에 요구해 온 것은 **편집**이며, 그림은 편집의 반대말이다.

#### 기각 (B) — 파싱하되 못 다루는 것이 하나라도 있으면 통째로 거절한다

**망친 결과를 절대 내지 않는다** — 그것이 이 안의 값이다. 받아들이는 파일이 적어지는 것이
대가다. 그리고 그 "적어짐" 이 실제로 얼마나 되는지가 기각의 이유다: 현실의 SVG 는 거의 언제나
`<defs>` 에 안 쓰는 그라디언트가 하나쯤 남아 있고, 내보내기 도구가 붙인 `<metadata>` 와
`<style>` 이 있으며, 잉크스케이프 문서는 `sodipodi:namedview` 를 달고 나온다. **그 가운데
어느 것도 그림에 영향을 주지 않는데**, 통째 거절은 그 전부를 거절 사유로 만든다.

즉 (B) 는 "망치지 않는다" 를 사는 대신 **"거의 아무 파일도 못 연다"** 를 치른다.

#### 채택 (C) — 파싱해 요소로 풀되, 못 다룬 것을 화면이 말한다

**(B) 의 목적("망친 결과를 내지 않는다")을 (B) 의 수단(통째 거절) 없이 얻는다.** 조용히
버리지 않고 **놓기 전에 보고**한다 — 무엇이 들어오고 무엇이 버려졌고 무엇이 근사되었는지를
사용자가 보고 나서 [놓기] 를 누른다. 버림이 그림을 알아볼 수 없게 만드는 종류라면 사용자가
[취소] 를 누르면 된다.

**이것이 (C) 가 (B) 보다 나은 유일한 이유다: 판단을 하는 쪽이 파서가 아니라 사람이다.**
파서는 "이 그라디언트가 이 그림에 중요한가" 를 알 수 없지만 사람은 미리보기를 보면 안다.

**(C) 가 치르는 값을 숨기지 않는다.** 보고를 읽지 않고 [놓기] 를 누르는 사용자는 (B) 라면
받지 않았을 결과를 받는다. 완화는 둘이다 — (1) 보고가 **접혀 있지 않다**(요약 한 줄은 언제나
보이고 목록만 접힌다), (2) **가져올 것이 하나도 없으면 [놓기] 단추 자체가 서지 않는다**.

### 004 가 이미지를 기각한 근거 넷은 007 에 대해 어떻게 되는가

008 이 같은 표를 경로에 대해 만들었고 셋이 죽었다. **007 은 남의 SVG 문서를 읽으므로 넷째
근거가 다시 살 자리가 있다** — 그래서 하나씩 다시 대조한다. 추정이 아니라 실측이다.

| 004 가 든 근거 | 007 에서 | 확인 |
|---|---|---|
| 규칙이 심볼 **내부를 지목하지 못한다** | **적힌 대로는 죽는다. 더 가는 잔여가 남는다** | 가져오기의 산출은 **불투명한 그림 하나가 아니라 요소 N 개**이므로, 규칙 표는 각 요소를 id 로 지목한다. 다만 **한 `<path>` 가 만든 한 요소의 안쪽**은 여전히 지목되지 않는다 — 그 잔여는 008 이 `path` 를 들이며 이미 이름으로 적고 위험 R6 에 올린 성질이며, **007 이 만드는 것이 아니라 물려받는 것**이다 |
| `drawImage` 를 들이면 **비동기 로드·디코드·캐시 수명주기가 rAF 루프로 들어온다** | **죽는다. 그리고 007 이 죽은 채로 둔다** | 파싱은 동기이고 **프레임 콜백 밖**에서 일어난다(파일 고르기 사건 처리 안 — §파싱은 어느 층에서 일어나는가). `DrawContext2D` 에 더하는 멤버는 **0 개**다. 그리고 007 은 `<image>`(내장 래스터)를 **받지 않는다** — 그것을 받는 순간 이 근거가 되살아나므로, 거절이 곧 이 표의 한 줄을 지키는 일이다 |
| 자산은 **인증 헤더가 필요해** JSON→data-URL 왕복이 붙는다 | **죽는다** | 파일은 **로컬 파일 고르기**로만 들어오고 브라우저를 떠나지 않는다. `dashboard-assets` 를 쓰지 않으므로 왕복도, 백엔드 변경도 없다(§파일은 어디서 오는가) |
| `svgAsset.ts` 의 제약 셋을 물려받는다 | **적힌 대로는 죽는다. 셋 가운데 둘이 모습을 바꿔 다시 나타난다** | 아래에 하나씩 |

#### 넷째 근거의 세 조항은 각각 어떻게 되는가

- **"인라인 금지 — 업로드 SVG 는 data-URL `<img>` 로만 그린다(스크립트 격리)."**
  → **모습을 바꿔 다시 나타난다.** 007 은 `<img>` 를 쓰지 않으므로 그 형태로는 걸리지 않지만,
  같은 경계가 **"파싱한 문서를 살아 있는 문서에 붙이지 않는다"** 로 다시 선다(§아래). 그리고
  그 경계가 **`<style>` CSS 를 지원하지 않는 이유**다 — CSS 캐스케이드를 브라우저에게 시키는
  유일한 길이 `getComputedStyle` 이고, 그 함수는 요소가 **살아 있는 문서 안에** 있을 것을
  요구하기 때문이다. 즉 svgAsset 이 그은 선이 007 의 스타일 결정을 직접 정한다.
- **"`preserveAspectRatio` 가 CSS 를 이긴다."**
  → **모습을 바꿔 다시 나타난다.** 007 에는 뷰포트가 없으므로 그 속성이 CSS 를 이길 자리가
  없다. 그러나 같은 질문이 **"`viewBox` 를 로컬 격자에 어떻게 앉히는가"** 로 되돌아온다
  (§`transform` 과 `viewBox`). 007 은 그 속성을 **읽지 않고 무시하며**, 대신 **요소 상자의
  종횡비를 문서의 종횡비로 정한다** — 답이 다를 뿐 질문은 같다.
- **"`naturalWidth/Height` 는 sizeless SVG 에서 원본 크기가 아니다."**
  → **완전히 죽는다.** 007 은 브라우저에게 크기를 **묻지 않는다**. `viewBox` 를 직접 읽는데,
  그것이 정확히 `svgAsset.ts` 가 스스로 내린 결론이다("종횡비: `viewBox`(없으면 width/height
  속성)에서 직접 읽는다 — **브라우저 보고값보다 정확하다**", 실측 머리말).

**요약: 넷 가운데 둘(비동기·자산 왕복)은 흔적 없이 죽고, 하나(내부 지목)는 적힌 대로 죽되
008 이 이미 적어 둔 더 가는 잔여를 남기며, 하나(svgAsset 제약)는 죽되 두 조항이 007 의 두
결정(스타일 · viewBox)을 직접 정하는 형태로 되살아난다.** "넷 다 죽는다" 는 요약은 셋째와
넷째에 대해 거칠다.

### `DOMParser` 를 쓴다 — 그리고 이 저장소에 그것이 처음이다

**브리핑을 반증한 자리이므로 먼저 적는다.** `heatmap/svgAsset.ts` 는 SVG 문서 텍스트를
다루지만 **정규식으로** 다룬다(`rootSvgTag` 는 `/<svg\b[^>]*>/i`, `attr` 은 이름별
`RegExp` — 실측). 저장소 전체에 `DOMParser` 는 **0건**이다(`grep -rn 'DOMParser' web/src`).

**정규식으로 계속 가는 안을 기각한다.** svgAsset 이 정규식으로 되는 이유는 그것이 **루트 여는
태그 하나**만 읽기 때문이다. 007 은 중첩된 `<g>` 를 타고 내려가며 조상의 `transform` 을 쌓아야
하고, `<defs>` 안쪽은 건너뛰고 `<use>` 는 따라가야 한다. **그것은 트리 순회이고, 정규식으로
트리를 순회하는 코드는 이 저장소가 감당할 형태가 아니다.**

**채택 — `DOMParser.parseFromString(text, 'image/svg+xml')`.** 그 API 는 스크립트를 실행하지
않으며, 이것은 007 의 안전 논거가 **기대는 바로 그 성질**이다.

**측정으로 확인한 것(jsdom 25.x, 이 저장소의 시험 환경):**

```
root: svg   viewBox: 0 0 100 50
path d: M0 0 L10 10 Z   fill: red
g transform: translate(10,5)
script executed? undefined        ← <script>window.x=1</script> 가 들어 있는 문서였다
parsererror? false
getBBox? undefined                ← SVG 기하 DOM API 가 없다
SVGPathElement? undefined         ← 노드가 SVG 특수 인터페이스를 갖지 않는다
```

이 측정이 두 가지를 정한다.

1. **속성 읽기와 트리 순회만 쓴다.** `getBBox` · `getTotalLength` · `getPointAtLength` ·
   `pathSegList` · `getCTM` · `getComputedStyle` 은 **하나도 쓰지 않는다** — jsdom 에 없거나
   (앞의 넷) 살아 있는 문서를 요구한다(뒤의 하나). 이것은 편의가 아니라 **가능성의 경계**다.
2. **잘못된 XML 의 판정은 형상으로 한다.** 측정에서 깨진 문서는
   `documentElement.tagName === 'parsererror'` 였고 `querySelector('parsererror')` 도 참이었다.
   **브라우저마다 그 형상이 다르다는 것이 알려져 있으나 본 SPEC 은 그것을 실측하지 않았다**
   (미검증 — 가정 A9). 그래서 판정은 **둘 다** 본다: 루트가 `svg` 가 아니거나 문서 안에
   `parsererror` 가 있으면 실패로 읽는다.

**내부 엔티티는 확장된다**(측정: `<!ENTITY a "AAAA">` 를 쓴 `d="&a;"` 가 `"AAAA"` 로 읽혔다).
브라우저들이 확장 폭탄(billion laughs)에 상한을 둔다고 **알려져 있으나 본 SPEC 은 그것을
실측하지 않았다.** 그래서 기대지 않는다 — **파싱 전에 입력 바이트를 자른다**(§견고성).

### 파싱한 문서를 살아 있는 DOM 에 붙이지 않는다

`DOMParser` 가 만든 노드를 `document` 에 넣으면 그 안의 `<script>` 가 실행되는가 — 사양과
브라우저 구현이 미묘하고, **본 SPEC 은 그 답에 기대지 않는다.** 답을 몰라도 되게 만든다:

> **불변식 — 007 은 파싱한 문서(또는 그 자손)를 어떤 살아 있는 문서에도 붙이지 않는다.**
> `appendChild` · `insertBefore` · `replaceWith` · `importNode` · `adoptNode` 가 파싱 결과에
> 대해 불리는 자리가 **하나도 없다**(불변식 K3, 형상 판정).

그 불변식이 값을 셋 준다.

1. **스크립트 실행 가능성이 형상으로 닫힌다** — 실행 여부를 알 필요가 없어진다.
2. **`getComputedStyle` 로 가는 길이 닫힌다** → `<style>` CSS 미지원이 게으름이 아니라 이
   경계의 **귀결**이 된다(§스타일 추출).
3. **외부 자원 요청이 일어나지 않는다** — 붙지 않은 문서는 `<image href>` 도 `<use href>`(외부)
   도 가져오지 않는다.

### 파싱은 어느 층에서 일어나는가 — rAF 루프 밖이다

이 SPEC 이 이미지보다 싼 이유의 전부가 이 문단이다.

```
[사용자가 파일을 고른다]  ← DOM 사건 처리자
        │  await file.text()          ← 비동기. 그러나 프레임 콜백이 아니다
        ▼
[파싱 · 축약 · 변환 · 스타일 추출]   ← 전부 동기. 순수 산술과 속성 읽기뿐
        ▼
[미리보기 · 보고]  →  [놓기]  →  elements[] 에 요소 N 개
        ▼
[다음 렌더]  ← 여기서부터는 008 이 그리던 그 경로 그대로다
```

- **`CanvasSurface.tsx` 의 프레임 콜백은 한 줄도 바뀌지 않는다.** 유휴 정지 판정(실측 504행)도,
  가시성 게이팅도, DPR 처리도 그대로다.
- **`await file.text()` 의 비동기는 004 가 말한 그 비동기가 아니다.** 004 가 든 것은
  "**그리는 동안** 아직 안 온 것이 있다" 이고, 여기서는 그리기가 시작되기 **전에** 전부
  끝나 있다. 요소가 `elements[]` 에 들어간 시점에 그림에 필요한 것은 **숫자뿐**이다.
- **그래서 001 REQ-05 는 007 에 대해 무동작이다** — 경로 요소가 스무 개든 가져온 것이든
  트윈이 없으면 프레임은 예약되지 않는다(008 AC-E3 가 이미 잰 성질이며 007 이 다시 잰다).

### 결정 1 — 명령 축약: SVG 의 열 가지가 넷이 되는 법

**SVG 경로 데이터의 모든 명령이 `M`·`L`·`C`·`Z` 로 축약된다.** 축약은 **저장 전에** 끝난다 —
`PathCommand` 에 다섯 번째 갈래를 만들지 않는다.

| SVG | → | 방법 | 정확한가 |
|---|---|---|---|
| `m l h v c s q t a z`(상대) | 절대 | 현재 점을 누적해 더한다 | **정확** |
| `H x` / `V y` | `L` | 빠진 축은 현재 점의 값 | **정확** |
| `L` `C` `M` `Z` | 그대로 | — | **정확** |
| `S x2 y2 x y` | `C` | `c1` = 직전 `C`/`S` 의 `c2` 를 현재 점에 대해 반사. 직전이 `C`/`S` 가 **아니면** `c1` = 현재 점 | **정확** |
| `Q qx qy x y` | `C` | `c1 = p0 + ⅔(q − p0)`, `c2 = p + ⅔(q − p)` | **정확(항등)** |
| `T x y` | `Q` → `C` | `q` = 직전 `Q`/`T` 의 `q` 를 반사. 직전이 `Q`/`T` 가 **아니면** `q` = 현재 점 | **정확** |
| `A rx ry φ fa fs x y` | `C` 여럿 | 끝점→중심 매개변수화 후 ≤90° 조각마다 3차 근사 | **근사(아래 오차 한계)** |

**"직전이 그 종류가 아니면 현재 점" 이라는 조항 둘이 이 표에서 가장 잘 틀리는 자리다.**
그리고 `Z` 뒤의 현재 점은 **직전 점이 아니라 그 부분 경로의 시작점**이다 — `Z` 뒤에 오는
상대 명령이 그 규칙을 안 지키면 조각이 어긋난 자리에서 출발한다. 셋 다 시험 규율이 고정
입력을 못박는다(acceptance.md E4 · E5).

또 하나: **`M x y x2 y2 …` 처럼 좌표쌍이 이어지면 두 번째부터는 암묵적 `L`(소문자면 `l`)이다.**
`m` 뒤의 암묵 `l` 은 상대다. 이것을 "M 이 여러 개" 로 읽으면 채워야 할 도형이 점들의 나열이
된다.

#### `A` → 3차 베지어: 받아들이는 오차와 그 산술

**008 의 `k ≈ 0.5523` 은 여기 쓰지 않는다.** 그 상수는 **4분원 전용**이며, 회전(`φ`)과
두 플래그를 가진 일반 타원 호는 다른 문제다. 007 이 쓰는 것은 SVG 1.1 부록 F.6.5 의
끝점→중심 매개변수화이고, 조각각 `δ` 에 대한 일반식 **`k = (4/3)·tan(δ/4)`** 다.
`δ = 90°` 이면 `k = (4/3)·tan(22.5°) = 0.552285…` 로 008 의 상수와 **같은 수가 나온다** —
008 의 상수는 이 식의 특수해다.

**받아들이는 오차: 조각각을 90° 이하로 잘라 얻는 최대 반경 오차 `≤ 0.027% × max(rx, ry)`.**
타원의 회전 `φ` 는 등거리 변환이라 오차를 키우지 않고, `rx ≠ ry` 는 원 공간의 오차를 축별로
늘일 뿐이라 상한이 `max(rx, ry)` 로 선다.

**그 오차가 화면에서 어디쯤인지 수로 적는다**(가정 A3 · 008 이 같은 자리에서 한 산술):

```
최악: rx = ry = PATH_LOCAL_EXTENT/2 = 5000 로컬 단위
  → 반경 오차 ≤ 0.00027 × 5000 = 1.35 로컬 단위
로컬 격자 양자화 오차                    = 0.5 로컬 단위
합                                        ≈ 1.85 로컬 단위

요소 상자 한 변 160 캔버스 단위에서:     1.85 / 10000 × 160 = 0.0296 캔버스 단위
  → 캔버스 자체의 양자(1 단위)보다        약 34배 작다
스테이지 축척 0.5 에서:                   0.0148 px
  → FLATTEN_TOLERANCE_PX(0.5) 보다        약 34배 작다
```

즉 **호 근사 오차는 이미 받아들인 두 여유(캔버스 양자 · 평탄화 허용 오차) 어느 쪽보다도 두
자릿수 작다.** 이 관계가 뒤집히면 그것은 결함이 아니라 상수의 잘못이다(불변식 K5 — 008 의
J4 와 같은 규율).

**조각각을 45° 로 더 잘게 자르는 안을 기각한다.** 오차는 대략 `δ⁶` 로 줄어드니 45° 는
90° 의 1/64 이지만, **명령 수는 두 배**가 되고 그 수는 `MAX_PATH_COMMANDS` 라는 죔쇠를
직접 먹는다(§명령 상한). 위 산술이 이미 34배 여유를 보이므로 그 두 배를 살 이유가 없다.

#### 플래그를 틀리게 읽었을 때 시험이 그것을 어떻게 잡는가

`fa`(large-arc)와 `fs`(sweep)는 같은 두 끝점 사이에 **서로 다른 호 넷**을 만든다. 그래서
잘못 읽는 방식도 넷이다: 둘의 순서를 바꿔 읽기 · `fa` 를 무시하기 · `fs` 를 무시하기 ·
둘을 바꿔 쓰기.

**둘 다 0 인 고정 입력 하나로는 그 넷을 하나도 잡지 못한다** — 순서를 바꿔 읽어도 `(0,0)`
이고, 무시해도 `(0,0)` 과 같은 결과가 나온다. 이것이 브리핑이 지목한 그 함정이며, 시험은
아래를 **전부** 갖춰야 한다.

1. **네 조합 `(0,0) (0,1) (1,0) (1,1)` 을 전부 넣고, 평탄화한 폴리라인 넷이 서로 쌍마다
   다름을 단언한다.** 넷 중 둘이라도 같아지면 어떤 축이 죽은 것이다.
2. **`fs` 는 방향을 뒤집는다** — `(p0 → 호 → p1 → p0)` 의 **부호 있는 넓이**가 `fs=0` 과
   `fs=1` 에서 **부호가 반대**임을 단언한다.
3. **`fa` 는 크기를 키운다** — 현(chord) 중점에서 폴리라인 위 가장 먼 점까지의 거리가
   `fa=1` 에서 `fa=0` 보다 **크다**를 단언한다.
4. **알려진 점 하나** — 호의 중간 매개변수 지점이 해석적으로 계산한 중심·반경에서
   `0.027% × max(rx,ry)` 안에 있음을 단언한다(오차 한계 자체를 시험이 못박는다).
5. **뮤테이션**: `fa` 와 `fs` 의 읽는 순서를 맞바꾸면 1·2·3 가운데 **적어도 하나가 빨개져야
   한다**. 빨개지지 않으면 고정 입력이 대칭이라 가드가 자고 있는 것이다.

#### 그리고 붙은 플래그 — 실제 파일이 이 파서를 죽이는 자리

SVG 경로 문법에서 플래그는 **한 글자**다. 그래서 `a50 30 20 0160 20` 은 합법이며
`rx=50 ry=30 φ=20 fa=0 fs=1 x=60 y=20` 을 뜻한다. **SVGO · Illustrator · Figma 의 내보내기가
정확히 이 형태를 낸다.** 플래그를 일반 수로 읽는 토크나이저는 `0160` 을 한 수로 삼켜
그 뒤가 전부 밀린다 — 그림이 알아볼 수 없게 되지만 예외는 없다.

같은 부류의 문법 함정 셋을 더 못박는다.

- **`5.5.5` 는 두 수다** (`5.5` 그리고 `.5`). `parseFloat` 로 한 번에 읽으면 하나가 된다.
- **`.5` · `-.5` · `1e-5` · `1E5` 는 전부 합법이다.**
- **구분자는 공백일 수도 쉼표일 수도, 부호가 곧 구분자일 수도 있다** (`10-20` 은 두 수다).

### 결정 2 — 단축 요소: 여섯을 받고 나머지는 보고한다

| SVG 요소 | 받는가 | 무엇이 되는가 |
|---|---|---|
| `<path d>` | **받는다** | §결정 1 의 축약 |
| `<rect x y width height rx ry>` | **받는다** | `rx`/`ry` 가 없으면 `M L L L Z`. 있으면 변 넷(`L`) + 모서리 넷(`C`, 90° 호) |
| `<circle cx cy r>` | **받는다** | 4분원 넷 = `M C C C C Z` |
| `<ellipse cx cy rx ry>` | **받는다** | 같음 |
| `<line x1 y1 x2 y2>` | **받는다** | `M L` — **열린다**(`Z` 없음) |
| `<polyline points>` | **받는다** | `M L*` — **열린다** |
| `<polygon points>` | **받는다** | `M L* Z` |
| `<use href>` | **받는다(같은 문서 참조만)** | §결정 3 |
| `<text> <tspan> <textPath>` | 받지 않는다 | 보고(버림) — §이연 |
| `<image>` | 받지 않는다 | 보고(버림). **이것을 받으면 004 의 둘째 근거가 되살아난다** |
| `<foreignObject>` | 받지 않는다 | 보고(버림) |
| 중첩 `<svg>` | 받지 않는다 | 보고(버림) |
| `<defs> <symbol> <clipPath> <mask> <marker> <pattern>` | **내려가지 않는다** | **버림이 아니다** — SVG 사양이 이들을 직접 그리지 않으므로 건너뛰는 것이 곧 옳은 렌더다. `<use>` 가 가리키면 그때 내용이 산다 |
| `<metadata> <title> <desc> 주석 · 미지 네임스페이스 원소` | **내려가지 않는다** | 버림이 아니다 |

**`<defs>` 를 "버렸다" 고 보고하지 않는 것이 이 표의 요점이다.** 그리지 않는 것을 버렸다고
말하면 보고가 잡음이 되고, 잡음이 섞인 보고는 읽히지 않으며, 읽히지 않는 보고는 침묵과
같다. **보고에는 그림에 실제로 영향을 준 것만 오른다.**

**모서리 둥근 `rect` 의 세부**(실제 파일이 자주 어기는 자리): `rx` 만 있으면 `ry = rx`,
`ry` 만 있으면 `rx = ry`, 둘 다 없으면 모서리 없음. `rx > w/2` 는 `w/2` 로, `ry > h/2` 는
`h/2` 로 죈다. 음수·비유한은 없는 것으로 읽는다.

**기각 — `<line>`/`<polyline>` 을 `Z` 로 닫기.** 닫으면 채움이 생기고, 008 의
`pathSeedStyle` 은 `Z` 가 있으면 **채움 씨앗**을 심는다(실측). 열린 것을 닫으면 저술한 적
없는 변이 하나 생겨 화면에 정체 모를 덩어리가 나온다 — 008 이 곡선 화살표에 대해 이미
이름으로 적은 그 결함이다.

### 결정 3 — `transform` 과 `viewBox`

#### `transform` 은 좌표에 녹인다

`PathCommand` 는 변환을 나르지 않으므로 **좌표에 녹이는 것 말고 다른 길이 없다.**

- 받는 함수: `translate(tx[,ty])` · `scale(sx[,sy])` · `rotate(a[,cx,cy])` ·
  `matrix(a b c d e f)` · `skewX(a)` · `skewY(a)`. 각도는 **도(degree)** 다.
- 한 속성 안의 여러 함수는 **왼쪽이 바깥**이다(오른쪽부터 점에 적용된다).
- `<g>` 중첩은 **조상이 바깥**이다. 순회하며 2×3 행렬을 곱해 내려간다.
- **`<svg>` 루트의 `transform` 은 무시한다**(SVG 1.1 은 최외곽 `svg` 의 `transform` 을 정의하지
  않는다). 있으면 보고에 근사로 오른다.

**불변식 — `A` 축약이 `transform` 적용보다 먼저다**(불변식 K2). 아핀 변환은 3차 베지어를
3차 베지어로 **정확히** 옮기지만, SVG 의 호는 아핀 아래에서 같은 `rx`/`ry`/`φ` 의 호가
아니다. 순서를 뒤집으면 기울어진 `<g>` 안의 호가 조용히 틀어진다 — **화면에서만 드러나고
어느 시험도 울리지 않는 부류**이므로 형상으로 못박는다.

**비균등 배율 아래의 선 두께.** SVG 는 `scale(2,1)` 안의 선을 이방적으로 굵게 그리지만
캔버스의 `lineWidth` 는 스칼라 하나다. 그래서 `√|det|` 를 쓰고 **보고에 근사로 올린다.**
`|det|` 가 0(퇴화 행렬)이면 그 도형은 그려질 것이 없으므로 버림으로 올린다.

#### `viewBox` 는 로컬 격자에 앉는다

```
viewBox = "minX minY w h"
localX = (userX − minX) × PATH_LOCAL_EXTENT / w
localY = (userY − minY) × PATH_LOCAL_EXTENT / h      ← 축마다 독립이다
```

**축마다 독립으로 늘이면 그림이 일그러지지 않는가.** 일그러진다 — **요소 상자의 종횡비를
문서의 종횡비(`w : h`)로 정하지 않는다면.** 그래서 정한다: **가져온 그림의 상자는 문서
종횡비를 지킨다.** 그러면 로컬 격자의 정사각성과 상자의 비정사각성이 정확히 상쇄되어 화면에
나오는 것이 원본 비율이다.

**기각 — 종횡비를 지켜 로컬 격자 안에 레터박스한다.** 그러면 로컬 좌표 안에 **죽은 여백**이
박히고, 요소 상자의 8핸들이 그림에 닿지 않는 자리에 선다. 상자를 잡아 늘여도 여백이 함께
늘어나므로 사용자는 "왜 손잡이가 그림에서 떨어져 있는가" 를 영영 고칠 수 없다.

**그래서 문서의 `preserveAspectRatio` 를 읽지 않는다.** 그 속성은 뷰포트가 viewBox 를
레터박스하는 규칙인데 007 에는 뷰포트가 없고, **상자의 종횡비를 문서에 맞추는 것이 그
속성이 하려던 일을 이미 한 것**이다. `meet`/`slice`/정렬 지정이 있어도 무시하며, **기본값이
아닌 값이 붙어 있으면 보고에 근사로 올린다.**

**`viewBox` 가 없으면.** 순서는 `svgAsset.ts` 가 스스로 정한 그 순서다.

1. `width`/`height` 속성 — **단위 없는 수 또는 `px` 만 크기로 읽는다.** `%` 는 크기가 아니다
   (svgAsset 의 `lengthOf` 가 이미 그렇게 판정한다 — 실측). 있으면 `0 0 width height`.
2. 둘 다 없거나 못 읽으면 — **변환을 다 녹인 뒤 모든 도형의 합집합 바운딩 박스**를 암묵
   viewBox 로 쓴다.
3. 그 합집합이 퇴화(넓이 0)면 — **가져오기를 거절한다**(그릴 것이 없다).

**어느 경우에도 브라우저에게 크기를 묻지 않는다** — `<img>` 를 만들지 않고 `naturalWidth` 를
읽지 않는다. svgAsset 이 기록한 그 함정이 007 에는 **존재할 자리가 없다.**

#### `<use>` 는 따라간다 — 같은 문서 안에서만, 깊이 상한과 함께

`<use href="#id" x y width height>` 는 실제 파일에 흔하다(도구가 반복 도형을 이렇게 낸다).
따라가지 않으면 아이콘 세트가 통째로 빈 그림이 된다.

- 같은 문서의 `#id` 만 푼다. `xlink:href` 도 같이 본다(구 도구가 그것만 쓴다).
- `x`/`y` 는 `translate(x, y)` 로 접어 넣는다. `width`/`height` 는 `<symbol>`/중첩 `<svg>` 에만
  뜻이 있으므로 **무시하고 보고에 근사로 올린다**.
- **깊이 상한 `MAX_USE_DEPTH = 4`** 와 **경로 순환 검출**(현재 전개 중인 id 집합)을 둘 다 둔다.
  상한에 닿으면 그 가지를 버림으로 보고한다.
- 외부 문서 참조(`href="other.svg#id"`)는 **버림**이다 — 가져오면 §파일은 어디서 오는가의
  "브라우저를 떠나지 않는다" 가 깨진다.

**깊이 상한 가드는 그 상한에 실제로 닿는 고정 입력 없이는 잠든다.** 이 저장소가 이미 물린
부류이므로 시험 규율이 **깊이 5 짜리 문서**를 못박는다(acceptance.md E9).

### 결정 4 — `MAX_PATH_COMMANDS = 256` 은 하드 상한이다

**먼저 그 상수가 무엇을 지키는지 읽는다**(`shapes/pathTypes.ts` 실측):

> 손상되거나 거대한 목록 하나가 **한 프레임을 삼키지 않게** 하는 죔쇠다(REQ-07). 카탈로그
> 30종 가운데 가장 긴 것도 수십 개이므로 256 은 넉넉한 여유다.

그리고 정찰이 **적혀 있지 않은 둘째 하중**을 찾았다.

- **평탄화 비용의 상한이 이 수다.** `pathFlatten` 의 `MAX_SUBDIVISION_DEPTH = 10` 이므로
  한 곡선이 최악 `2¹⁰ = 1024` 점으로 갈라진다. 한 요소의 최악은 `256 × 1024 ≈ 262,144` 점이다.
- **그 비용은 요소마다 든다.** `hitTest` 는 **위에서부터 훑다 처음 맞는 것에서 멈추므로**
  (실측 `canvasHitTest.ts:304`) 빗나간 클릭 한 번은 **모든** 경로 요소를 평탄화한다.
- **상한을 N 배로 올리면 두 비용이 함께 N 배가 되고, 그 아래를 받쳐 줄 두 번째 죔쇠는 없다.**

**그리고 상한을 넘기는 목록을 만들어 내는 순간 생기는 결함이 하나 더 있다 — 이것이 결정을
정한다.** `parsePathCommands` 는 상한을 넘는 명령을 **조용히 자른다**(실측 `canvasConfig.ts:684`
`if (out.length >= MAX_PATH_COMMANDS) break;`). 그러므로 가져오기가 400 명령짜리 요소를
만들면:

> **저장한 직후에는 옳게 보이고, 다이얼로그를 닫았다 다시 열면 뒷부분이 잘려 있다.**

파서를 고칠 일이 아니다 — 그 자름은 001 이래의 견고성 규율이고 007 이 손댈 것이 아니다.
**만들지 않으면 된다.**

#### 채택 — 상한을 올리지 않는다. 감김 무리로 나누고, 그래도 넘으면 그 도형을 거절한다

한 SVG 도형이 256 을 넘으면 순서대로 시도한다.

1. **감김 무리(winding group)로 나눈다.** 부분 경로들을 포함 관계로 묶어(어느 부분 경로가
   다른 것 안에 드는가) 서로 독립인 무리마다 요소를 하나씩 만든다. 도넛의 바깥과 구멍은
   **같은 무리**라 나뉘지 않는다 — nonzero 채움 규칙이 둘을 함께 요구하기 때문이다.
2. **나뉜 조각들은 원본 도형의 상자를 함께 쓴다.** 조각마다 제 잉크의 바운딩 박스를 주는
   안을 **기각한다**: 상자 좌표는 정수 캔버스 단위로 반올림되므로 조각마다 최대 0.5 단위씩
   **서로 어긋난다.** 상자를 공유하면 로컬 좌표가 뜻을 그대로 유지해 어긋남이 **0** 이고,
   히트는 어차피 윤곽으로 하므로 겹친 상자가 선택을 흐리지 않으며, **여덟 핸들이 똑같이
   서는 것 자체가 "이 조각들은 한 덩어리였다" 는 눈에 보이는 표시**가 된다.
3. **한 무리가 그래도 256 을 넘으면 그 도형을 거절하고 보고한다.**

**기각한 안 셋.**

- **상수를 올린다.** 위 두 비용을 함께 올리고 받쳐 줄 것이 없다. 그리고 008 REQ-07 이
  그 죔쇠를 요구 조항으로 적었으므로 올리려면 008 을 개정해야 한다 — 남의 SPEC 의 요구를
  이 SPEC 의 편의로 무르는 일이다.
- **단순화한다(Douglas–Peucker 또는 곡선 재적합).** 사용자가 저술한 적 없는 그림을 만든다.
  그리고 허용 오차를 무엇에 걸 것인가에 답이 없다 — 요소 상자 크기는 **가져오기 시점에
  우리가 고른 값**이라 그 위에 오차를 세우면 오차가 우리 결정에 종속된다. 게다가 곡선을
  폴리라인으로 바꾸면 `C` 가 `L` 로 풀려 **명령 수가 오히려 는다.**
- **자른다(앞에서 256개만).** §결정 5 가 금지하는 그것이다 — 설명 없는 틀린 그림.

**거절이 사용자를 막다른 길에 두지 않는다.** 보고가 그 도형의 명령 수와 상한을 함께 말하고,
"그림 전체를 배경으로 걸고 싶다면 히트맵 패널의 도면 레이어" 라는 다른 길을 이름으로 가리킨다
(그 기능은 이미 있다 — `heatmap/svgAsset.ts`).

### 결정 5 — 못 다루는 것은 조용히 버리지 않는다

**이 저장소가 되풀이해 맞은 실패 형상은 "움직인 것" 이 아니라 "말하지 않은 것" 이었다** —
006 REQ-07 의 내력이 그 문장으로 닫혔다("위험한 것은 침묵이었지 움직임이 아니었다"). 007 은
남의 문서를 읽으므로 침묵할 기회가 가장 많은 SPEC 이다.

**채택 — 놓기 전에 보고하고, 보고는 도크 안 화면에 뜬다. 로그가 아니다.**

보고는 세 갈래로 나뉘고, **셋을 섞지 않는 것이 보고가 읽히는 조건**이다.

| 갈래 | 뜻 | 예 |
|---|---|---|
| **들어옴** | 요소가 된 것 | 도형 N개 · 명령 M개 · 약 K KB |
| **근사됨** | 그렸으나 원본과 다르다 | 그라디언트 → 단색 · 비균등 배율의 선 두께 → `√|det|` · `fill-rule: evenodd` → 감김 뒤집기 · `preserveAspectRatio` 무시 · `<use>` 의 `width`/`height` 무시 |
| **버림** | 그리지 않았다 | `<text>` N개 · `<image>` N개 · 필터 N개 · `clip-path` 참조 N개 · `mask` 참조 N개 · `<style>` 규칙 N개 · 명령 상한 초과 도형 N개 · `<use>` 깊이 초과 N개 · 중첩 `<svg>` N개 |

- **각 항목은 개수를 말한다.** "필터가 있습니다" 가 아니라 "필터 3개를 버렸습니다".
- **`<defs>` 처럼 원래 그려지지 않는 것은 어느 갈래에도 오르지 않는다**(§결정 2).
- **들어올 것이 0 이면 [놓기] 가 서지 않는다** — 빈 요소를 만들지 않는다.
- **보고 요약 한 줄은 접히지 않는다.** 갈래별 목록만 접힌다.
- **토스트로 띄우고 사라지게 하는 안을 기각한다.** 사용자가 [놓기] 를 누르기 전에 읽어야
  하는 정보인데, 사라지는 것은 결정 뒤에 읽힌다.

**필터(`filter`)를 근사가 아니라 버림에 두는 이유**: 그림자·흐림을 무시하고 그린 도형은
원본과 "조금 다른" 것이 아니라 **다른 그림**이고, 사용자가 그것을 근사로 읽으면 미리보기의
차이를 자기 눈 탓으로 돌린다.

### 결정 6 — 파일은 어디서 오는가: 로컬 파일 고르기 하나

**채택 — 도크 안의 `<input type="file" accept=".svg,image/svg+xml">`.**

- **파일이 브라우저를 떠나지 않는다.** 004 가 든 "인증 자산 → data-URL 왕복" 이 존재할 자리가
  없다.
- **백엔드 변경 0 이 유지된다.** 004 · 005 · 006 · 008 이 지켜 온 그 값이 007 에서도 선다.
  본 SPEC 은 Go 파일을 한 줄도 건드리지 않는다.
- **읽는 기구는 이미 있다.** `heatmap/imageAsset.ts` 가 `FileReader` 를 **주입 가능하게** 두어
  DOM 없이 단위 시험한다(실측 머리말). 007 도 같은 형상을 쓴다 — 파서가 받는 것은 **문자열**
  이므로 파서 시험에는 `File` 이 아예 등장하지 않는다.

**기각 — `POST/GET /api/v1/dashboard-assets` 에 올린다.** 그 엔드포인트는 실재하고
`image/svg+xml` 도 받는다(실측 `dashboard_asset.go:43`, 상한 12MB). 그럼에도 기각한다.

1. **004 가 죽인 왕복이 되살아난다** — 인증 헤더 때문에 직접 참조가 안 되어 JSON→data-URL 로
   받아야 한다.
2. **올린 자산이 곧바로 죽은 무게가 된다.** 007 은 문서에서 **기하만 뽑고 문서는 버린다.**
   가져오기가 끝나는 순간 자산은 아무도 읽지 않는 바이트이며, 내용 해시 id 라 지워지지도
   않는다.
3. **되돌아올 이유가 없다.** 재편집을 위해 원본을 보관한다는 논거는 성립하지 않는다 —
   재가져오기는 원본 파일을 다시 고르면 되고, 그 파일은 사용자 기기에 있다.

**기각 — 캔버스 위로 파일을 끌어놓기.** 편리하지만 **캔버스 표면에 드롭 강조라는 표시 층을
그려야 하고, 그 층을 다스리는 손잡이는 도크에만 있다.** 006 이 배달한 I23 결함과 **정확히
같은 형상**이다(§I23). 파일 고르기는 끌기가 아니므로 WCAG 2.2 SC 2.5.7 의 등가물 요구도
발생하지 않는다 — **접근성이 이 기각과 같은 방향을 가리킨다.**

### 결정 7 — 한 번의 가져오기가 낼 수 있는 것

**요소 400개를 내는 가져오기와 4개를 내는 가져오기는 다른 물건이다.** 셋을 죈다.

```
MAX_IMPORT_FILE_BYTES = 2 MiB     ← 파싱 전에 자른다(엔티티 폭탄·거대 문서)
MAX_IMPORT_ELEMENTS   = 64        ← 한 번에 만들 수 있는 요소 수
MAX_IMPORT_COMMANDS   = 640       ← 한 번에 만들 수 있는 명령 총수
```

**요소 수만으로는 바이트가 죄어지지 않는다** — 64개가 전부 256 명령이면 16,384 명령이고,
그것은 예산을 통째로 먹는다. 그래서 **명령 총수를 함께 죈다.**

#### 그 수들의 출처 — 산술

명령 한 개의 직렬화 크기(실측 형상 `{"c":"C","x1":1234,…}`):

```
{"c":"M","x":1234,"y":5678}                                        = 27 B
{"c":"L","x":1234,"y":5678}                                        = 27 B
{"c":"C","x1":1234,"y1":5678,"x2":1234,"y2":5678,"x":1234,"y":5678} = 67 B
{"c":"Z"}                                                           =  9 B
```

- **현실적 혼합**(L 60% · C 30% · M/Z 10%, 구분 쉼표 포함): `≈ 39 B/명령`
  → `640 × 39 ≈ 25.0 KB`
- **요소 한 건의 명령 밖 부분**(id · kind · geometry · style): `≈ 135 B`
  → `64 × 135 ≈ 8.6 KB`
- **합 ≈ 33.6 KB = 256KB 예산의 약 13.1%**
- **최악(640 전부 `C`)**: `640 × 68 + 8.6KB ≈ 52 KB = 예산의 약 20.3%`

**즉 한 번의 가져오기는 어떤 파일에 대해서도 대시보드 예산의 21% 를 넘지 않는다.** 이 상한이
이 결정의 존재 이유이며, 인수 기준이 **실측으로 확인한다**(AC-E5 — 008 이 같은 자리에서
한 일).

#### 넘으면 무엇을 하는가 — 거절한다

**거절이다. 자르지 않는다.** 앞에서 64개만 가져오면 z-order 를 잘라 낸 그림이 되고, 그것은
§결정 5 가 금지하는 "설명 없는 틀린 그림" 이다.

**기각 — "412개 중 앞의 64개만 가져올까요?" 를 제안한다.** 사용자가 동의한 절단은 침묵이
아니지만, **절단된 SVG 는 거의 언제나 의미가 없다** — 도구가 내는 순서는 배경→전경이라
앞의 64개는 대개 배경 조각들이다. 알고 하는 무의미한 선택지는 선택지가 아니다.

**기각 — 대시보드 페이로드 실제 크기를 보고 죈다.** 그것이 이상적이지만 **패널은 대시보드
페이로드를 보지 못한다.** 256KB 판정은 서버의 PUT 경계에 있고(실측 `dashboard.go:738`
`Content-Length > maxDashboardPayloadBytes` → 413), 거기까지 가면 **가져오기가 아니라 저장이**
실패해 원인이 사용자에게 보이지 않는다. 고정 상한은 **일찍 · 읽히는 자리에서** 실패하기
위한 것이다.

#### 묶음으로 만들 것인가 — 이미 만들어져 있다

가져오기가 낸 요소들을 **하나로 묶을 그릇**은 007 이 만들지 않는다. 두 기구가 이미 있다.

1. **놓은 직후 새 id 전부를 선택으로 세운다**(008 REQ-04 가 스크래치패드 놓기에 대해 한 그것).
   오버레이의 무리 이동이 선택 전부에 같은 델타를 더하므로 **놓자마자 한 덩어리로 끌린다.**
2. **그 선택을 스크래치패드에 한 단추로 저장한다**(008 이 배달한 "선택 항목 저장").
   그러면 가져온 그림이 **되쓸 수 있는 항목 하나**가 된다 — 서랍의 한도 안에 든다
   (실측 `SCRATCHPAD_MAX_ENTRIES = 50` · `SCRATCHPAD_MAX_BYTES = 256KB`; 최악 52KB 짜리
   가져오기는 그 서랍의 20% 를 쓴다).

**진짜 그룹 노드는 004 의 몫이다.** 004 가 착륙하면 가져온 요소들도 `GroupElement.parts` 에
그대로 담긴다 — 그 필드의 타입이 `CanvasElement[]` 이므로 형상 변경이 없다(008 REQ-08 이
스크래치패드에 대해 못박은 그 성질과 같다).

### 결정 8 — 스타일 추출: 아홉 축에 무엇이 앉고 무엇이 떨어지는가

`ElementStyle` 은 **정확히 아홉 축**이다(실측 `canvasConfig.ts:190–204`):
`fill` · `stroke` · `strokeWidth` · `opacity` · `fontSize` · `fontWeight` · `textColor` ·
`align` · `visible`.

| SVG | → `ElementStyle` | 비고 |
|---|---|---|
| `fill="<color>"` | `fill` | 그대로 |
| `fill="none"` | 없음 | 채우지 않는다. `paintFill` 이 `undefined` 면 안 그린다(실측) |
| `fill="url(#g)"` | `fill`(**근사**) | 참조된 그라디언트의 **첫 `<stop stop-color>`**. 못 읽으면 씨앗 색 |
| `stroke` / `stroke="none"` | `stroke` | 같은 규칙 |
| `stroke-width` | `strokeWidth` | 아래 §단위 |
| `opacity` | `opacity` | 요소 전체 불투명도 → `globalAlpha`(실측 272행) |
| `fill-opacity` | **`fill` 색의 알파로 접는다** | 아래 §알파 |
| `stroke-opacity` | **`stroke` 색의 알파로 접는다** | 같음 |
| `stop-color` / `stop-opacity` | 위 그라디언트 근사의 입력 | |
| `display:none` · `visibility:hidden` | **요소를 만들지 않는다** | 아래 §감춤 |
| `fill-rule="evenodd"` | 감김 방향 변환(**근사**) | 아래 §evenodd |
| `stroke-linecap` · `linejoin` · `miterlimit` · `dasharray` · `dashoffset` | **떨어진다** | `ElementStyle` 에 축이 없다. `dasharray` 는 **버림**으로 보고(점선이 실선이 되는 것은 다른 그림이다). 나머지 셋은 보고하지 않는다 — 끝 모양의 차이는 두께 2px 에서 눈에 띄지 않는다 |
| `filter` · `clip-path` · `mask` | **떨어진다 · 버림 보고** | |
| `font-*` · `text-anchor` | 해당 없음 | `<text>` 를 받지 않으므로 `fontSize`·`fontWeight`·`textColor`·`align` **네 축은 007 이 한 번도 쓰지 않는다** |

**아홉 축 가운데 007 이 쓰는 것은 다섯**(`fill`·`stroke`·`strokeWidth`·`opacity`·`visible`)
**이고 넷은 글자 축이라 원리적으로 쓰이지 않는다.** 이 분해가 §결정 2 의 `<text>` 거절과
같은 사실의 두 얼굴이다.

#### 알파 — 축이 하나뿐인데 SVG 는 셋이다

SVG 는 `opacity` · `fill-opacity` · `stroke-opacity` 를 따로 갖고 `ElementStyle` 은
`opacity` 하나만 갖는다. 그러나 **잃지 않고 옮길 수 있다.**

`drawElement.paintFill` 은 `ctx.fillStyle = style.fill` 로 **문자열을 그대로 넘긴다**(실측
178–182행). 그러므로 `rgba(r,g,b,a)` 와 `#RRGGBBAA` 가 그대로 산다.

```
style.fill    ← 색에 (fill-opacity)   를 접은 rgba/8자리 hex
style.stroke  ← 색에 (stroke-opacity) 를 접은 rgba/8자리 hex
style.opacity ← 요소 수준 opacity 그대로
```

**이것은 근사가 아니라 정확한 옮김이다.** 그래서 보고에 오르지 않는다. 셋을 곱해 하나로
뭉개는 안(`opacity × fill-opacity`)을 기각한다 — 채움과 선의 불투명도가 다른 도형에서
둘 중 하나가 조용히 틀어진다.

#### 선 두께의 단위 — 있는 규율을 그대로 쓴다

`strokeWidth` 는 투영을 지나지 않는 **원시 px** 다(실측: `ctx.lineWidth =
resolveStrokeWidth(style.strokeWidth)`, 축척이 곱해지지 않는다). 이것은 007 이 만드는 성질이
아니라 **이 패널의 모든 요소가 이미 가진 성질**이다.

그래서 변환도 그 규율을 따른다: SVG 사용자 단위의 두께를 **`상자 크기 ÷ viewBox 크기` 비로
캔버스 단위로 옮기고 그 수를 그대로 적는다.** 축척 1 에서 정확하고(006 불변식 I21 — 편집이
꺼진 채 저술 크기 패널에 놓였을 때), 다른 축척에서는 다른 모든 요소와 **같은 방식으로**
어긋난다. **새 규율을 만들지 않는 것이 요점이다.**

상자 종횡비를 문서 종횡비로 맞추는 결정(§결정 3) 덕에 이 비는 **두 축에서 같다** —
비균등 축척은 문서 **안쪽**의 `transform` 에서만 생기고, 그때만 `√|det|` 근사를 보고한다.

#### 감춤 — 만들지 않고 보고한다

`display:none` 또는 `visibility:hidden` 인 도형을 `visible: false` 로 가져오는 안을 **기각**
한다. 그렇게 하면 사용자가 볼 수 없는 요소가 **요소 상한과 명령 상한을 먹는다** — 보이는
그림이 상한에 걸려 거절되었는데 원인은 화면에 없는 도형인 상황이 생긴다. **만들지 않고
개수를 보고한다.** 침묵이 아니므로 001 의 "보이지 않는 요소를 만들지 않는다" 규율과도
어긋나지 않는다.

#### `fill-rule: evenodd` — 감김으로 옮긴다

캔버스의 `fill()` 은 nonzero 이고 `ElementStyle` 에는 채움 규칙 축이 없다. 008 은 그 사실을
알고 **카탈로그 셋의 감김 방향을 손으로 맞춰 두었다**(실측 `shapeCatalog.ts` 머리말).

**채택 — 포함 관계로 evenodd 를 nonzero 로 옮긴다.** 부분 경로 A 가 B 안에 들면 A 의 감김을
B 와 **반대로** 뒤집는다. 중첩 깊이가 짝수/홀수인지로 방향을 정하면 evenodd 의 의미가
nonzero 위에서 **정확히** 재현된다 — 부분 경로들이 서로 교차하지 않는 한.

**한계를 이름으로 적는다: 스스로 교차하거나 서로 교차하는 부분 경로에서는 두 규칙이 원리적
으로 다르며, 그때 이 변환은 틀린다.** 그래서 이 변환은 **언제나 근사로 보고**한다 — 옳게
옮겨진 경우까지 포함해서. 사용자가 미리보기에서 확인할 수 있게 하는 편이, 파서가 "이번엔
정확했다" 를 판정하려 드는 것보다 싸고 정직하다.

#### 세 스타일 출처 — 둘을 받고 하나를 거절한다

| 출처 | 받는가 | 우선순위 |
|---|---|---|
| 표현 속성 (`fill="red"`) | **받는다** | 가장 낮다 |
| `style` 속성 (`style="fill:red"`) | **받는다** | 가장 높다 |
| `<style>` 안의 CSS 규칙 | **받지 않는다 · 버림 보고** | — |

**`<style>` 을 받지 않는 것은 §파싱한 문서를 살아 있는 DOM 에 붙이지 않는다의 귀결이다.**
CSS 캐스케이드를 옳게 적용하는 길은 둘뿐이다.

- **`getComputedStyle`** — 요소가 **살아 있는 문서 안에** 있어야 한다. 그 순간 위 불변식이
  깨지고, svgAsset 이 스크립트 격리를 위해 그은 선이 무너진다. 그리고 **jsdom 에는 레이아웃이
  없어 시험에서 서지 않는다**(측정).
- **선택자 엔진을 들인다** — 신규 의존성이거나 수백 줄의 새 코드이고, 특이도 계산·상속·
  `!important` 까지 따라와야 한다. 007 의 크기가 아니다.

**그래서 스타일 상속(`<g fill="red">` 안의 자식)은 어떻게 되는가.** 표현 속성과 `style`
속성의 **상속만** 순회 중에 쌓아 내려간다 — 그것은 CSS 엔진이 아니라 트리 순회의 부수
효과이며 `transform` 을 쌓는 것과 같은 층이다. 상속되는 속성은 SVG 사양이 상속으로 정한
것(`fill`·`stroke`·`stroke-width`·`fill-rule`·`fill-opacity`·`stroke-opacity`)만이고,
`opacity` 는 **상속되지 않는다**(그룹 불투명도는 합성 규칙이지 상속이 아니다).

**그룹 `opacity` 를 자식에게 곱해 내리는 안을 기각한다.** SVG 의 그룹 불투명도는 "자식들을
따로 그린 뒤 그 결과 전체에 알파를 곱한다" 이고, 자식마다 곱하면 **겹친 자리가 진해진다.**
곱해 내리는 것이 흔한 편법이지만 겹침이 있는 그림에서 눈에 보이게 틀린다. **그룹 `opacity` 는
버림이 아니라 근사로 보고하고 자식마다 곱한다** — 대안이 그룹 노드(004 의 주제)뿐이기
때문이며, 그 사실을 감추지 않는다.

### I23 — 그려지는 자리에 손잡이가 닿는가

006 0.7.0 이 세운 원리다: **표시 층이 그려지는 자리에는 그 층을 다스리는 손잡이가 닿아야
한다.** 006 은 표시 층 셋을 조건 없이 그리면서 컨트롤 전부를 `dockHost !== null` 뒤에 두어
그 원리를 깼고, **어떤 시험도 울리지 않았다 — 두 조건이 같은 자리에서 비교된 적이 없었기
때문**이다. 008 은 그 대조를 **기계적으로** 했다(M7 · AC-E9). 007 도 같은 것을 요구한다.

**007 이 그 원리에 대해 답해야 하는 질문은 하나다: 대시보드(도크 없음)에서 가져오기 컨트롤은
무엇을 하는가.**

**답 — 아무것도 하지 않는다. 존재하지 않는다.** `CanvasEditDock` 은 설정 다이얼로그 안에만
살고 대시보드에서는 `dockHost === null` 이다(실측 `canvasEditDockHost.ts`). 007 의 화면
요소는 **전부 그 도크 본문의 자식**이다.

그 "없음" 이 006 의 결함과 같은 형상이 아닌 이유를 셋으로 적는다.

1. **가져오기는 표시 층이 아니라 컨트롤이고, 캔버스 표면에 아무것도 그리지 않는다.**
   층과 손잡이의 렌더 조건이 **같은 한 값**(`dockHost !== null`)이므로 I23 은 **형상으로**
   지켜진다. 006 이 깬 것은 "조건 없이 그려지는 층 + 조건부 손잡이" 였고, 007 에는 그 조합이
   만들어질 자리가 없다.
2. **그래서 캔버스 위로 파일을 끌어놓지 않는다**(§결정 6). 그것을 받으면 드롭 강조가
   **다스릴 수 없는 표시 층**이 되어 006 의 결함이 그대로 재현된다. 이 금지는 편의의 문제가
   아니라 I23 의 직접 귀결이다.
3. **놓인 요소는 새 비대칭을 만들지 않는다.** 가져온 `path` 요소는 008 의 경로와 **같은
   컨트롤**(선택 · 드래그 · 8핸들 · 목록 편집기 · 정렬 · 순서)로 다스려지고, 그 컨트롤은
   006 M7 이 작업 영역까지 넓혀 둔 그대로 대시보드에서도 닿는다.

**이 셋을 시험이 비교하게 만든다 — 유추가 아니라 기계로**(acceptance.md E11 · AC-E9).

### 범위 — 무엇이 들어오고 무엇이 안 들어오는가

**들어온다:** 로컬 SVG 파일 고르기 · `DOMParser` 파싱 · 경로 데이터 축약(10 명령 → 4) ·
단축 요소 7종 · `transform` 평탄화 · `viewBox` 매핑 · `<use>` 전개 · 스타일 추출 ·
evenodd→nonzero 변환 · 감김 무리 분할 · 예산 죔쇠 셋 · 가져오기 보고 · 미리보기 · 놓기 ·
놓은 뒤 전량 선택.

**들어오지 않는다:**

- **`<text>` 가져오기.** §이연이 값을 적는다.
- **내장 래스터(`<image>`) 가져오기.** 받으면 004 의 둘째 근거가 되살아난다.
- **`<style>` CSS 캐스케이드.** §결정 8.
- **SVG 로 **내보내기**.** 반대 방향이며 다른 주제다(§이연).
- **원본 문서 보관 · 재편집.** §결정 6 기각 2.
- **캔버스 위로 끌어놓기.** §I23.
- **정점 편집기.** 009 의 주제(008 이 예약).
- **004 의 `group`.** 004 의 주제.
- **취소/되돌리기.** 이 패널에 오늘 없으며 007 이 만들지 않는다(위험 R11).

### 이연 — 무엇을 미루고, 미룬 것이 무엇을 치를지

**(1) `<text>` 가져오기.** `TextElement` 가 실재하므로 형상만 보면 담을 수 있다. 미룬 값:

- **이 패널의 글꼴은 하나다**(`DEFAULT_FONT_FAMILY`, 실측). 원본의 글꼴이 무엇이든 다른
  자형으로 그려지고, **글자 폭이 달라진다.** 그러면 그 글자에 맞춰 그려진 상자·밑줄·말풍선이
  전부 어긋난다 — "글자만 조금 다른" 것이 아니라 **레이아웃이 틀어진다.**
- **`tspan` · `textPath` · `text-anchor` · `dominant-baseline` 에 표현이 없다.** 한 줄
  모델이므로 여러 줄 텍스트는 겹쳐 그려진다.
- **그래서 지금은 버림이고 개수를 말한다.** 사용자는 필요한 글자를 `text` 요소로 직접
  더할 수 있으며, 그 길이 화면에 이미 있다.

**(2) SVG 로 내보내기.** 캔버스를 SVG 문서로 저술하는 일. 007 의 축약이 **한 방향**이라

## 요구사항 (Requirements — EARS)

### REQ-01 — 축약과 그 정확성 (Ubiquitous)

시스템은 **항상** SVG 경로 데이터의 모든 명령(`M m L l H h V v C c S s Q q T t A a Z z`)을
`M`·`L`·`C`·`Z` 넷으로 축약해야 하며, **`PathCommand` 에 다섯 번째 갈래를 만들지 않아야
한다**.

시스템은 **항상** `H`/`V`/`S`/`Q`/`T`/상대 명령을 **정확히(무손실로)** 축약해야 한다.
`Q → C` 는 `c1 = p0 + ⅔(q − p0)` · `c2 = p + ⅔(q − p)` 여야 한다.

시스템은 **항상** `A` 를 끝점→중심 매개변수화 후 **조각각 90° 이하**의 3차 베지어들로
축약해야 하며, 그 최대 반경 오차가 **`0.027% × max(rx, ry)` 이하**여야 한다.

시스템은 **항상** `A` 의 사양 규정 경계를 지켜야 한다: 두 끝점이 같으면 **그 명령을 통째로
건너뛰고**, `rx` 또는 `ry` 가 0 이면 **직선(`L`)으로** 읽으며, 반지름이 모자라면
(`Λ > 1`) **`√Λ` 배로 키운다**.

시스템은 **항상** `Z` 뒤의 현재 점을 **그 부분 경로의 시작점**으로 두어야 한다.

시스템은 **항상** `M`/`m` 뒤에 이어지는 좌표쌍을 **암묵 `L`/`l`** 로 읽어야 한다.

시스템은 **항상** SVG 경로 문법의 토큰 규칙을 지켜야 한다: **플래그는 한 글자**이고(`0160`
은 `0`·`1`·`60` 이다), `5.5.5` 는 **두 수**이며, 부호는 구분자 역할을 한다.

시스템은 **항상** `DrawContext2D` 에 **멤버를 하나도 더하지 않아야 한다**.

### REQ-02 — 문서 층: 요소 · 변환 · viewBox (Ubiquitous)

시스템은 **항상** `DOMParser.parseFromString(text, 'image/svg+xml')` 로 문서를 읽어야 하며,
**파싱 결과(또는 그 자손)를 어떤 살아 있는 문서에도 붙이지 않아야 한다**.

시스템은 **항상** SVG 기하 DOM API(`getBBox` · `getTotalLength` · `getPointAtLength` ·
`pathSegList` · `getCTM` · `getComputedStyle`)를 **하나도 쓰지 않아야 한다** — 속성 읽기와
트리 순회만 써야 한다.

시스템은 **항상** `path` · `rect`(`rx`/`ry` 포함) · `circle` · `ellipse` · `line` ·
`polyline` · `polygon` 일곱을 받아야 하며, `line` 과 `polyline` 은 **닫지 않아야 한다**.

시스템은 **항상** `transform`(`translate`·`scale`·`rotate`·`matrix`·`skewX`·`skewY`)을
조상 `<g>` 를 거쳐 누적한 뒤 **좌표에 녹여야** 한다. 시스템은 **항상** `A` 축약을
`transform` 적용보다 **먼저** 해야 한다.

시스템은 **항상** `viewBox` 를 축마다 독립으로 로컬 격자 `0..PATH_LOCAL_EXTENT` 에 앉히고,
**요소 상자의 종횡비를 문서 종횡비로** 정해야 한다. 시스템은 **항상** 문서의
`preserveAspectRatio` 를 **읽지 않아야** 하며, 기본값이 아닌 값이 있으면 근사로 보고해야 한다.

시스템은 **항상** `viewBox` 가 없으면 `width`/`height` 속성(단위 없음 또는 `px` 만)을,
그것도 없으면 **변환을 녹인 뒤의 합집합 바운딩 박스**를 쓰고, 그것이 퇴화하면 가져오기를
**거절해야** 한다.

시스템은 **항상** 브라우저에게 문서 크기를 **묻지 않아야 한다**(`<img>` 생성 금지 ·
`naturalWidth` 참조 금지).

시스템은 **항상** `<use>` 를 같은 문서의 `#id` 에 대해서만 전개하고, **깊이 상한과 순환
검출**을 함께 두어야 한다. 외부 문서 참조는 버림이어야 한다.

시스템은 **항상** `<defs>`·`<symbol>`·`<clipPath>`·`<mask>`·`<marker>`·`<pattern>` 안으로
내려가지 **않아야** 하며, 그 건너뜀을 **버림으로 보고하지 않아야 한다**.

### REQ-03 — 예산과 상한 (State-Driven)

**IF** 입력 파일이 `MAX_IMPORT_FILE_BYTES` 를 넘으면 **THEN** 시스템은 **파싱하기 전에**
거절하고 그 사실과 상한을 화면에 말해야 한다.

**IF** 한 SVG 도형의 축약 결과가 `MAX_PATH_COMMANDS` 를 넘으면 **THEN** 시스템은 먼저
**감김 무리 단위로 나누어** 보고, 그래도 넘는 무리가 있으면 **그 도형을 거절하고 보고해야
한다**. 시스템은 명령을 **잘라서는 안 되며**, `MAX_PATH_COMMANDS` 를 넘는 목록을 가진 요소를
**만들어서는 안 된다**.

**IF** 나뉜 조각들이 생기면 **THEN** 그 조각들은 **원본 도형의 상자를 함께 써야 한다**.

**IF** 산출 요소 수가 `MAX_IMPORT_ELEMENTS` 를 넘거나 명령 총수가 `MAX_IMPORT_COMMANDS` 를
넘으면 **THEN** 시스템은 가져오기 전체를 **거절하고** 실제 수와 상한을 함께 말해야 한다 —
앞부분만 가져와서는 **안 된다**.

**IF** 가져올 것이 하나도 없으면 **THEN** [놓기] 는 **쓸 수 없어야** 한다.

**IF** 문서가 파싱되지 않으면 **THEN** 시스템은 예외를 밖으로 던지지 않고 그 사실을 말해야
하며, 판정은 **루트 태그와 `parsererror` 존재 둘 다**를 보아야 한다.

### REQ-04 — 못 다룬 것은 화면이 말한다 (Unwanted)

시스템은 그림에 영향을 준 미지원 내용을 **조용히 버려서는 안 된다** — 보고는 **화면**에
있어야 하고 콘솔 로그만으로는 안 된다.

시스템은 보고를 **들어옴 · 근사됨 · 버림** 세 갈래로 나누어야 하며, 각 항목에 **개수**를
말해야 한다.

시스템은 **원래 그려지지 않는 내용**(`<defs>` 등)을 버림으로 **보고해서는 안 된다**.

시스템은 보고 **요약 한 줄을 접어서는 안 된다**.

시스템은 사용자가 [놓기] 를 누르기 **전에** 보고를 보여야 하며, 사라지는 알림(토스트)만으로
대신해서는 **안 된다**.

시스템은 `<image>`(내장 래스터)를 **받아서는 안 된다** — 받으면 004 가 `drawImage` 를
기각한 근거가 되살아난다.

시스템은 `<text>` 를 받아서는 **안 되며**, 그 개수를 버림으로 말해야 한다.

시스템은 캔버스 표면 위로의 **파일 끌어놓기를 두어서는 안 된다**(I23).

시스템은 팔레트에 **다섯 번째 원시형 단추를 만들어서는 안 된다**.

시스템은 `PanelSettingsDialog.tsx` 를 **자라게 하지 않아야 한다**(006 I7 · 008 J12).

### REQ-05 — 스타일 (Ubiquitous)

시스템은 **항상** 표현 속성과 `style` 속성을 읽고, `style` 속성이 이기게 해야 한다.
시스템은 **항상** `<style>` 안의 CSS 규칙을 **적용하지 않고 버림으로 보고해야 한다**.

시스템은 **항상** SVG 사양이 상속으로 정한 속성만 조상에서 물려받아야 하며, `opacity` 를
**상속 속성으로 다루어서는 안 된다**.

시스템은 **항상** `fill-opacity`/`stroke-opacity` 를 **각각 `fill`/`stroke` 색 문자열의
알파로 접어야** 하며, 셋을 곱해 `style.opacity` 하나로 뭉개서는 **안 된다**.

시스템은 **항상** `stroke-width` 를 `상자 ÷ viewBox` 비로 옮겨야 하며, 그 값의 단위 규율은
이 패널의 **기존 규율 그대로**여야 한다(새 규율을 만들지 않는다).

시스템은 **항상** `display:none`/`visibility:hidden` 인 도형에 대해 **요소를 만들지 않고**
개수를 보고해야 한다.

시스템은 **항상** `fill-rule="evenodd"` 를 포함 관계 기반 감김 뒤집기로 옮기고, **성공 여부와
무관하게 근사로 보고해야 한다**.

시스템은 **항상** 그룹 `opacity` 를 자식마다 곱하되 그것을 **근사로 보고해야 한다**(겹친
자리가 진해지는 성질을 감추지 않는다).

### REQ-06 — 요소 생성과 놓기 (Event-Driven)

**WHEN** 사용자가 [놓기] 를 누르면 **THEN** 시스템은 산출 요소들을 `elements[]` **끝에
문서 순서대로** 덧붙여야 한다(끝 = 맨 위 = 문서의 나중 = SVG 의 위 — 두 순서가 일치한다).

**WHEN** 요소들이 만들어지면 **THEN** id 발급은 **`canvasElementFactory` 의 그 한 입구**를
지나야 한다 — 가져오기가 자기 id 규칙을 갖지 **않아야 한다**.

**WHEN** 상자가 정해지면 **THEN** 시스템은 **문서 종횡비를 지켜 캔버스 안에** 담고, 계단
오프셋을 **가져오기 무리 전체에 한 번만** 더해야 한다 — 요소마다 더하면 그림이 흩어진다.

**WHEN** 상자가 정해지면 **THEN** 시스템은 두 변 모두 **`MIN_ELEMENT_EXTENT` 이상**을
보장해야 한다 — 퇴화 상자는 파서가 기하 전체를 씨앗으로 갈아 끼운다(가정 A15).

**WHEN** 요소의 씨앗 스타일이 정해지면 **THEN** SVG 가 스타일을 말하지 않은 도형은
**008 의 `pathSeedStyle`** 을 써야 한다(닫힘이면 채움, 열림이면 선) — 두 번째 씨앗 규칙을
만들지 않아야 한다.

**WHEN** 놓기가 끝나면 **THEN** 시스템은 **새로 만들어진 요소 id 전부를 선택으로 세워야
한다** — 그래야 놓자마자 한 덩어리로 끌린다.

**WHEN** 가져오기가 취소되면 **THEN** `elements[]` 도 config 도 **한 바이트도 바뀌지 않아야
한다**.

### REQ-07 — 견고성 (Unwanted)

시스템은 파싱·축약·변환 어느 단계에서도 **예외를 밖으로 던져서는 안 된다** — 실패는 값으로
돌아와야 한다.

시스템은 손상된 좌표(비유한 · 결측 · 비수치)를 만나면 그 **명령 하나만** 버리고 나머지를
살려야 하며, 도형 전체나 문서 전체를 죽여서는 안 된다.

시스템은 파싱 전에 입력 바이트를 죄어 **엔티티 확장 폭탄에 브라우저 방어를 기대지 않아야
한다**.

시스템은 `<use>` 전개에 **깊이 상한과 순환 검출**을 두어야 하며, 그 상한이 **실제로 닿는
고정 입력으로 시험되어야 한다**.

시스템은 `PATH_LOCAL_EXTENT` 로 나누는 자리를 **늘려서는 안 된다** — 투영은
`projectPathPoints` 하나다(008 불변식 J3).

시스템은 **두 번째 좌표 공간 변환 함수를 만들어서는 안 된다**.

시스템은 `CanvasProjection` 을 **세 칸으로 넓혀서는 안 된다**.

시스템은 `MAX_PATH_COMMANDS` 를 **키워서는 안 된다**.

### REQ-08 — 후속 SPEC 전방 호환 (Ubiquitous)

시스템은 **항상** 가져온 요소를 **카탈로그에서 놓은 경로와 구별 불가능한 형상**으로 두어야
한다 — 009(정점 편집기)가 출처를 구분할 필요가 없어야 한다.

시스템은 **항상** 가져온 요소가 004 의 `GroupElement.parts`(`CanvasElement[]`)에 **그대로**
담길 수 있게 두어야 한다.

시스템은 **항상** 가져온 요소가 008 의 스크래치패드에 **그대로** 저장될 수 있게 두어야 한다.

시스템은 **항상** 가져온 요소가 **출력 영역 밖에도 놓일 수 있게** 해야 한다(006 계승).

시스템은 **항상** 파싱 층(순수)과 문서 층(DOM)을 **모듈로 갈라** 두어, 훗날 다른 벡터 형식이
들어와도 축약 산술이 재사용되게 해야 한다.

## 명세 (Specifications)

### 층 — DOM 을 아는 모듈은 하나뿐이다

```
문자열 →  [svgDocument.ts]      ← DOM 을 아는 유일한 모듈. 트리 순회 + 속성 읽기
              │  ImportedShape[] (사용자 단위 좌표 · 스타일 원자 · 출처 표식)
              ▼
          [svgPathData.ts]      ← 순수. d 문자열 → 절대 PathCommand[](사용자 단위)
          [svgArc.ts]           ← 순수. A → 3차 베지어들
          [svgShapes.ts]        ← 순수. rect/circle/… → PathCommand[]
          [svgTransform.ts]     ← 순수. 변환 목록 → 2×3, 합성, 점 적용
          [svgStyle.ts]         ← 순수. 속성 자루 → ElementStyle + 보고 항목
              │
              ▼
          [svgImportPlan.ts]    ← 순수. 상자 · 로컬 정규화 · 분할 · 상한 · 보고 집계
              │  { elements: CanvasElement[], report: ImportReport } | { refused: … }
              ▼
          [CanvasSvgImport.tsx] ← 도크 안. 파일 고르기 · 미리보기 · 보고 · 놓기/취소
```

**`svgDocument.ts` 만 DOM 을 안다.** 나머지 여섯은 문자열과 숫자만 다루므로 jsdom 의
SVG 거동에 얽히지 않는다. **이것은 "jsdom 없이 돈다" 는 주장이 아니다** — 이 저장소의 시험
환경은 전역 jsdom 이다(실측). 값은 다른 데 있다: **산술의 시험이 DOM 의 변덕과 분리된다.**

### 자료 모델 — 새 타입은 전부 가져오기 안에서만 산다

```
// 사용자 단위 좌표의 도형 하나(아직 요소가 아니다).
ImportedShape {
  commands: PathCommand[]        // 사용자 단위. 변환은 이미 녹아 있다
  style: ElementStyle            // 알파는 색에 접혀 있다
  closed: boolean                // Z 가 하나라도 있는가(씨앗 스타일 판정용은 아니다 — 실제 스타일이 있으면 그것을 쓴다)
  hasOwnStyle: boolean           // SVG 가 스타일을 말했는가(아니면 pathSeedStyle 을 쓴다)
}

ImportNoteKind = 'approximated' | 'dropped'
ImportNote { kind: ImportNoteKind; reasonKey: string; count: number }

  shapes: number                 // 들어옴
  commands: number
  estimatedBytes: number
  notes: ImportNote[]            // 근사됨 + 버림
}

ImportRefusal { reasonKey: string; actual: number; limit: number }

// 상한 — 전부 이 SPEC 이 새로 두는 상수다.
```

**`CanvasElement` · `PathCommand` · `ElementStyle` · `CanvasPanelConfig` 는 한 글자도 바뀌지
않는다.** 위 타입들은 전부 `svgimport/` 안에 살고 config 로 나가지 않는다.

### 축약 산술 — 명세로 못박는 식

**`Q → C`**
```
c1 = p0 + 2/3·(q − p0)
c2 = p1 + 2/3·(q − p1)
```

**`S` 의 첫 제어점**
```
직전이 C 또는 S 이면   c1 = 2·p0 − 직전의 c2
아니면                  c1 = p0
```

**`T` 의 2차 제어점** — 같은 규칙을 `Q`/`T` 에 대해.

**`A` → 3차들** (SVG 1.1 F.6.5)
```
0) p0 == p1        → 명령을 버린다(호가 없다)
1) rx == 0 || ry == 0 → L p1
2) rx ← |rx|, ry ← |ry|
3) (x1',y1') = R(−φ)·((p0 − p1)/2)
4) Λ = x1'²/rx² + y1'²/ry² ;  Λ > 1 → rx ← √Λ·rx, ry ← √Λ·ry
5) c' = ±√( max(0, (rx²ry² − rx²y1'² − ry²x1'²) / (rx²y1'² + ry²x1'²)) ) · ( rx·y1'/ry , −ry·x1'/rx )
        부호는 fa ≠ fs 이면 +, 같으면 −
6) c  = R(φ)·c' + (p0 + p1)/2
7) θ1 = ∠( (1,0) , ((x1'−cx')/rx, (y1'−cy')/ry) )
   Δθ = ∠( 위 벡터 , ((−x1'−cx')/rx, (−y1'−cy')/ry) )
   fs == 0 && Δθ > 0 → Δθ −= 2π
   fs == 1 && Δθ < 0 → Δθ += 2π
8) n = ceil(|Δθ| / ARC_SEGMENT_MAX_RAD) ; δ = Δθ/n ; k = (4/3)·tan(δ/4)
   조각마다 3차 하나
```

**4단계의 `√Λ` 확대와 5단계의 `max(0, …)` 가 이 식에서 가장 잘 빠지는 둘이다.** 앞의 것이
빠지면 반지름이 모자란 호에서 `NaN` 이 나오고, 뒤의 것이 빠지면 반올림 잔차로 음수 제곱근이
나온다. **둘 다 실제 파일에서 흔하다**(도구가 반올림해 내보낸 좌표).

### 변환 — 2×3 하나

```
M = [ a c e ]      점 적용:  x' = a·x + c·y + e
    [ b d f ]                y' = b·x + d·y + f

translate(tx,ty) = [1 0 tx; 0 1 ty]
scale(sx,sy)     = [sx 0 0; 0 sy 0]
rotate(a)        = [cos −sin 0; sin cos 0]           (a 는 도 → 라디안)
rotate(a,cx,cy)  = T(cx,cy)·R(a)·T(−cx,−cy)
skewX(a)         = [1 tan(a) 0; 0 1 0]
skewY(a)         = [1 0 0; tan(a) 1 0]
matrix(a,b,c,d,e,f) = 그대로

한 속성 안:  M = M₁·M₂·…·Mₙ        (왼쪽이 바깥)
조상 누적:    M = M_조상 · M_자신
선 두께 배율: √|det M|              (비균등이면 근사 보고)
```

### 로컬 정규화 — 나눗셈은 여전히 한 곳

가져오기가 만드는 것은 **로컬 정수 명령**이고, 그것을 px 로 옮기는 나눗셈은 여전히
`projectPathPoints` 하나다(008 불변식 J3). 007 이 하는 것은 **곱셈**이다.

```
box(캔버스 단위) ← 문서 종횡비를 지켜 캔버스 안에 담고 계단 오프셋을 한 번 더한 값
                    두 변 모두 ≥ MIN_ELEMENT_EXTENT

local.x = round( (user.x − minX) × PATH_LOCAL_EXTENT / vbW )
local.y = round( (user.y − minY) × PATH_LOCAL_EXTENT / vbH )
```

**반올림은 `canvasConfig.coordinate()` 의 규율을 그대로 쓴다** — 유한하면 반올림, 아니면
폴백. 두 번째 수치 규율을 만들지 않는다(008 이 같은 자리에서 한 결정).

**로컬 좌표를 clamp 하지 않는다.** 도형의 잉크가 상자 밖으로 나가는 경우가 실재하고(선 두께 ·
문서 밖 좌표), 008 이 말풍선 꼬리에 대해 이미 그렇게 정했다.
