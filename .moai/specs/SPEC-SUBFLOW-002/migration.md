# SPEC-SUBFLOW-002 마이그레이션 가이드

로컬 서브플로우 참조(flow-node) 의미론 변경에 대한 마이그레이션 안내.

## 무엇이 바뀌나 (Breaking)

flow-node 가 **로컬 플로우(bare flow_id)** 를 참조할 때의 기본 동작이 바뀝니다.

| 항목 | 이전 (SPEC-SUBFLOW-001) | 이후 (SPEC-SUBFLOW-002) |
|------|------------------------|------------------------|
| 기본 동작 | 인라인 확장(참조 플로우의 네임스페이스 **복제본**을 부모마다 생성) | **공유(shared)** — 실행 중인 단일 인스턴스에 in-process 라이브 브릿지로 연결 |
| `mode` 미지정 | (개념 없음) | `shared` 로 해석 |
| 같은 플로우 다중 참조 | 참조마다 별도 복제본 | **같은 실행 인스턴스 공유**(fan-in/fan-out) |
| 참조 플로우 편집 반영 | 부모 재시작 시 복제본 재생성 | 참조 플로우(또는 그 플로우)를 재시작하면 모든 참조에 즉시 반영 |
| 참조 플로우 미실행 시 | 복제본이 부모와 함께 항상 실행 | flow-node 오프라인 대기 → 참조 플로우 시작 시 자가치유 연결 |

원격 참조(`remote://{instance}/{flow}`)는 이전과 동일하게 라이브 브릿지로 동작합니다(변경 없음).

## 영향 받는 사용자

- **로컬 flow-node 로 서브플로우를 쓰던 모든 플로우.** `mode` 가 없으므로 재배포 시 자동으로 shared 로 동작합니다.

### 핵심 운영 변화 (반드시 숙지)

shared 모드에서는 **참조 플로우가 독립적으로 실행 중이어야** flow-node 가 메시지를 주고받습니다(자동 시작 안 함).

- 참조 플로우가 정지 상태면 flow-node 는 오프라인(연결 끊김)으로 표시되고 메시지가 전달되지 않습니다.
- 참조 플로우를 시작하면 자가치유로 자동 연결됩니다.

> 기존에 "부모만 시작하면 서브플로우 복제본도 같이 돌던" 동작에 의존했다면, 이제는 **참조 플로우도 별도로 시작**해야 합니다.

## 기존 동작을 유지하려면 (인라인 복제)

flow-node 설정에서 **참조 방식(mode) = 인스턴스(instance)** 로 명시하세요.

- 웹 에디터: flow-node 속성 패널 → "참조 방식" → `instance` 선택.
- 플로우 정의(JSON): 해당 flow-node 의 `config.mode = "instance"`.

instance 모드는 SPEC-SUBFLOW-001 의 인라인 확장 동작을 그대로 보존합니다(자동 시작·부모 종속·복제본 통계 임베디드 병합 포함).

## 통계 화면

- **shared**: 참조 플로우 화면의 노드 통계는 그 플로우의 **직접 실행 통계**입니다(모든 shared 부모의 트래픽이 단일 인스턴스에 누적). 별도 임베디드 병합 없음.
- **instance**: 기존처럼 부모의 임베디드 복제본 통계를 병합해 보여줍니다.
- 혼합(같은 플로우를 shared·instance 가 동시에 참조)도 이중계상 없이 합산됩니다. 노드 통계 응답의 `stat_source`(`direct`/`embedded`/`direct+embedded`)로 출처를 구분합니다.

## 순환 참조

shared/instance/혼합 어느 조합이든 순환(A↔B)은 배포 시 거부됩니다.

## 체크리스트

- [ ] 로컬 서브플로우를 쓰는 플로우에서 참조 플로우가 **독립 실행**되도록 배포 절차 정비.
- [ ] 이전의 "부모만 시작" 운영 스크립트가 있으면 참조 플로우 시작을 추가.
- [ ] 인라인 복제 의미가 반드시 필요한 flow-node 는 `mode: instance` 로 명시.
- [ ] 재배포 후 flow-node 연결 상태 인디케이터(공유=보라색 점)와 통계 확인.
