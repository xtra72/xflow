# SPEC-WEB-001: Web Dashboard - 인수 테스트 기준

## 1. App Shell & Routing (P0)

### AC-WEB-001-01: App Shell 레이아웃 렌더링
```gherkin
기능: SPA 루트 레이아웃

  시나리오: App Shell 정상 렌더링
    주어진 사용자가 인증된 상태일 때
    만약 대시보드 페이지에 접근하면
    그러면 사이드바 네비게이션이 왼쪽에 표시되어야 한다
    그리고 헤더 바가 상단에 표시되어야 한다
    그리고 메인 콘텐츠 영역이 중앙에 표시되어야 한다

  시나리오: 사이드바 접기/펼치기
    주어진 사이드바가 펼쳐진 상태일 때
    만약 사이드바 접기 버튼을 클릭하면
    그러면 사이드바가 아이콘만 표시하는 축소 상태로 변경되어야 한다
    그리고 접기 상태가 localStorage에 저장되어야 한다

  시나리오: 사이드바 접기 상태 유지
    주어진 사이드바가 접힌 상태로 localStorage에 저장되었을 때
    만약 페이지를 새로고침하면
    그러면 사이드바가 접힌 상태로 표시되어야 한다
```

### AC-WEB-001-02: 라우팅 및 인증 가드
```gherkin
기능: 선언적 라우팅 및 접근 제어

  시나리오: 인증된 사용자 라우트 접근
    주어진 유효한 Access Token을 가진 사용자가 있을 때
    만약 /editor/flow-001 경로에 접근하면
    그러면 플로우 에디터 페이지가 렌더링되어야 한다

  시나리오: 미인증 사용자 보호 라우트 접근
    주어진 Access Token이 없는 사용자가 있을 때
    만약 /monitoring 경로에 접근하면
    그러면 /login 페이지로 리다이렉트되어야 한다
    그리고 원래 접근하려던 경로(/monitoring)가 returnUrl로 저장되어야 한다

  시나리오: 활성 메뉴 하이라이트
    주어진 사용자가 /monitoring 경로에 있을 때
    그러면 사이드바의 "모니터링" 메뉴 항목이 하이라이트되어야 한다

  시나리오: 코드 스플리팅 로딩
    주어진 에디터 페이지의 JavaScript 번들이 아직 로드되지 않았을 때
    만약 /editor/flow-001 경로로 이동하면
    그러면 스켈레톤 UI(로딩 상태)가 먼저 표시되어야 한다
    그리고 번들 로드 완료 후 에디터 페이지가 렌더링되어야 한다
```

### AC-WEB-001-03: Error Boundary
```gherkin
기능: 렌더링 에러 처리

  시나리오: 컴포넌트 렌더링 에러 발생
    주어진 특정 페이지 컴포넌트에서 렌더링 에러가 발생할 때
    그러면 전체 앱이 크래시되지 않고 폴백 UI가 표시되어야 한다
    그리고 "문제가 발생했습니다" 메시지와 새로고침 버튼이 표시되어야 한다
    그리고 에러 정보가 console.error로 로깅되어야 한다
```

## 2. Authentication Pages (P0)

### AC-WEB-001-04: 로그인
```gherkin
기능: 사용자 로그인

  시나리오: 정상 로그인
    주어진 유효한 이메일(admin@xflow.io)과 비밀번호가 있을 때
    만약 로그인 폼에 입력하고 로그인 버튼을 클릭하면
    그러면 POST /api/v1/auth/login이 호출되어야 한다
    그리고 Access Token과 Refresh Token이 메모리에 저장되어야 한다
    그리고 대시보드(/) 페이지로 이동되어야 한다

  시나리오: returnUrl이 있는 로그인 성공
    주어진 /monitoring에서 리다이렉트된 로그인 페이지일 때
    만약 정상적으로 로그인에 성공하면
    그러면 /monitoring 페이지로 이동되어야 한다

  시나리오: 잘못된 자격 증명으로 로그인 실패
    주어진 유효하지 않은 비밀번호를 입력했을 때
    만약 로그인 버튼을 클릭하면
    그러면 서버의 에러 메시지가 폼 상단에 표시되어야 한다
    그리고 비밀번호 필드가 초기화되어야 한다
    그리고 이메일 필드는 유지되어야 한다

  시나리오: 클라이언트 유효성 검증
    주어진 빈 이메일과 빈 비밀번호 상태일 때
    만약 로그인 버튼을 클릭하면
    그러면 API 호출 없이 "이메일을 입력해주세요" 유효성 오류가 표시되어야 한다

  시나리오: 잘못된 이메일 형식
    주어진 "not-an-email" 형식의 이메일을 입력했을 때
    만약 로그인 버튼을 클릭하면
    그러면 "올바른 이메일 형식이 아닙니다" 유효성 오류가 표시되어야 한다
```

### AC-WEB-001-05: 토큰 관리
```gherkin
기능: JWT 토큰 자동 관리

  시나리오: Access Token 자동 갱신
    주어진 Access Token이 만료된 상태이고 유효한 Refresh Token이 있을 때
    만약 보호된 API를 호출하면
    그러면 401 응답 후 자동으로 POST /api/v1/auth/refresh가 호출되어야 한다
    그리고 새로운 Access Token이 저장되어야 한다
    그리고 원래 요청이 새 토큰으로 재시도되어야 한다

  시나리오: Refresh Token 만료
    주어진 Refresh Token도 만료된 상태일 때
    만약 토큰 갱신을 시도하면
    그러면 사용자가 로그아웃 처리되어야 한다
    그리고 /login 페이지로 리다이렉트되어야 한다
    그리고 "세션이 만료되었습니다" 토스트가 표시되어야 한다

  시나리오: 동시 401 응답 처리
    주어진 3개의 API 요청이 동시에 401을 받았을 때
    그러면 토큰 갱신 요청은 1회만 발생해야 한다
    그리고 3개의 요청 모두 갱신된 토큰으로 재시도되어야 한다
```

### AC-WEB-001-06: 로그아웃
```gherkin
기능: 사용자 로그아웃

  시나리오: 정상 로그아웃
    주어진 사용자가 인증된 상태일 때
    만약 헤더의 로그아웃 버튼을 클릭하면
    그러면 POST /api/v1/auth/logout이 호출되어야 한다
    그리고 메모리의 토큰이 삭제되어야 한다
    그리고 /login 페이지로 이동되어야 한다
```

## 3. Flow Editor (P0)

### AC-WEB-001-07: 플로우 로드 및 렌더링
```gherkin
기능: 플로우 시각적 렌더링

  시나리오: 플로우 에디터 페이지 진입
    주어진 flow-001 플로우가 서버에 존재할 때
    만약 /editor/flow-001 경로에 접근하면
    그러면 GET /api/v1/flows/flow-001이 호출되어야 한다
    그리고 플로우의 모든 노드가 캔버스에 올바른 위치에 렌더링되어야 한다
    그리고 노드 간 와이어(엣지)가 올바르게 연결되어 표시되어야 한다
    그리고 미니맵이 캔버스 하단에 표시되어야 한다

  시나리오: 줌/팬 조작
    주어진 플로우가 렌더링된 상태일 때
    만약 마우스 휠로 줌을 조작하면
    그러면 캔버스의 확대/축소가 부드럽게 동작해야 한다
    만약 캔버스를 드래그하면
    그러면 뷰포트가 드래그 방향으로 이동(팬)해야 한다
```

### AC-WEB-001-08: 노드 추가 및 연결
```gherkin
기능: 드래그 앤 드롭으로 노드 추가 및 와이어 연결

  시나리오: 노드 팔레트에서 노드 추가
    주어진 Node Palette에 "MQTT Input" 노드 타입이 있을 때
    만약 "MQTT Input"을 캔버스로 드래그 앤 드롭하면
    그러면 드롭 위치에 "MQTT Input" 노드 인스턴스가 추가되어야 한다
    그리고 기본 설정값으로 초기화되어야 한다
    그리고 에디터 상태가 isDirty=true로 변경되어야 한다

  시나리오: 노드 간 와이어 연결
    주어진 "MQTT Input" 노드와 "Filter" 노드가 캔버스에 있을 때
    만약 "MQTT Input"의 출력 포트에서 "Filter"의 입력 포트로 드래그하면
    그러면 두 노드를 연결하는 새로운 와이어(Edge)가 생성되어야 한다

  시나리오: 호환되지 않는 포트 연결 방지
    주어진 출력 타입이 "string"인 포트와 입력 타입이 "number"인 포트가 있을 때
    만약 두 포트 간 연결을 시도하면
    그러면 연결이 거부되어야 한다
    그리고 대상 포트가 빨간색으로 하이라이트되어야 한다
```

### AC-WEB-001-09: 플로우 저장 및 배포
```gherkin
기능: 플로우 저장 및 배포 제어

  시나리오: 플로우 저장 (버튼)
    주어진 플로우에 변경사항이 있을 때 (isDirty=true)
    만약 저장 버튼을 클릭하면
    그러면 PUT /api/v1/flows/:flowId가 호출되어야 한다
    그리고 성공 시 "저장 완료" 토스트가 표시되어야 한다
    그리고 isDirty가 false로 변경되어야 한다

  시나리오: 플로우 저장 (단축키)
    주어진 플로우에 변경사항이 있을 때
    만약 Ctrl+S (Mac: Cmd+S)를 누르면
    그러면 브라우저 기본 저장 동작이 방지되어야 한다
    그리고 PUT /api/v1/flows/:flowId가 호출되어야 한다

  시나리오: 플로우 배포
    주어진 저장된 플로우가 있을 때
    만약 "배포" 버튼을 클릭하면
    그러면 POST /api/v1/flows/:flowId/deploy가 호출되어야 한다
    그리고 배포 진행 상태(로딩 스피너)가 표시되어야 한다
    그리고 성공 시 "배포 완료" 토스트가 표시되어야 한다
    그리고 플로우 상태가 "Deployed"로 업데이트되어야 한다

  시나리오: 배포된 플로우 시작
    주어진 Deployed 상태의 플로우가 있을 때
    만약 "시작" 버튼을 클릭하면
    그러면 POST /api/v1/flows/:flowId/start가 호출되어야 한다
    그리고 플로우 상태가 "Running"으로 변경되어야 한다
    그리고 도구 모음의 상태 표시기가 "Running" 뱃지를 표시해야 한다

  시나리오: 미저장 변경사항 경고
    주어진 플로우에 미저장 변경사항이 있을 때 (isDirty=true)
    만약 다른 페이지로 이동하려고 하면
    그러면 브라우저 beforeunload 경고가 표시되어야 한다
```

### AC-WEB-001-10: 노드 선택 및 삭제
```gherkin
기능: 노드/엣지 선택 및 삭제

  시나리오: 노드 선택 시 Property Panel 표시
    주어진 캔버스에 "MQTT Input" 노드가 있을 때
    만약 해당 노드를 클릭하면
    그러면 Property Panel에 "MQTT Input"의 설정 폼이 표시되어야 한다

  시나리오: 노드 삭제
    주어진 "Filter" 노드가 선택된 상태일 때
    만약 Delete 키를 누르면
    그러면 "Filter" 노드가 캔버스에서 제거되어야 한다
    그리고 연결된 와이어도 함께 제거되어야 한다
    그리고 Undo로 복원이 가능해야 한다

  시나리오: Undo/Redo 동작
    주어진 노드를 삭제한 직후일 때
    만약 Ctrl+Z (Undo)를 누르면
    그러면 삭제된 노드와 와이어가 복원되어야 한다
    만약 Ctrl+Y (Redo)를 누르면
    그러면 노드가 다시 삭제되어야 한다
```

## 4. API Client Service (P0)

### AC-WEB-001-11: HTTP 클라이언트
```gherkin
기능: 중앙화된 API 통신

  시나리오: 정상 API 요청
    주어진 유효한 Access Token이 있을 때
    만약 GET /api/v1/flows를 호출하면
    그러면 Authorization: Bearer {token} 헤더가 자동으로 추가되어야 한다
    그리고 응답의 {success, data, error, meta} 엔벨로프가 파싱되어야 한다

  시나리오: 네트워크 오류 자동 재시도
    주어진 네트워크 연결이 불안정할 때
    만약 API 요청이 네트워크 오류로 실패하면
    그러면 최대 3회까지 자동 재시도되어야 한다
    그리고 재시도 간격이 지수적으로 증가해야 한다 (1초, 2초, 4초)

  시나리오: 서버 에러 응답 처리
    주어진 서버가 500 Internal Server Error를 반환할 때
    만약 에러 응답을 받으면
    그러면 응답의 error.message가 일관된 에러 객체로 변환되어야 한다
```

### AC-WEB-001-12: WebSocket 클라이언트
```gherkin
기능: 실시간 WebSocket 통신

  시나리오: WebSocket 연결 수립
    주어진 유효한 인증 토큰이 있을 때
    만약 모니터링 페이지에 진입하면
    그러면 ws(s)://서버주소/api/v1/ws로 WebSocket 연결이 수립되어야 한다
    그리고 연결 상태가 "connected"로 변경되어야 한다

  시나리오: WebSocket 자동 재연결
    주어진 WebSocket이 연결된 상태에서 연결이 끊어졌을 때
    그러면 5초 간격으로 자동 재연결을 시도해야 한다
    그리고 UI 상단에 "연결 끊김 - 재연결 중..." 표시가 나타나야 한다
    그리고 최대 10회 재연결 시도 후 실패 시 "연결 실패" 메시지를 표시해야 한다

  시나리오: 하트비트 유지
    주어진 WebSocket이 연결된 상태일 때
    그러면 30초 간격으로 하트비트(ping)를 전송해야 한다
    그리고 응답(pong)이 없으면 연결 끊김으로 처리해야 한다

  시나리오: 페이지 이탈 시 연결 정리
    주어진 WebSocket이 연결된 상태에서
    만약 모니터링 페이지를 떠나면
    그러면 WebSocket 연결이 정상적으로 종료되어야 한다
    그리고 재연결 타이머가 해제되어야 한다
```

## 5. State Management (P0)

### AC-WEB-001-13: Zustand 스토어
```gherkin

기능: 프론트엔드 보안 기준

  시나리오: XSS 방지
    주어진 사용자 입력에 <script>alert('xss')</script>가 포함되었을 때
    그러면 해당 입력이 이스케이프 처리되어야 한다
    그리고 스크립트가 실행되지 않아야 한다

  시나리오: 토큰 보안 저장
    주어진 로그인 성공 후 토큰을 저장할 때
    그러면 Access Token이 localStorage에 직접 저장되지 않아야 한다
    그리고 메모리 또는 httpOnly 쿠키에 저장되어야 한다

  시나리오: RBAC UI 제한
    주어진 Viewer 역할의 사용자가 로그인했을 때
    그러면 플로우 생성/수정/삭제 버튼이 표시되지 않아야 한다
    그리고 배포/시작/중지 버튼이 비활성화되어야 한다
    그리고 조회 기능만 활성화되어야 한다
```

## 16. 경계 조건

### AC-WEB-001-27: 엣지 케이스 처리
```gherkin
기능: 경계 조건 처리

  시나리오: 빈 플로우 목록
    주어진 등록된 플로우가 없을 때
    만약 대시보드에 접근하면
    그러면 "플로우가 없습니다. 새 플로우를 생성하세요." 빈 상태 UI가 표시되어야 한다

  시나리오: 빈 플로우 에디터
    주어진 노드가 하나도 없는 새 플로우를 에디터에서 열었을 때
    그러면 빈 캔버스와 "Node Palette에서 노드를 드래그하세요" 안내가 표시되어야 한다

  시나리오: 네트워크 연결 끊김
    주어진 인터넷 연결이 끊어진 상태에서 API를 호출했을 때
    그러면 "네트워크 연결을 확인해주세요" 에러 토스트가 표시되어야 한다
    그리고 자동 재시도 후에도 실패하면 오프라인 상태 표시기가 나타나야 한다

  시나리오: 존재하지 않는 플로우 접근
    주어진 삭제된 플로우 ID로 에디터에 접근했을 때
    만약 GET /api/v1/flows/:id가 404를 반환하면
    그러면 "플로우를 찾을 수 없습니다" 메시지가 표시되어야 한다
    그리고 대시보드로 돌아가는 링크가 제공되어야 한다

  시나리오: 동시 플로우 수정 (낙관적 업데이트 충돌)
    주어진 다른 사용자가 같은 플로우를 수정한 상태에서
    만약 현재 사용자가 저장을 시도하면
    그러면 409 Conflict를 수신하고 "플로우가 다른 사용자에 의해 변경되었습니다" 메시지를 표시해야 한다
    그리고 "새로고침" 또는 "강제 저장" 옵션을 제공해야 한다
```
