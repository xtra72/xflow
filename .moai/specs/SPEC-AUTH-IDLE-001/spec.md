# SPEC-AUTH-IDLE-001: 자리를 비우면 잠근다

## HISTORY

| 버전 | 날짜 | 작성자 | 변경 내용 |
|------|------|--------|----------|
| 0.1.0 | 2026-09-20 | xtra | 최초 작성 + 구현 — 요구: "일정시간(설정 - 기본 10분) 사용이 없을 경우 로그아웃 - 옵션(기본)" |

## 개요

사용자 입력이 설정된 시간 동안 없으면 자동으로 로그아웃한다. 설정은 **서버 전역 1벌**
(관리자가 정하면 모든 사용자에게 적용)이며 기본은 **10분·켜짐**이다. 잠기기 **1분 전**에
안내를 띄우고 "계속 사용" 을 준다.

## 요구사항 (Requirements — EARS)

### REQ-01 — 무활동이 한도를 넘으면 로그아웃한다 (Event-Driven)

**When** 마지막 사용자 입력으로부터 설정된 시간이 지나면, 클라이언트는 로그아웃한다.
로그아웃은 `useAuth.logout()` 을 지나므로 서버가 액세스 토큰을 블랙리스트에 넣고, 이어서
AuthGuard 가 로그인 화면으로 보낸다.

### REQ-02 — 잠기기 전에 알린다 (Event-Driven)

**When** 남은 시간이 경고 선행 시간 이하가 되면, 화면에 남은 시간과 "계속 사용" 단추를
띄운다. 경고 시간은 전체 유휴 시간 **안에** 포함된다(10분 설정 → 9분에 경고, 10분에 로그아웃).

### REQ-03 — 설정은 서버 전역 1벌이다 (Ubiquitous)

설정은 기존 전역 key-value 저장소(`GET/PUT /settings/{key}`, 키 `auth.idle-logout`)에
`{enabled, timeoutMinutes}` 로 저장된다. 읽기는 `system.read`, 쓰기는 `system.update` 이다.

### REQ-04 — 읽지 못해도 정책은 살아 있다 (Unwanted)

미저장(404)·권한 없음(403)·망가진 값 — 어느 쪽이든 **기본 정책(10분·켜짐)** 으로 떨어진다.
설정을 못 읽었다고 잠금을 꺼 버리면 보안 정책이 조용히 사라진다.

### REQ-05 — 돌지 않아야 할 때는 돌지 않는다 (State-Driven)

**While** 인증이 비활성인 서버이거나, 미인증(로그인 화면)이거나, 설정이 꺼져 있는 동안
유휴 감시는 동작하지 않는다.

## 명세 (Specifications)

### 결정 1 — 판정은 순수 층이 한다

`lib/idle/idlePolicy.ts` 는 "지금 몇 시, 마지막 활동 언제, 한도 몇 분" 만 받아
`active | warning | expired` 를 돌려준다. 타이머도 이벤트도 모르므로 시험이 시계를 붙잡을
필요가 없다. 배선(`useIdleLogout`)은 그 판정에 필요한 재료를 모으는 일만 한다.

### 결정 2 — 활동의 기준

포인터·키·휠·터치·스크롤은 활동이다. **탭 전환과 창 포커스는 활동이 아니다** — 두 시간
만에 돌아온 탭이 돌아왔다는 이유로 연장되면 "자리를 비우면 잠근다" 가 무너진다. 반대로
`pointermove` 는 활동으로 친다. 대시보드를 읽는 사람도 사용자이기 때문이다.

### 결정 3 — 탭 사이로 활동을 나눈다

한 탭에서 일하는 동안 다른 탭이 잠기면 안 되므로 마지막 활동 시각을 localStorage 로
공유한다(쓰기는 5초에 한 번 — 매 입력마다 쓰면 다른 탭의 이벤트가 폭주한다).

### 결정 4 — 짧은 한도에서는 경고를 줄인다

기본 경고는 1분이지만 한도의 절반을 넘지 않게 한다. 1분 설정에 1분 경고면 창이 뜨는 순간이
곧 만료다(1분 → 30초).

### 결정 5 — 수가 아닌 값은 기본 정책으로 돌린다

`NaN`/`Infinity` 는 범위 비교가 **둘 다 거짓**이라 클램프를 그냥 통과한다. 그렇게 새어 나간
`NaN` 은 한도 ms 를 `NaN` 으로 만들고, 남은 시간도 `NaN` 이라 어떤 비교도 참이 되지 않아
**기능이 조용히 꺼진다** — 잠긴다고 믿는 화면이 영원히 열려 있는 모습이다. 하한(1분)이
아니라 기본값으로 돌리는 까닭은, 읽을 수 없는 값 때문에 관리자가 정한 적 없는 가장 공격적인
정책이 적용되면 그것대로 사고이기 때문이다.

## 불변식 (Invariants)

- 설정을 읽지 못해도 잠금은 돈다(기본 정책).
- 경고는 항상 로그아웃보다 먼저, 같은 유휴 시간 안에서 뜬다.
- 로그아웃은 서버 토큰 폐기를 지난다(화면만 잠그지 않는다).

## 범위 밖 (Non-Goals)

1. **개인별 조정** — 사용자마다 다른 한도를 두지 않는다(전역 1벌).
2. **설정 변경의 즉시 전파** — 다른 탭·다른 사용자는 다음 조회(staleTime 60초) 때 받는다.
3. **리프레시 토큰 폐기** — 서버는 제시된 액세스 토큰만 무효화한다.
4. **활동 기준의 설정화** — 어떤 이벤트를 활동으로 칠지는 코드가 정한다.
