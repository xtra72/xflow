# SPEC-AUTH-006 인수 조건

AC-01 ~ AC-07 은 서버 인증이 활성이고 `/auth/me` 가 `permissions` 를 제공하는 상태를 전제로 한다.

---

## AC-01 — 권한 컨텍스트 적재

**Given** 서버가 `/auth/me` 로 `permissions: ["agent.read","agent.execute","device.read"]` 를 반환하고
**When** 사용자가 로그인하면
**Then** 인증 스토어의 권한 집합이 그 3개와 일치하고, `hasPermission('agent.read')` 는 true, `hasPermission('agent.delete')` 는 false 를 반환한다.
**And** 페이지를 새로고침해 세션이 복원되어도 동일한 결과가 유지된다.

## AC-02 — 폴백 규칙

**Given** 서버 인증이 비활성(`authEnabled === false`)일 때
**When** 임의의 권한을 판정하면
**Then** 항상 true 를 반환한다.
**And** `permissions` 필드가 없는 구버전 서버 응답에서도 항상 true 를 반환한다.
**And** 두 경우 모두 메뉴·버튼이 인증 도입 이전과 동일하게 전부 노출된다.

## AC-03 — 사용자 관리 화면

**Given** `user.read` / `user.create` 권한을 가진 관리자가 `/admin/users` 를 열었을 때
**When** 사용자 목록이 렌더되면
**Then** username·역할·생성일이 표시되고 비밀번호 해시는 어디에도 표시되지 않는다.
**And** 등록 폼에서 역할 선택 목록은 `GET /api/v1/roles` 결과(빌트인 3종 + 커스텀)로 채워진다.
**And** 마지막 관리자 삭제를 시도해 서버가 409를 반환하면, 원인이 사용자 언어로 안내되고 목록 상태는 변하지 않는다.

## AC-04 — 역할 관리 화면

**Given** `role.read` / `role.create` 권한을 가진 관리자가 `/admin/roles` 를 열었을 때
**When** 역할 생성 폼에서 권한 행렬을 조작하면
**Then** 리소스×액션 체크박스가 `GET /api/v1/permissions` 카탈로그로 렌더되고, 선택한 권한만 생성 요청에 포함된다.
**And** 빌트인 역할(`admin`/`editor`/`viewer`) 행은 수정·삭제 컨트롤이 비활성이고 사유가 표시된다.

## AC-05 — 메뉴 게이팅

**Given** 권한이 `agent.read`, `device.read` 뿐인 사용자가 로그인해 있을 때
**When** 사이드바가 렌더되면
**Then** 에이전트·디바이스 메뉴는 보이고, 플로우·모니터링·설정·사용자 관리·역할 관리 메뉴는 보이지 않는다.
**And** 하위 항목이 하나도 접근 불가한 그룹 메뉴는 그룹 자체가 표시되지 않는다.

## AC-06 — 라우트 직접 진입 차단

**Given** `user.read` 권한이 없는 사용자가 로그인해 있을 때
**When** 주소창에 `/admin/users` 를 직접 입력하면
**Then** 사용자 관리 화면이 렌더되지 않고 대시보드로 리다이렉트되며 안내가 표시된다(빈 화면이 아니다).

## AC-07 — 액션 컨트롤 게이팅

**Given** `agent.read` 만 가진 사용자가 에이전트 목록 화면을 열었을 때
**When** 화면이 렌더되면
**Then** 등록·수정·삭제·시작/정지 컨트롤이 비활성 상태이고 `aria-disabled` 와 사유 툴팁을 가진다.
**And** `agent.execute` 를 추가로 부여하면 시작/정지만 활성화되고 등록·수정·삭제는 비활성으로 남는다.

## AC-08 — 403 응답 처리

**Given** UI 게이팅을 통과했으나 서버가 403을 반환하는 요청이 발생했을 때
**When** 응답을 받으면
**Then** 사용자 언어로 권한 부족이 안내되고, 동일 요청을 자동 재시도하지 않는다.

## AC-09 — 역할 변경 반영

**Given** 관리자가 어떤 사용자의 역할을 변경했을 때
**When** 해당 사용자가 다음에 `auth/me` 를 갱신하면(재로그인 또는 세션 복원)
**Then** UI 권한이 새 역할 기준으로 갱신된다.
**And** 갱신 전이라도 서버가 거부하므로 실제 작업은 수행되지 않는다.

## AC-10 — 역할 이름 비교 잔존 없음

**Given** 게이팅 전환이 완료된 코드베이스에서
**When** `web/src` 전체를 검사하면
**Then** 게이팅 목적의 역할 이름 비교(`role === 'admin'`, `roles.includes(...)`, `requireRole`)가 남아 있지 않다.
**And** 역할 이름을 표시 용도로만 쓰는 코드는 허용된다.

## 엣지 케이스

| 상황 | 기대 동작 |
|------|-----------|
| 권한 0개 사용자 | 대시보드만 접근. 빈 사이드바가 아니라 대시보드 항목은 남음 |
| 권한 목록 조회 실패 | 폴백하지 않고 권한 없음으로 처리 + 재시도 안내(서버는 어차피 차단) |
| 삭제된 역할을 가진 사용자 | 권한 0개로 처리, 화면 크래시 없음 |
| 자기 자신의 역할을 강등 | 요청은 서버가 409로 거부, UI는 사유 안내 |
| 매우 긴 역할 이름 | 목록에서 말줄임 처리, 레이아웃 붕괴 없음 |
